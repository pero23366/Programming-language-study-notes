实验 03 · 响应式的边界

同一批操作，左边 Vue2、右边 Vue3。哪个按钮按下去了界面没动，哪个就是"拦不到"。

Vue 2 · Object.defineProperty

defineProperty 只能拦"对象上已经存在的 key"

arr[0]{{ arr[0] }}
user.name{{ user.name }}
user.age{{ user.age === undefined ? '（不存在）' : user.age }}
user.email{{ user.email === undefined ? '（不存在）' : user.email }}


Vue 3 · Proxy

Proxy 拦"对对象的任何操作"

arr[0]{{ s.arr[0] }}
user.name{{ s.user.name }}
user.age{{ s.user.age === undefined ? '（不存在）' : s.user.age }}
user.email{{ s.user.email === undefined ? '（不存在）' : s.user.email }}


怎么读这个实验
左边按 arr[0] = 'X'：控制台里 vm.arr[0] 确实变成 X 了，但上面那行没变 —— 数据改了，界面不知道。
左边按 $set：变了。因为 $set 走的是"手动补通知"的路径。
右边两个按钮都变。因为 Proxy 能拦到"设置下标"和"新增 key"这两件事本身。
这就是 Vue3 重写响应式的原因，不是性能噱头。

⚠️ 一个 $set 都救不了的坑（自己在控制台试）：
先执行 vm2.user.age = 18（界面不动，但 age 这个 key 已经真的挂到对象上了）， 再执行 Vue.set(vm2.user, 'age', 18) —— 依然不动。
因为 $set 源码里第一件事是 if (key in target)：key 已经存在，它就当作"这个属性早就被观察过了"， 直接 target[key] = val 完事，不发通知。
→ $set 只对"从来没存在过的 key"有效，先手赋过值就废了。这个顺序依赖没有任何警告。
