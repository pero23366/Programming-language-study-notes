==一：概念==

## 1. AI 的基本认知：它到底在干什么（190）

### 1.1 先把名词层级理清

课程里这几个词是混着说的，先钉死归属：

| 词 | 范围 | 一句话 |
|---|---|---|
| AI（人工智能） | 最大 | 「让机器做需要智能的事」的总称，1956 年就有了 |
| ML（机器学习） | ⊂ AI | 不写规则，**从数据里拟合规则** |
| DL（深度学习） | ⊂ ML | 用多层神经网络拟合，2012 年后成为主流 |
| LLM（大语言模型） | ⊂ DL | 只在**文本**上训练的巨型神经网络，ChatGPT 属于这一类 |

**你日常说的「AI」= LLM**，这个等号先记住，后面所有结论都建立在它上面。

**C# 对照（只对照工程习惯，不对照原理）**：把它当成一个**你没法看源码、没法断点、只能通过 HTTP 调用的第三方库**。你不知道内部实现，但你必须知道它的输入格式、输出格式、失败模式 —— 这跟接一个支付网关是同一类问题。

### 1.2 核心机制：它不是一个数据库

这是**一切误解的源头**，必须一句一句看：

| 你可能以为 | 实际是 |
|---|---|
| 它在知识库里检索答案 | 它**根据上文预测下一个词**（token），一个接一个吐出来 |
| 它有「正确答案」存档 | 它只有「哪些词接在后面概率高」的统计规律 |
| 同一个问题两次答案一样 | 默认带**随机采样**，两次可以不同 |

**所以「它答对了」和「它知道」是两件事** —— 它答对是因为训练语料里这种问法后面常跟这种答案，不是因为查到了。

**一个能自证的实验**（不用装任何东西）：

> 问它：「`C#` 里 `List<T>` 的 `Capacity` 增长策略是什么？请给出 .NET 具体版本的源码行号。」
>
> 观察点：**它会给出一个非常像真的行号，而这个行号大概率是错的。**

这就是 **幻觉（hallucination）**。不是它坏了，是「预测下一个词」这个机制在「不知道」时**没有「我不知道」这个选项更大概率** —— 编一个符合格式的答案，比说「不知道」更像训练数据里的回答。**这是必现的、结构性的，不是修 bug 能解决的。**

### 1.3 三个你必须知道的工程参数

| 概念 | 是什么 | 对你写代码的影响 |
|---|---|---|
| **Token** | 模型处理的最小单位，≈ 0.75 个英文词 / 1-2 个汉字 | 计费按 token；上下文按 token 算，不按「字数」 |
| **上下文窗口** | 一次对话能记住的 token 上限 | **超了就忘**，而且忘的是最早的部分（你的需求说明） |
| **训练 vs 推理** | 训练 = 改权重（几个月、几千万美元）；推理 = 用固定权重算一次 | 你用的永远是推理。**它不知道训练截止日之后的事** |

**「上下文窗口」这一条在实战里最容易咬人**：你跟它聊了 40 轮，第 1 轮说「这个项目用 Vue3 + TS，不要用 Vue2 写法」，到第 30 轮它开始给你 Vue2 的 `this.$refs` —— **不是它不听话，是那句话被挤出窗口了**。

工程对策：**关键约束要重复**。每 5-10 轮复述一次「项目是 Vue3 `<script setup>`，只用组合式 API」。这跟 C# 里「不要依赖跨 await 的 `HttpContext`」是一个性质的坑：**状态会失效，只是不报错**。

### 1.4 能力边界表（这张表决定你什么时候该用它）

| 任务类型 | 可用度 | 原因 |
|---|:--:|---|
| 解释概念、翻译、总结、改写 | ⭐⭐⭐ | 语料充足，错了也容易发现 |
| 写样板代码（CRUD、表单、样式） | ⭐⭐⭐ | 模式固定，训练集里遍地都是 |
| 从报错信息定位问题 | ⭐⭐ | 报错原文是关键上下文；它擅长「这条报错通常意味着」 |
| 解释一段你不认识的代码 | ⭐⭐⭐ | 它的最强场景之一 |
| 架构决策（该不该上 Pinia / 拆不拆组件） | ⭐ | 它会给一个很像样的答案，但**没有你的项目上下文** |
| 精确 API 签名 / 版本差异 | ⚠️ | 高频幻觉区，**必须回官方文档核对** |
| 实时信息（今天的股价、昨天发布的版本） | ❌ | 训练截止日之后的事它不知道，除非联网 |
| 「我这行代码为什么报错」但不给代码 | ❌ | 没有上下文，它只能猜 |

**记住第 6 行**：`Element Plus` 的某个属性名、`Vue Router` 的某个守卫签名 —— **这些恰恰是最容易编的**，因为格式太规整了。凡是「差一个字母就不生效」的东西，一律查文档。

### 1.5 提示词（Prompt）：为什么它也需要「接口约定」

**先看没有格式的世界**：

> 「帮我写个登录页。」

它给你一个 Vue2 的、用 `this` 的、带 jQuery 的、样式写死的登录页。**问题不在它，在输入** —— 你没告诉它任何约束，它只能返回「互联网上最常见的登录页」。

**四要素模板**（这一篇唯一要背的东西）：

| 要素 | 作用 | 例子 |
|---|---|---|
| **角色** | 限定知识域和语气 | 「你是一个资深 Vue3 前端工程师」 |
| **背景** | 给它项目上下文 | 「项目用 Vue3 `<script setup>` + TS + Element Plus，Pinia 管状态」 |
| **任务** | 要它做什么，动词开头 | 「写一个登录页组件」 |
| **约束** | 边界，越具体越好 | 「不要用 Options API；样式用 scoped；表单校验用 el-form 的 rules」 |
| **输出格式** | 决定你怎么用结果 | 「只给 `<template>` 和 `<script setup>` 两块，不要解释」 |

**加一条「示例」（few-shot）效果最大**：

> 「参考这个写法：`<script setup>const form = ref({ username: '', password: '' })</script>`」

一句示例，胜过三行形容词。因为模型是「续写」的 —— **给它一个开头，它就会顺着你的风格续**。

**C# 对照**：提示词 ≈ **方法签名 + 泛型约束 + XML 注释**。你不写约束，编译器不管你；你不写约束，模型也不管你。**区别是编译器会报错，模型会静默给你一个错的东西。**

## 2. ChatGPT 的基本使用：把「聊天」用成「工具」（191）🔥

### 2.1 界面三件事

| 元素 | 关键点 |
|---|---|
| 新对话（New Chat） | **一个任务一个对话**。换任务不换对话 = 上一个任务的约束污染当前任务 |
| 上下文 | 同一对话里它记得前面所有内容（到窗口上限） |
| 重新生成 / 编辑上一条 | 改你的提问再让它答，比「不，我不是这个意思」有效十倍 |

**「一个任务一个对话」是最省时间的习惯**：写登录页的对话里突然问「帮我优化 SQL」，它后续回答会带着前一个任务的语气和假设。

### 2.2 提代码问题的标准姿势

**差的问法**：

> 「我的 Vue 报错了怎么办？」

**好的问法（四段式）**：

```
【环境】Vue 3.4 + Vite 5 + Element Plus 2.5，<script setup> + TS
【代码】<贴出完整的、能复现的组件文件，不要只贴一行>
【报错】<原封不动贴控制台原文，包括堆栈第一行>
【期望】点「提交」时应该校验通过后发请求，实际是点了没反应、控制台无报错
```

**四个括号一段不能少**，理由分别是：

- **环境** —— 同一个 `ref` 在 Vue2 和 Vue3 里完全不同，它必须知道你在哪个世界；
- **完整文件** —— 前端 bug 八成在「这个文件和别的文件的关系」上，只贴一行它只能猜；
- **报错原文** —— 报错信息本身就是最好的提示词，改写过就废了；
- **期望 vs 实际** —— 这是**唯一能让它区分「代码没错但行为不对」的说法**。前端大量问题是「不报错的静默失败」，你只说「报错」，它会去找不存在的异常。

### 2.3 五种高频用法（按性价比排序）

| # | 用法 | 提问模板 |
|:--:|---|---|
| 1 | **解释代码** | 「逐行解释这段代码，重点说每一行为什么必须存在，不写会怎样」 |
| 2 | **定位 bug** | 用 2.2 的四段式，最后加一句「先只给诊断，不要给修改后的代码」 |
| 3 | **写样板** | 用 1.5 的四要素 + 「只给代码，不要解释」 |
| 4 | **重构/瘦身** | 「这段逻辑能压到 5 行以内吗？保持行为完全一致」 |
| 5 | **学新 API** | 「`defineModel` 解决什么问题？没有它之前怎么写？给前后对照」 |

**第 2 条的「先只给诊断」是关键技巧**：如果你直接说「帮我改」，它会**一边猜原因一边改**，改完你也不知道为什么好了 —— **这就等于把调试能力外包出去了**。先要诊断，你自己确认原因，再要改法。

### 2.4 让它「反过来问你」

遇到需求说不清时，加一句：

> 「在动手之前，先列出你需要我补充的信息，最多 3 个问题。」

它问出来的三个问题，往往正好是你自己没想清楚的地方（数据从哪来、失败怎么提示、要不要做权限）。

**这一步等价于需求评审**。跳过它直接要代码，就是跳过设计直接写 —— 你 C# 那边不会这么干。

### 2.5 三条安全红线

| 红线 | 原因 |
|---|---|
| 不贴密钥、token、连接串 | 对话会被留存；贴一次就等于泄露 |
| 不贴公司/他人完整业务代码 | 合规问题，不是技术问题 |
| 不把它的答案直接进生产 | 你没法为一段你不理解的代码负责 |

**第三条对现在的你尤其重要**：你正在学 —— **一段「能跑但你没看懂」的代码，对学习是负收益**，因为它会伪装成进度。

## 3. Copilot 入门：AI 进到编辑器里（192）

### 3.1 和 ChatGPT 的根本差别

| | ChatGPT（网页） | Copilot（编辑器插件） |
|---|---|---|
| 上下文 | 你**手动**贴给它 | **自动**读取当前文件、打开的文件、甚至整个项目 |
| 交互 | 一问一答，来回切窗口 | **内联补全**，Tab 接受 |
| 粒度 | 一个函数 / 一个文件 | 一行 / 一段 |
| 打断成本 | 高（切窗口 = 离开心流） | 极低（灰色字就在光标后面） |

**「打断成本」是它真正的价值**：写代码时最贵的是上下文切换。网页版要你复制、切换、粘贴、再切回来，插件把这一步压成了「按一下 Tab」。

### 3.2 三种触发方式

| 方式 | 怎么触发 | 典型场景 |
|---|---|---|
| **注释生成代码** | 写一行注释 `// 校验两次密码是否一致，不一致返回错误信息`，回车 | 逻辑明确但懒得敲的校验/转换 |
| **函数名补全** | 写 `function validatePassword(` 停住 | 有命名习惯的样板逻辑 |
| **半句续写** | 写 `const rules = {` | 表单校验、配置对象、重复结构 |

**灰色字 = 建议，Tab = 接受，Esc = 拒绝。** 灰色字**永远不要盲按 Tab** —— 先读，再按。这是唯一重要的操作纪律。

### 3.3 对「正在学」的人，它是双刃剑

**先讲没有它的世界**：你要写一个「两次密码一致」的校验，得先想 `validator` 的签名（`(rule, value, callback)`）、想 `callback(new Error(...))` 怎么写、想 `trigger` 填什么 —— **这个「想」的过程就是学习本身**。

**有了它**：你写到 `validator: (rule, value, callback) =>` 它就补完了。你按了 Tab，表单能跑，**但你没经历那个「卡住 → 想通」的过程**。

| 用法 | 结果 |
|---|---|
| 卡住 30 秒 → 自己想出来 → 按 Tab 补剩下的样板 | ⭐⭐⭐ 学习 + 效率兼得 |
| 一动手就 Tab，从不读灰色字 | ❌ 假进度，换个场景写不出来 |
| 让它写完整个组件，自己只负责运行 | ❌❌ 这不是在学前端，是在学「怎么让别人写前端」 |

**给你的具体规则（就这一条）**：

> **第一次遇到某个 API，手写。第二次开始，可以 Tab。**

因为学习的本质是「建立第一次的神经连接」，第二次只是复用。**第一次就外包，等于从未建立。**

### 3.4 同类工具

课程讲的是 GitHub Copilot，机制一样的还有：**通义灵码**（阿里，国内免费）、**CodeGeeX**（智谱）、**Codeium**（国外免费版）。它们都是「内联补全 + 对话面板」这两件套。

**选型只看两点**：能不能读整个项目（影响补全准确度）、能不能离线/内网（影响合规）。对个人学习，免费的那个就够。

==三：代码==

## 1. 一个「对照实验」：同一需求，两种提问

不用跑代码，看输出差异就够了。**建议你自己拿这两段去问一次，感受差距**。

**提问 A（差）**

```
写个表单校验，密码两次要一样
```

典型输出：一个脱离项目的 `if (pwd !== pwd2) alert('不一致')`。

**提问 B（好）**

```
角色：资深 Vue3 前端。
背景：Element Plus 的 el-form，<script setup> + TS。
任务：给「确认密码」字段写 rules。
约束：
1. 用 el-form 官方的 validator 签名，不要自己造
2. 两次不一致时提示「两次输入的密码不一致」
3. 不要改我其他字段
输出：只给 rules 这一个对象。
```

**差别不在「它聪明了」，在于你把约束变成了输入。** 这和 C# 里「不写泛型约束，`T` 就什么都不能调」是完全同构的。

## 2. `validator` 的手写版（192 讲的「别急着 Tab」的例子）

下面这段**建议手打一遍**，它是 196 集要用的东西：

```js
const validatePass2 = (rule, value, callback) => {
  if (value !== form.value.password) {
    callback(new Error('两次输入的密码不一致'))
  } else {
    callback()              // ← 必须调用，否则表单永远卡在校验中
  }
}
```

**三个点，每个都是坑**：

| 点 | 说明 | 不这么写会怎样 |
|---|---|---|
| 签名是 `(rule, value, callback)` | 位置固定，`rule` 你多半用不到 | 参数顺序错了不报错，只是永远通过 |
| 成功也要 `callback()` | 不传参就是「通过」 | **漏掉 → 表单校验 Promise 永远 pending，提交按钮点了没反应** |
| 抛错用 `callback(new Error(msg))` | 不是 `throw` | `throw` 会让整个校验链断掉，控制台一堆红字 |

**第三行的 `throw` 是最常见的错法**：`validator` 里 `throw new Error(...)` 看起来更符合 C# 直觉（抛异常 = 校验失败），但这里它是**回调式的**，抛出去没人接，Element Plus 拿不到「这是校验信息」这个语义。

**C# 对照**：这更像 `IValidatableObject.Validate` 里 `yield return new ValidationResult(...)` —— **返回值/回调携带错误，而不是抛异常**。异常是「程序坏了」，校验失败是「业务正常分支」，两者不该共用一条通道。

==四：总结==

## 1. 一句话记住三个

- **LLM 是「按上文续写」，不是「按问题检索」** —— 所以它会流畅地编。
- **提问的质量 = 约束的数量**，四要素（角色/背景/任务/约束）+ 输出格式，缺一样它就返回「互联网平均值」。
- **Copilot 降低的是输入成本，不是理解成本** —— 它省下的时间如果没变成理解，那就是负收益。

## 2. ⭐⭐ 本轮要背的

## 3. ⭐ 收敛时刻

**这一篇看似脱离了前端，其实把三条老结论接到了新场景上：**

**① 「静默失败」这条暗线，在 AI 身上重演了**

你从 JS 一路学过来：`undefined` 不报错、`ref` 漏 `.value` 不报错、`provide` 传 `.value` 不报错。**AI 幻觉是同一类东西的最高形态** —— 它给你一个格式完美、语法正确、逻辑自洽、**事实错误**的答案，且**没有任何报错**。

判据也一模一样：**别问「它会不会错」，要问「我怎么知道它对」**。答案是：**有可验证的判据才算数**（能跑、能对照文档、能看类型）。

**② 「约束越少，自由度越大，越不可控」—— 这是你已经学过三次的东西**

| 场景 | 不写约束的后果 |
|---|---|
| C# 泛型不加 `where T : class` | `T` 上什么都不能调 |
| `defineProps` 不写类型 | 父组件传错也没提示 |
| **提示词不写约束** | **返回「互联网平均值」** |

**约束不是麻烦，约束是让结果可预测的唯一手段。** 这条能一路解释到 TypeScript 存在的意义。

**③ 你已经具备「判断它答得对不对」的能力，这才是重点**

AI 对你最大的风险不是「它不会」，是**你没有能力识别它错了**。而你现在会 JS/TS/Vue 的基础语法 —— 意味着它给你的 Vue3 代码，你能看出「这不是组合式写法」「这个 `ref` 少了 `.value`」。

**所以「学基础」和「用 AI」不是两件事**：**基础决定了 AI 对你是不是净收益**。基础越薄，AI 越是「看起来在帮你，实际在替你决定」。

## 4. 静默失败清单

| # | 场景 | 现象 | 真相 |
|:--:|---|---|---|
| 1 | 问了 API 具体签名 | 给了个很像的，跑起来报「属性不存在」 | 高频幻觉区，文档为准 |
| 2 | 长对话后它开始用 Vue2 写法 | `this.$refs`、`export default` | 早期约束被挤出上下文窗口 |
| 3 | 「帮我改」而不是「先诊断」 | 代码变了，但不知道为什么好了 | 把调试能力外包，下次还不会 |
| 4 | 只贴一行代码问「为什么报错」 | 它给一堆泛泛的可能原因 | 它没有复现条件，只能概率猜 |
| 5 | 「不报错但没反应」只说「报错」 | 它去找不存在的异常 | 静默失败没有异常可找，必须描述**期望 vs 实际** |
| 6 | 一个对话里问三件不相关的事 | 后一个答案带着前一个的语气/假设 | 上下文是共享的 |
| 7 | 盲按 Tab | 代码能跑，但你没读懂 | 补全的速度远超理解的速度 |
| 8 | 让它「优化性能」但没给数据量 | 给一堆 `v-if`/`v-memo` 建议 | 没有量化指标就没有优化 |
| 9 | 把它的答案当「已学会」 | 一周后自己写不出来 | 能读 ≠ 能写，判据是**能否不看答案重写** |

**第 5 和第 9 条是给你当下的**。第 5 条对应你项目里已经踩过的坑（`.hidden` 压过 `v-show`，控制台干净但行为不对）；第 9 条是**自我检出的唯一办法**：合上答案，从空白文件写一遍。

## 5. C# 类比可用度

| C# / .NET 侧 | AI 工具侧 | 可用度 | 注意 |
|---|---|:--:|---|
| 调用一个没有源码的第三方 SDK | 调 LLM | ⭐⭐⭐ | 都是「黑盒 + 契约」，你不知道内部 |
| 方法签名 / 泛型约束 | 提示词的约束部分 | ⭐⭐⭐ | 不写约束 = 结果不可预测 |
| `IValidatableObject` 返回 `ValidationResult` | `validator` 的 `callback(new Error())` | ⭐⭐⭐ | **校验失败走返回值，不走异常** |
| `try/catch` + 异常冒泡 | LLM 幻觉 | ⭐ | **幻觉不抛异常**，没有 catch 的机会 |
| NuGet 包的 README + IntelliSense | **官方文档** | ⭐⭐⭐ | 唯一权威源，永远优先 |
| Code Review 的人 | ChatGPT / Copilot | ⭐⭐ | 它会说「看起来不错」，因为它没有你的上下文 |
| `dotnet format` / 代码生成器 | Copilot 补全 | ⭐⭐⭐ | 都生成样板，都不理解意图 |

**用法建议**：把 AI 读成 **「一个很快、很自信、没有源码、不会说『我不知道』的第三方库」**。你对它的态度应该跟你对一个来路不明的 NuGet 包一样：**能用，但每个返回值都要验**。
