==一：概念==

## 1. 作用域：每个函数自带一个"抽屉"

**先看没有作用域的世界长什么样**：所有变量摊在一个平面上，谁都能读、谁都能写。两个函数里各写一个 `i`，后写的把先写的踩了；你改一个不起眼的变量名，隔了 300 行的另一个函数突然出 bug —— 而且你不知道是谁改的。

**作用域 = 给每个函数发一个抽屉。** 变量在**声明的那一刻**就被决定了住哪个抽屉。

**JS 有三种作用域**：

| 作用域 | 谁创建 | 谁住在这里 |
|---|---|---|
| **全局作用域** | 脚本一开始就有 | 最外层的 `let`/`const`/`var`，以及挂在 `window` 上的东西 |
| **函数作用域** | 每**调用**一次函数就新建一个 | 函数内部声明的变量、形参 |
| **块级作用域** | 每遇到一对 `{}`（`if` / `for` / `while` / 裸块） | `let` / `const` 声明的变量 |

⚠️ **`var` 是唯一的例外：它看不见 `{}`。** `var` 只认函数边界，不认块。

```js
if (true) {
  var a = 1;   // var 无视这个 {}  → a 跑到了外层
  let b = 2;   // let 认这个 {}    → b 出了 if 就没了
}
console.log(a);   // 1
console.log(b);   // ReferenceError: b is not defined
```

**C# 对照**：C# 从诞生起就是**块级作用域**，"出了 `{}` 就没了"是你的默认直觉 —— 这个直觉在 JS 里**只对 `let`/`const` 成立**。`var` 是 1995 年的遗产，活在 C# 出现之前的世界里。

## 2. 作用域链：找不到就往外一层问

读一个变量时，JS 按这条路径找：

```
当前作用域 → 外层函数的作用域 → 再外层 → … → 全局作用域 → 还没有 → ReferenceError
```

这条路径就是**作用域链**。

⭐ **关键：链子在函数"写下来的那一刻"就定死了，跟谁调用它无关。**

```js
let x = '全局';

function outer() {
  let x = 'outer';
  function inner() { console.log(x); }   // inner 里写死：找不到 x 就问 outer
  return inner;
}

outer()();   // 'outer' —— 不是 '全局'
```

这叫**词法作用域**（静态作用域）。C# 也是词法作用域 —— 这一点两边**完全一致** ✅。

## 3. 垃圾回收：JS 帮你干 C 的 `free`

你学过 C：`malloc` 必须配 `free`，忘了就漏，多 `free` 一次就崩。**GC 就是自动帮你调 `free`。**

**判据不是"还有没有人引用"，而是"从根出发走得到走不到"** —— 这叫**可达性（reachability）**。

- **根（roots）**：全局对象 `window`、当前调用栈里还活着的局部变量
- 从根顺着引用一层层往外走，**能走到的 = 活的**；走不到的，**哪怕它们之间互相引用成一圈，照样是垃圾**

**主流算法：标记清除（Mark-and-Sweep）**

1. **标记**：从根出发，把所有走得到的对象标上
2. **清除**：没被标记的，回收

**C# 对照**

| | C# | JS |
|---|---|---|
| 自动回收 | ✅ | ✅ |
| 判据 | GC Roots + 可达性 ✅ **同源** | 根 + 可达性 |
| 分代 | Gen0 / Gen1 / Gen2 ✅ | V8 也是新生代 / 老生代 ✅ |
| 手动释放的钩子 | **`IDisposable` / `using` / 终结器** | ❌ **完全没有** |
| 弱引用 | `WeakReference<T>` | `WeakMap` / `WeakSet`（课程外） |

⚠️ **最大的差异**：C# 给你 `IDisposable` 和 `using`，是因为文件句柄、数据库连接这些"操作系统资源"不能等 GC。**JS 里没有这个东西** —— JS 的思路只有一条：**让引用断掉。**

**四种最常见的泄漏**（全都是"引用没断"）：

| 泄漏源 | 怎么断 |
|---|---|
| 意外的全局变量（漏写 `let`） | 补上 `let`/`const` |
| `setInterval` 忘了停 | `clearInterval` |
| 事件监听忘了解绑 | `removeEventListener` |
| **闭包长期握着大对象** | 见下一节 |

**工程上怎么防**：F12 → **Memory** 面板拍两次快照对比，看谁在涨；以及立一条**定势** —— 写下 `setInterval` 的同时就把 `clearInterval` 写上，写下 `addEventListener` 的同时就想好什么时候 `remove`。

## 4. 闭包：函数 + 它的"出生地"

**定义**：一个函数能"记住"它被定义时所在的那个作用域；**即使外层函数早就执行完了**，它依然能读写那些变量。

**三个条件（缺一不成）**

1. 函数**嵌套**
2. 内层函数**引用**了外层的变量
3. 内层函数在外层函数**返回之后**还被调用

**为什么叫"闭"包**：外层的那些变量被"关"在了这个包里 —— 外层函数的调用栈早已销毁，但变量**不释放**，因为内层函数还握着它。

**没有闭包的世界长什么样**：想在两次调用之间"记住"一个值，只能挂到全局变量上 —— 谁都能改，还会撞名。**闭包第一次让"私有状态"成为可能。**

**C# 对照 —— 这是最像的一对**

```csharp
// C#
static Func<int> MakeCounter() {
    int count = 0;
    return () => ++count;      // 捕获 count
}
```

```js
// JS
function makeCounter() {
  let count = 0;
  return function () { return ++count; };   // 捕获 count
}
```

**几乎一模一样** ✅。你学过的 Lambda 捕获外部变量，就是闭包。

⚠️ **但要记住两条差异**：

| | C# | JS |
|---|---|---|
| 捕获的是值还是变量 | 捕获**变量本身**（同一个绑定） | 捕获**变量本身**（同一个绑定）—— **一致** ✅ |
| 什么时候成立 | **编译期**就把它变成一个真正的类字段，确定 | **运行期**顺着作用域链找，运行时才定 —— 结果一样，但过程**你看不见** |
| 意外程度 | 得写 Lambda 才会产生 | ⚠️ **一个回调、一个 `setInterval` 就捕获了，你可能根本没意识到** |

**闭包的四个用途**：计数器 / 私有变量（模拟 C# 的 `private`）· **防抖节流**（第 196-197 集）· 循环里给每个元素绑独立的值 · 模块化

**闭包的代价**：被捕获的变量**永远活着**。上面 `makeCounter` 的 `count` 会一直在。如果闭包里握着一个 DOM 节点、一个 5MB 的数组 —— 那 5MB 就永远回收不掉。**这正是 153 集说的那个"引用没断"的泄漏源。**

==二：格式==

## 1. 四种声明方式的横向对照

| 声明方式 | 作用域 | 能否重复声明 | 声明前访问 | 挂到 `window` 上吗 |
|---|---|---|---|---|
| `var` | **函数**（穿透 `{}`） | ✅ 能（**静默**覆盖） | `undefined`（提升） | ✅ **会** |
| `let` | **块级** | ❌ 抛 `SyntaxError` | ❌ **抛 `ReferenceError`（TDZ）** | ❌ 不会 |
| `const` | **块级** | ❌ 同上 | ❌ 同上 | ❌ 不会 |
| 不写关键字就赋值 | **全局** | ✅ 能 | —— | ✅ **会**，而且**静默** |

⚠️ **最后一行是"静默失败"的经典款**：

```js
function f() {
  totel = 100;    // 本来想写 total，手滑漏了个字母 → 没有任何报错
}                 // 结果：凭空多了一个全局变量 totel，total 还是 undefined
```

严格模式（`'use strict'`，或 ES Module 自动开启）下，这一行才会抛 `ReferenceError`。

## 2. 作用域链查找：四步

1. 先看**当前作用域**有没有
2. 没有 → 顺着**书写位置**往外一层
3. 一直找到**全局作用域**
4. 还没有 → `ReferenceError`

⭐ 记两句就够：
- **链子按"写在哪"定，不按"谁调用"定**（词法作用域）
- **只出不进**：内层能读外层，外层读不到内层

## 3. 闭包的标准骨架

```js
function outer() {          // ① 嵌套
  let n = 0;                //    被捕获的变量
  return function () {      // ② 内层引用外层变量
    n = n + 1;              // ③ 内层被带出去，外层结束后还能调用
    return n;
  };
}
const c = outer();
c();   // 1
c();   // 2   ← outer 早就执行完了，n 还活着
```

**两条纪律**

1. **不需要了就放掉引用** —— `c = null;`，让 `n` 变成不可达
2. **别让闭包长期握着大对象** —— 尤其 DOM 节点、大数组、大 JSON

## 4. 循环绑事件的经典坑

```js
// ✗ var 版：三个按钮都打印 4
for (var i = 1; i <= 3; i++) {
  btns[i - 1].addEventListener('click', function () {
    console.log(i);
  });
}

// ✅ let 版：1 / 2 / 3
for (let i = 1; i <= 3; i++) {
  btns[i - 1].addEventListener('click', function () {
    console.log(i);
  });
}
```

**病根**：`var` 是**函数作用域** → 三个闭包捕获的是**同一个 `i`**；循环退出时 `i` 已经自增到 **4**，所以三个都打印 4。

**⭐ 这不是 JS 的锅** —— C# 一模一样：

```csharp
var fs = new List<Func<int>>();
for (int i = 1; i <= 3; i++) { fs.Add(() => i); }
// 全部输出 4
```

C# 的 `foreach` 从 C# 5 起已经改成"每次迭代一个新变量"，但 `for` 至今仍是同一个变量。**这是"循环变量 + 闭包"的通用数学，不是某个语言的缺陷。**

`let` 为什么能修好：**`let` 让每次迭代都创建一个新的块级绑定** → 三个闭包各捕获一个。

==三：代码==

## 1. 闭包计数器（对标 C# Lambda 捕获）

```html
<!DOCTYPE html>
<html lang="zh-CN">
<head><meta charset="UTF-8"><title>闭包计数器</title></head>
<body>
  <p>点击次数：<span id="count">0</span></p>
  <button id="btn">点我</button>

  <script>
    // 工厂函数：每次调用都得到一个「自带私有变量」的计数器
    function makeCounter() {
      let n = 0;                       // ← 私有变量，外面看不到
      return function () {
        n = n + 1;
        return n;
      };
    }

    const counter = makeCounter();     // makeCounter 已经执行完了
    const span = document.querySelector('#count');
    const btn  = document.querySelector('#btn');

    btn.addEventListener('click', function () {
      span.innerText = counter();      // 1 2 3 4 …  → 说明 n 没被回收
    });
  </script>
</body>
</html>
```

**两个可自证的实验**

1. Console 里打 `typeof n` → `'undefined'`。**外面真的看不到 `n`** —— 这就是 C# `private` 字段的效果。
2. 再 `const counter2 = makeCounter();` → 它从 1 开始，和 `counter` 互不干扰。**每次调用 `outer` 都新建一个独立的作用域。**

## 2. 循环绑事件（作用域 + 闭包的合力）

```html
<!DOCTYPE html>
<html lang="zh-CN">
<head><meta charset="UTF-8"><title>循环绑事件</title></head>
<body>
  <button>按钮 1</button>
  <button>按钮 2</button>
  <button>按钮 3</button>

  <script>
    const btns = document.querySelectorAll('button');

    for (let i = 0; i < btns.length; i++) {
      btns[i].addEventListener('click', function () {
        console.log('我原来是第 ' + (i + 1) + ' 个');
      });
    }
  </script>
</body>
</html>
```

**动手做这三个调试**

1. 把 `let` 换成 `var` → 三个按钮**全打印"第 4 个"**（闭包捕获了同一个 `i`）
2. 在回调**外面**加一句 `console.log(i)` → 正常打印 0 1 2（那是同步执行，还没进闭包）
3. 把 `addEventListener` 换成直接调用 → 立刻拿到正确的 `i`（因为不再是"事后调用"）

## 3. 一次泄漏的现场

```js
const big = new Array(1000000).fill('x');   // 假装是个大数组

function setup() {
  const el = document.querySelector('#panel');
  setInterval(function () {
    console.log(big.length, el);            // ← 闭包捕获了 big 和 el
  }, 1000);
}
setup();
```

`big` 和 `el` 永远回收不掉。**修法**：把定时器 id 存下来，该停的时候 `clearInterval(id)`；或让闭包别引用 `big`。

==四：总结==

## 1. 一句话记住三个

| 集 | 一句话 |
|---|---|
| 152 | **变量住在哪个抽屉，是"写下来的时候"决定的**；`var` 看不见 `{}` |
| 153 | **判断垃圾的标准是"从根走得到吗"，不是"还有没有人引用"**；JS 没有 `Dispose`，只能断引用 |
| 154 | **闭包 = 函数 + 它的出生地**；好处是私有状态，代价是**变量不释放** |

## 2. ⭐ 收敛时刻：三个知识点其实是一条线

- **152 讲了"变量住在哪"**
- **153 讲了"什么时候被回收"** —— 判据是可达性
- **154 的闭包，恰恰是"让一条引用路径一直可达"**

所以：**闭包不是新东西，它就是"作用域链 + 不释放"，缩写成一句话。** 同时也解释了上一阶段那个没人明说的现象 —— **你写过的每一个事件回调，全都是闭包**；只是它们捕获的多半是全局变量，所以你没感觉。

## 3. C# 类比可用度（本轮新增）

| JS | C# | 档 |
|---|---|---|
| 作用域链 / 词法作用域 | 局部作用域、嵌套作用域 | ✅ 同源 |
| `var` 穿透 `{}` | 无对应（C# 一直是块级） | ❌ 差异 |
| 垃圾回收 · 可达性 · 分代 | GC · GC Roots · Gen0/1/2 | ✅ 概念通 |
| 手动释放资源 | `IDisposable` / `using` | ❌ **JS 完全没有** |
| 闭包 | Lambda 捕获外部变量 | ✅ 概念同源（少见的几乎完全对应） |
| 循环里闭包捕获同一个变量 | C# 的 `for` + Lambda 也一样 | ⚠️ 两边同病 → **不是 JS 的锅** |

## 4. 静默失败复述（本课程的暗线）

| 你写的 | 实际发生 |
|---|---|
| `totel = 100`（漏了 `let`） | 凭空多一个全局变量，**无报错** |
| `for (var i…)` + 闭包 | 全部是同一个 `i`，**无报错** |
| `setInterval` 忘了 `clearInterval` | 内存慢慢涨，**无报错** |
| 闭包握着大对象 | 内存不降，**无报错** |

> 这一轮里**唯一会报错的是 `let` 的 TDZ**（声明前访问抛 `ReferenceError`）—— 记住它是例外，不是常态。

## 5. 三条工程纪律

1. **一律 `let` / `const`，不写 `var`** —— 一次性消灭"穿透块级""重复声明""循环闭包"三类问题
2. **写了 `setInterval`，当场就写 `clearInterval`** —— 定时器是第一个泄漏源
3. **闭包不用了就 `= null`** —— 尤其当它握着 DOM 或大数组
