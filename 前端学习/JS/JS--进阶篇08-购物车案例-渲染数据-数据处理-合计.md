==一：概念==

## 1. 为什么这三集必须一起讲

课程把它们切成三集，但它们**不是三个知识点，是同一个程序的三层**：

| 集 | 模块 | 干的事 |
|---|---|---|
| 173 | **渲染数据** | 数据 → HTML（把 `cart` 数组画成表格） |
| 174 | **数据处理** | 用户的点击 → 改数据 → 重新渲染 |
| 175 | **合计模块** | 算小计 / 总计 / 件数（派生数据） |

**只学 173，你得到的是"一个会画一次的表格"；三集连起来，你得到的才是"一个会跟着数据变的界面"。**

这才是这一轮真正的东西 —— 前面每一轮学的是**零件**（`map` / `filter` / `reduce` / 事件委托 / `innerHTML`），这一轮学的是**怎么把它们装成一台机器**。

## 2. ⭐⭐ 三层分离（本轮最该带走的心智模型）

```
              ┌─────────────────────────┐
              │  数据层（唯一真相）      │
              │  const cart = [ ... ]   │
              └───────────┬─────────────┘
                          │ 数据是输入
                          ▼
              ┌─────────────────────────┐
              │  渲染层  render(list)    │
              │  数据 → HTML 字符串      │
              └───────────┬─────────────┘
                          │ 顺便算
                          ▼
              ┌─────────────────────────┐
              │  计算层（派生数据）      │
              │  小计 / 总计 / 件数      │
              └─────────────────────────┘

        用户的点击 ────► 改「数据层」───► 再跑一遍渲染层
```

**三个层的职责，一句话各一条：**

- **数据层**：`cart` 数组。**它是唯一的真相**，界面上显示的一切都是它的投影。
- **渲染层**：`render(list)`。**只做一件事** —— 把传进来的数组画成 HTML。它**不改数据、不筛数据、不算总数**（算出来是为了显示，属于画的一部分）。
- **计算层**：小计、总计、件数。**它们是"算出来的"，不是"存在某个变量里的"。**

> 这三层不是课程里的名词，是我给你提炼的。**但你以后写任何一个带界面的程序，都是这三层** —— 不管是手写 JS，还是用 Vue / React。

## 3. ⭐⭐ 本轮第一原则：**能算出来的，就不要存**

这是整轮最容易违反、后果最隐蔽的一条。

**反例（新手必犯）**：

```js
let totalPrice = 0;                   // ← 把"总计"存成了一个变量

function addItem(item) {
  cart.push(item);
  // 忘了写 totalPrice += ...
}
```

现在你有**两个真相源**：`cart` 和 `totalPrice`。你把商品加进去了，但因为忘了同步，界面上总价还是旧的。**而且它不报错。**

**正例**：

```js
function getTotal(list) {                          // 总计是一个函数
  return list.reduce(function (acc, item) {
    return acc + item.price * item.count;
  }, 0);
}
```

**每次要显示的时候现算一遍。** 数据变了，算出来自然就变了 —— **根本不存在"忘了同步"这件事。**

⭐ **判断规则**：凡是**能从已有数据推出来**的东西（总计、件数、小计、平均分、是否全选……），**一律写成函数，不要存成变量或字段。**

> **C# 类比（这条你会非常熟）**：这正是 **ViewModel 的计算属性**。
> ```csharp
> public class CartVm {
>     public List<CartItem> Items { get; set; }
>     public decimal Total => Items.Sum(x => x.Price * x.Count);   // ← 算的，不是字段
>     public int Count => Items.Sum(x => x.Count);
> }
> ```
> 你在 WPF / ASP.NET 里**从来不会**单独维护一个 `Total` 字段然后手动加减 —— 因为你知道那必然会不同步。**JS 这里是一模一样的道理。**

## 4. 数据驱动的三件事，正好对应三集

| 集 | 动作 | 代码骨架 |
|---|---|---|
| 173 | **渲染**：数据 → DOM | `map` 翻字符串 → `join('')` → `innerHTML =` |
| 174 | **改数据**：点击 → 改数组 → 重渲染 | 事件委托 → `splice` / 改字段 → **再 `render(cart)`** |
| 175 | **算**：渲染时顺便算 | `reduce` 求和、`map` 求小计 |

⭐⭐ **124 集里最关键的一句**：**改完数据之后，必须重新渲染。**

```js
function plus(id) {
  const item = cart.find(function (x) { return x.id === id; });
  item.count++;          // ① 改数据
  render(cart);          // ② 重新渲染 ← 忘了这行，界面不动，而且不报错
}
```

**"改了数据但忘了重新渲染"**，是数据驱动里最经典的静默失败。

## 5. ⚠️ 两个具体的技术要点

**① 动态元素不能用普通方式绑事件**

购物车的每一行都是 `innerHTML =` 重新生成的。你**没法**在渲染完之后给每个按钮绑事件 —— 因为下一次渲染，那些按钮就是**全新的元素**了，之前绑的事件全丢。

**解法：事件委托**（第 4 轮学过）。**绑在不会变的父容器上**，靠事件冒泡接住子元素的点击：

```js
document.querySelector('.cart').addEventListener('click', function (e) {
  if (e.target.tagName !== 'BUTTON') return;         // 点的不是按钮，不管
  const id = Number(e.target.dataset.id);            // 从 data-id 认领是哪一行
  ...
});
```

⭐ **这一句是本轮第二个要背下来的东西：数据驱动的界面，事件一律委托到"容器"上。**

**② 从 `data-` 属性认出"点的是哪一行"**

渲染时给每个按钮写上 `data-id`，点击时从 `e.target.dataset.id` 读回来 —— **这就是"DOM 元素"和"数据里的某一条"之间唯一的桥**。

⚠️ `dataset.id` 读出来是**字符串**，用之前先 `Number(...)`（否则 `=== 3` 永远不成立）。

## 6. 完整数据流（一个闭环）

```
     ┌──► 点击按钮 ──► 事件委托捕获 ──► 读 data-id 找到那一条 ──┐
     │                                                          │
     │                                                          ▼
     │                                                    改数据层
     │                                                （count++ / splice）
     │                                                          │
     │                                                          ▼
     └────────── 用户在界面上看到变化 ◄── innerHTML 重写 ◄── render(cart)
                                                        （顺便算合计）
```

**这个圈，就是"数据驱动"的全部。** 你手写这一圈，是为了理解 Vue / React 在替你做什么 —— **数据一变，自动重画。**

==二：格式==

## 1. 三层骨架（照这个抄）

```js
// ═══ 数据层：唯一的真相 ═══
const cart = [
  { id: 1, name: '手机', price: 2999, count: 1, checked: true },
  { id: 2, name: '耳机', price: 199,  count: 2, checked: false }
];

// ═══ 计算层：全是函数，不存 ═══
function getTotal(list) {                      // 总价
  return list.reduce(function (acc, item) {
    return acc + item.price * item.count;
  }, 0);
}
function getCount(list) {                      // 总件数
  return list.reduce(function (acc, item) { return acc + item.count; }, 0);
}

// ═══ 渲染层：只画，不改 ═══
function render(list) {
  document.querySelector('.cart').innerHTML = list.map(function (item) {
    const subtotal = item.price * item.count;              // 行内小计（算出来的）
    return '<div class="row">'
         +   '<span>' + item.name + '</span>'
         +   '<span>￥' + item.price + '</span>'
         +   '<button data-id="' + item.id + '" data-act="minus">-</button>'
         +   '<span>' + item.count + '</span>'
         +   '<button data-id="' + item.id + '" data-act="plus">+</button>'
         +   '<span>小计 ￥' + subtotal + '</span>'
         +   '<button data-id="' + item.id + '" data-act="del">删除</button>'
         + '</div>';
  }).join('');

  // 合计（计算层的结果，只是显示出来）
  document.querySelector('.total').textContent = '合计 ￥' + getTotal(list);
}

// ═══ 事件层：改数据 → 重新渲染 ═══
document.querySelector('.cart').addEventListener('click', function (e) {
  if (e.target.tagName !== 'BUTTON') return;
  const id = Number(e.target.dataset.id);          // ⚠️ 转数字
  const act = e.target.dataset.act;

  if (act === 'plus') {
    cart.find(function (x) { return x.id === id; }).count++;
  } else if (act === 'minus') {
    const item = cart.find(function (x) { return x.id === id; });
    item.count > 1 ? item.count-- : cart.splice(cart.indexOf(item), 1);
  } else if (act === 'del') {
    const i = cart.findIndex(function (x) { return x.id === id; });
    cart.splice(i, 1);                             // 原地删除
  }

  render(cart);                                    // ⭐ 别忘了这行
});

render(cart);      // 页面一打开先画一次
```

## 2. 删除的两种写法（都行，理解区别）

```js
// 写法 A：splice —— 原地修改原数组（第 46 集学过）
const i = cart.findIndex(function (x) { return x.id === id; });
cart.splice(i, 1);

// 写法 B：filter —— 生成新数组，再替换回去
let cart2 = cart.filter(function (x) { return x.id !== id; });
```

| | `splice` | `filter` |
|---|---|---|
| 原数组 | **被改了** | 不动 |
| 通常配合 | `cart.splice(...)` | `cart = cart.filter(...)` |
| 变量声明 | `const` 够用 | 必须 `let`（要重新赋值） |

**都正确**，选一种保持一致即可。⚠️ 但**不要混着来** —— 一会儿原地改一会儿重新赋值，最容易出 bug。

## 3. 数量减到 0 怎么办？（一个产品决策，不是技术问题）

```js
item.count > 1 ? item.count-- : cart.splice(cart.indexOf(item), 1);
```

三种常见策略，**先想清楚再写代码**：

| 策略 | 写法 |
|---|---|
| 减到 1 就停住（不允许 0） | `if (item.count > 1) item.count--;` |
| 减到 0 自动删除 | 上面那行三元 |
| 允许 0（0 就是不要了） | `item.count--` 后另外处理 |

**⚠️ 别让数量变成负数** —— `count--` 没有下限保护，点到 -1 也不报错。

## 4. 合计怎么算（175）

```js
// 总价 = 每一项「单价 × 数量」加起来
list.reduce(function (acc, item) { return acc + item.price * item.count; }, 0);

// 只算勾选的（进阶：先 filter 再 reduce）
list.filter(function (x) { return x.checked; })
    .reduce(function (acc, item) { return acc + item.price * item.count; }, 0);

// 总件数
list.reduce(function (acc, item) { return acc + item.count; }, 0);
```

⭐ **注意那个 `0`** —— `reduce` 的初始值**必须给**。不给的话，空购物车会抛 `TypeError`（第 169 集那个坑）。**空购物车是真实场景**（用户删光了），所以这里绝不能省。

> **C# 对照**：`Items.Sum(x => x.Price * x.Count)` —— `Sum` **天然带"空集合返回 0"的语义**，所以 C# 里你从来没担心过这件事。**JS 的 `reduce` 没有这个保护，必须自己给初始值。这是本轮唯一一处"C# 更省心"的地方。**

## 完整购物车（可直接另存为 .html 打开）

```html
<!DOCTYPE html>
<html lang="zh-CN">
<head>
  <meta charset="UTF-8">
  <meta name="viewport" content="width=device-width, initial-scale=1.0">
  <title>购物车</title>
  <style>
    body { font-family: sans-serif; max-width: 720px; margin: 24px auto; }
    .row { display: flex; align-items: center; gap: 12px;
           padding: 10px 0; border-bottom: 1px solid #eee; }
    .row > span:nth-child(1) { flex: 1; }
    button { padding: 2px 10px; cursor: pointer; }
    .total { margin-top: 16px; font-size: 20px; font-weight: bold; color: #c00; }
    .empty { color: #999; padding: 24px 0; }
  </style>
</head>
<body>
  <h3>我的购物车</h3>
  <div class="cart"></div>
  <div class="total"></div>

  <script>
    // ═══ ① 数据层：唯一真相 ═══
    const cart = [
      { id: 1, name: '手机',   price: 2999, count: 1 },
      { id: 2, name: '耳机',   price: 199,  count: 2 },
      { id: 3, name: '充电器', price: 59,   count: 3 }
    ];

    // ═══ ② 计算层：能算的就不存 ═══
    function getTotal(list) {
      return list.reduce(function (acc, item) {
        return acc + item.price * item.count;
      }, 0);                                  // ⚠️ 初始值 0 不能省
    }
    function getCount(list) {
      return list.reduce(function (acc, item) { return acc + item.count; }, 0);
    }

    // ═══ ③ 渲染层：只画，不改数据 ═══
    const box = document.querySelector('.cart');
    const totalEl = document.querySelector('.total');

    function render(list) {
      if (list.length === 0) {                // 空购物车也是一种状态
        box.innerHTML = '<div class="empty">购物车是空的</div>';
      } else {
        box.innerHTML = list.map(function (item) {
          const subtotal = item.price * item.count;      // 行内小计（算出来的）
          return '<div class="row">'
               +   '<span>' + item.name + '（￥' + item.price + '）</span>'
               +   '<button data-id="' + item.id + '" data-act="minus">-</button>'
               +   '<span>' + item.count + '</span>'
               +   '<button data-id="' + item.id + '" data-act="plus">+</button>'
               +   '<span>小计 ￥' + subtotal + '</span>'
               +   '<button data-id="' + item.id + '" data-act="del">删除</button>'
               + '</div>';
        }).join('');
      }

      // 合计：算出来，只是显示在这儿
      totalEl.textContent = '共 ' + getCount(list) + ' 件，合计 ￥' + getTotal(list);
    }

    // ═══ ④ 事件层：改数据 → 重新渲染（事件委托）═══
    box.addEventListener('click', function (e) {
      if (e.target.tagName !== 'BUTTON') return;         // 过滤掉点空白

      const id  = Number(e.target.dataset.id);           // ⚠️ 转数字！
      const act = e.target.dataset.act;
      const item = cart.find(function (x) { return x.id === id; });

      if (act === 'plus'  && item) {
        item.count++;
      } else if (act === 'minus' && item) {
        if (item.count > 1) item.count--;                // 减到 1 停住，不删
        else cart.splice(cart.indexOf(item), 1);         // 想自动删就打开这行
      } else if (act === 'del') {
        const i = cart.findIndex(function (x) { return x.id === id; });
        if (i !== -1) cart.splice(i, 1);                 // ⚠️ -1 是真值，必须这样判
      }

      render(cart);                                      // ⭐ 数据改了，必须重画
    });

    render(cart);                                        // 首次渲染
  </script>
</body>
</html>
```

**照着这份代码，做三个自证实验：**

1. **把 `render(cart);` 那一行删掉** → 点 + 号，界面不动、**控制台不报错**。
   → 这就是本轮要你亲眼看到的：**"改了数据忘了重新渲染"是静默失败。**
2. **把 `Number(...)` 去掉** → 点 + 号，**什么也不发生**，还是不报错。
   → 因为 `dataset.id` 是字符串 `"1"`，而 `x.id` 是数字 `1`，`"1" === 1` 永远是 `false`。（**静默失败的经典脸**）
3. **页面打开后先用控制台 `cart.push({ id: 9, name: '鼠标', price: 99, count: 1 })`，再手动调 `render(cart)`** → 新商品出现了。
   → **数据变了，界面重画一遍就对了** —— 这就是整轮的总结论。

==四：总结==

## 1. 一句话记住三个

| 集 | 一句话 |
|---|---|
| 173 | 渲染 = `map` 翻字符串 → `join('')` → **`innerHTML =` 覆盖写入**（不是追加） |
| 174 | **改完数据必须重新渲染**；动态元素的事件一律**委托到容器**上 |
| 175 | 合计**是算出来的，不是存的** —— 能算出来的东西一律写成函数 |

## 2. ⭐⭐ 两个要背下来的结论

**① 能算出来的，就不要存。**

存了合计，你就有两个真相源，早晚不同步，**而且不报错**。C# 里你早就在用 `Total => Items.Sum(...)` 这个写法了 —— **JS 这里一模一样**。

**② 数据驱动的界面，事件一律委托到"容器"上。**

因为每次渲染都是 `innerHTML =` 整体重写，子元素是全新的，绑在子元素上的事件会全部丢失。**绑容器，靠冒泡接。**

## 3. ⭐ 收敛时刻：前面学的东西，这一轮全部就位了

这一轮一个新语法都没有，但它把前面五六轮的零件装成了机器：

| 前面学的 | 在本轮的位置 |
|---|---|
| `map` + `join`（第 133 集） | 渲染层：数据 → HTML 字符串 |
| `filter`（第 162 集） | 只显示勾选的商品 |
| `reduce`（第 169 集） | 计算层：总价 / 总件数 |
| `find` / `findIndex`（第 170 集） | 从 `data-id` 找到数据里对应的那一条 |
| 事件委托（第 4 轮 Web APIs） | 接住动态生成的按钮的点击 |
| `dataset`（Web APIs） | DOM 与数据之间唯一的桥 |
| 数据驱动四条铁律（第 133 集） | **本轮第一次完整落地** |

**第 133 集那四条铁律当时只是"讲给你听"，到这一轮第一次有了一台真机器去验证它。** 这就是为什么这一轮值得单独走一遍。

## 4. 架构铁律（购物车四条，可迁移到任何界面）

| 铁律 | 不遵守会怎样 |
|---|---|
| **数据层是唯一真相** | 改界面不改数据 → 两边对不上，下次重画就打回原形 |
| **渲染层只渲染** | 在渲染函数里改数据 → 下一轮渲染结果不可预测 |
| **能算的不存** | 两个真相源 → 静默不同步 |
| **改数据 → 必须重新渲染** | 界面不动，**且不报错**（本轮最经典的坑） |

## 5. 静默失败清单（本轮 5 条，5 条全不报错）

| 你写的 | 实际发生 |
|---|---|
| 改完数据忘了 `render(cart)` | 界面不动，**无报错** |
| `e.target.dataset.id === 3` | 字符串 `"3"` ≠ 数字 `3`，条件永远假，**无报错** |
| `if (cart.findIndex(...))` 判有没有 | `-1` 是真值，**永远成立**，**无报错** |
| `count--` 没有下限 | 点成负数，**无报错** |
| 渲染用了 `innerHTML +=` | 每次都追加一份，页面越点越长，**无报错** |

**会报错的一条**：`reduce` 空数组**不带初始值** → `TypeError`（本轮唯一"会出声"的，而且在"清空购物车"这个真实场景里必然触发）。

## 6. C# 类比可用度（本轮新增）

| JS 里的做法 | C# 对应 | 档 |
|---|---|---|
| 合计写成函数现算 | ViewModel 计算属性 `Total => Items.Sum(...)` | ✅ **思路完全一致** |
| 数据层是唯一真相 | MVVM 的 Model / ViewModel 是唯一真相 | ✅ 一致 |
| 渲染 = 数据 → DOM | XAML 绑定 / Razor 渲染视图 | ⚠️ C# 靠**绑定框架**，JS 要**手写重画** |
| 事件委托到容器 | WPF 的路由事件 / 事件冒泡 | ✅ 机制同源（**JS 靠 DOM 冒泡，C# 靠路由事件**） |
| `dataset.id` 认领哪一行 | `Tag` / `CommandParameter` 携带身份 | ✅ 一致（都是"DOM/控件 ↔ 数据"的桥） |
| `reduce(f, 0)` 求和 | `Items.Sum(...)` | ⚠️ **C# 的 `Sum` 空集合返回 0，JS 不给初始值会抛异常** |
| `cart.splice(i, 1)` | `List.RemoveAt(i)` | ✅ 一致（都是**原地**修改） |
| `cart.filter(...)` 替换原数组 | `list = list.Where(...).ToList()` | ✅ 一致 |

⭐ **本轮最大的 C# 迁移价值**：**"能算的不存"和"数据是唯一真相"，在 C# 世界里你已经信奉了很多年**（MVVM / DDD 都这么要求）。把它们平移到 JS 上，就是你写前端的架构骨架。

⚠️ **本轮最大的差异**：C# 里"数据变了界面自动变"是**框架给的**（绑定）；**JS 原生没有任何绑定 —— 你必须手动重画**。Vue / React 就是把这层手动劳动自动化了。
