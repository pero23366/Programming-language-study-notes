==一：概念==

## 1. 提升：JS 执行前会先把整段脚本"扫一遍"

**先看没有提升的世界长什么样**：JS 是"读一行执行一行"的解释型语言。如果真的一行一行来，那么下面这两件事就不可能成立 ——

```js
console.log(a);
var a = 1;

sayHi();                          // 先调用
function sayHi() { console.log('hi'); }   // 后定义
```

可它们都能跑（第一个打印 `undefined`，第二个正常打印 `hi`）。原因是：**JS 在执行之前，会先把整个作用域从头到尾扫一遍**，把要用的"名字"先登记好。这一步叫**预解析**。

整个执行分成两个阶段：

| 阶段 | 干什么 | 后果 |
|---|---|---|
| **① 预解析（扫描）** | 收集所有 `var` 变量名和 `function` 声明，先在内存里建好 | 名字比代码"先到" |
| **② 执行** | 逐行跑，**赋值在这一步才真正发生** | `var` 提前访问只有名字、没有值 → `undefined` |

**C# 完全没有这个概念。** 你在 C# 里写 `Console.WriteLine(a); int a = 1;`，编译器直接报"使用了未赋值的局部变量"，根本轮不到运行。**JS 把这个检查推到了运行期** —— 提升就是"先把名字登记好、值到了再填"的妥协产物。

## 2. 四种写法，各自提升成什么样

这是本集最该背下来的一张表：

| 你写的 | 预解析阶段登记什么 | 提前访问的结果 |
|---|---|---|
| `var a = 1;` | 只登记**名字** `a` | `undefined`（**一声不响**） |
| `function f() {}` | 登记**名字 + 整个函数体** | ✅ 可以正常调用 |
| `var f = function () {};` | 只登记名字 `f` | `undefined` → 调用时抛 **`TypeError: f is not a function`** |
| `let a = 1;` / `const a = 1;` | 登记了，但锁进**暂时性死区（TDZ）** | ❌ 抛 **`ReferenceError`** |

⭐ **一句话抓重点**：**只有 `function` 声明是"整个函数"被提升，其余都只提升名字。** 所以"先调用后定义"这个写法**只有函数声明能用**。

⚠️ 顺带一条常被问到的：`var` 和 `function` **同名**时：

```js
console.log(f);   // [Function: f]  ← 函数声明在预解析阶段胜出
var f = 1;
function f() {}
console.log(f);   // 1              ← 执行阶段那行赋值生效
```

**函数声明在预解析阶段优先于 `var` 变量声明。** 别写这种代码，但面试问得到。

## 3. `...`：一个符号，两副面孔

ES6 用同一个 `...` 表达两件事，**靠它在什么位置来判断**：

| 位置 | 名字 | 干什么 | 例子 |
|---|---|---|---|
| 函数**形参**位置（左边） | **剩余参数** | 把**多个实参收成一个数组** | `function f(...nums) {}` |
| 函数**调用** / 数组字面量位置（右边） | **展开运算符** | 把**一个数组摊成多个值** | `Math.max(...arr)` |

**剩余参数 ↔ C# 的 `params`，概念完全一致** ✅

```csharp
static int Sum(params int[] nums) { ... }   // C#
```
```js
function sum(...nums) { ... }               // JS
```

**两边都要求它必须是最后一个参数** ✅。C# 用 `params` 时要传数组，JS 的实参直接写一串就行。

**剩余参数比老写法 `arguments` 好在哪**：

| | `arguments` | `...nums` |
|---|---|---|
| 是什么 | **伪数组**（没有 `map`/`filter`） | **真数组**（数组方法全都能用） |
| 箭头函数里有吗 | ❌ 没有 | ✅ 有 |
| 能只取一部分吗 | 不能，总是全部 | 能（配合前面的普通形参） |

## 4. 箭头函数：本轮唯一被"解锁"的语法

**没有箭头函数的世界长什么样**：你想把一个短函数传给 `setInterval` / `addEventListener` / 排序，都必须老老实实写 `function () { ... }`，一个"加一"的小逻辑也要占四行。

```js
// 旧写法
const add = function (a, b) { return a + b; };
// 箭头函数
const add = (a, b) => a + b;
```

**↔ C# 的 Lambda 表达式，语法几乎一一对应** ✅ —— 这是你早就熟的东西：

```csharp
Func<int, int, int> add = (a, b) => a + b;   // C#
```
```js
const add = (a, b) => a + b;                 // JS
```

⚠️ **但有一条差异要命**（第 192 集会专门讲透）：**箭头函数没有自己的 `this`**。

一条 **`this`**、一条 **`arguments`**、一条 **`prototype`** —— 这三样普通函数自带的东西，箭头函数**都没有**。它内部的 `this` 不是"自己的"，而是**顺着作用域链去外层取**。

⭐ **想通它其实不难**：箭头函数取 `this` 的方式，**跟取一个普通变量完全一样** —— 外层作用域里有什么，它就拿到什么。这**不是新机制，就是第 154 集的闭包**。一句话收口：

> **箭头函数 = 闭包 + 简写 + 没有自己的 `this` / `arguments` / `prototype`。**

==二：格式==

## 1. 提升速查（把一、§2 那张表记成图）

```
预解析阶段：  var a  ──▶ 登记名字        function f(){} ──▶ 登记名字 + 函数体
              let/const ──▶ 登记但锁进 TDZ
执行阶段：    赋值才真正发生
```

三条实用结论：

1. **`function` 声明可以在定义之前调用**；`var f = function () {}` **不行**
2. **`var` 提前访问得到 `undefined`**，不报错（静默失败的经典款）
3. **`let` / `const` 提前访问抛 `ReferenceError`** —— 这其实是**好事**，它把静默的 `undefined` 换成了明确的报错

## 2. `...` 的两种位置

```js
// ① 左边（形参）—— 收集
function sum(...nums) { }        // nums 是真数组，[1,2,3]
sum(1, 2, 3);

// ② 右边（调用/字面量）—— 摊开
Math.max(...[1, 5, 3]);          // 等价于 Math.max(1, 5, 3)
const merged = [...arr1, ...arr2];       // 合并数组
const copyArr = [...arr];                // 浅拷贝数组
const merged2 = { ...obj1, ...obj2 };    // 合并对象
const copyObj = { ...obj };              // 浅拷贝对象
const chars = [...'abc'];                // ['a', 'b', 'c']
```

⚠️ **三条边界**：

1. **剩余参数必须在最后一位**，否则语法错误（这条会报错，算好相处的坑）
2. **展开对象是浅拷贝** —— 只复制**第一层**，嵌套的对象仍然是同一个（第 187 浅拷贝、189 深拷贝从这里接）
3. **展开只认"可迭代"的东西**：`[...document.querySelectorAll('div')]` ✅ 可以（节点集合可迭代）；但 `[...{a:1}]` ❌ 不行 —— 对象要用 `{...obj}` 这种**字面量展开**，它复制的是"可枚举的自有属性"

## 3. 箭头函数的四种简写

```js
const f1 = (a, b) => a + b;          // 多个参数：括号不能省
const f2 = x => x * 2;               // 单个参数：括号可以省
const f3 = () => console.log('hi');  // 没有参数：括号必须留
const f4 = (a, b) => {               // 多行：必须有 {} 和 return
  const s = a + b;
  return s;
};
const f5 = x => ({ n: x });          // ⚠️ 直接返回对象字面量：要包一层圆括号
```

最后一条最容易踩：`x => { n: x }` 里的 `{}` 会被当成**函数体**，于是它什么都不返回。

## 4. 什么时候**不能**用箭头函数

| 场景 | 为什么不能 | 怎么办 |
|---|---|---|
| 事件回调里要用 `this` 指当前元素 | 箭头函数没有自己的 `this`，拿到了外层的 | 用 `function () {}` |
| 要当构造函数 `new` 用 | 没有 `prototype`，`new` 会抛 `TypeError` | 用普通函数 |
| 需要 `arguments` 对象 | 箭头函数没有 `arguments` | 用 `...nums` 或普通函数 |

**反过来，什么时候该用**：只是"一段逻辑"，不关心 `this` 是谁 —— 数组方法的回调、`setInterval`、排序比较函数，全部用箭头函数。

==三：代码==

## 1. 提升的三个实验（放进 `.html` 直接看 Console）

```html
<!DOCTYPE html>
<html lang="zh-CN">
<head><meta charset="UTF-8"><title>提升实验</title></head>
<body>
  <script>
    // 实验 ① var 只提升名字 → undefined，不报错
    console.log('①', a);       // undefined
    var a = 1;
    console.log('①', a);       // 1

    // 实验 ② 函数声明整体提升 → 先调用后定义，能跑
    sayHi();                   // hi
    function sayHi() { console.log('hi'); }

    // 实验 ③ 函数表达式只提升名字 → 调用时是 undefined
    try {
      sayBye();                // TypeError: sayBye is not a function
    } catch (e) {
      console.log('③', e.name, e.message);
    }
    var sayBye = function () { console.log('bye'); };

    // 对比：let 是 ReferenceError（不是 undefined）
    try {
      console.log(c);          // ReferenceError: Cannot access 'c' before initialization
    } catch (e) {
      console.log('④', e.name);
    }
    let c = 3;
  </script>
</body>
</html>
```

**看点**：`①` 不报错、`③` 报的是 `TypeError`（不是 `ReferenceError`）、`④` 才是 `ReferenceError`。三个结果不一样，是因为三种声明的登记方式不同。

## 2. 剩余参数 + 展开

```js
// 剩余参数：收集
function sum(...nums) {
  let total = 0;
  for (let i = 0; i < nums.length; i++) {
    total = total + nums[i];
  }
  return total;
}
console.log(sum(1, 2, 3));      // 6
console.log(sum(1, 2, 3, 4, 5)); // 15

// 普通形参 + 剩余参数配合
function show(first, ...rest) {
  console.log('第一个', first, '其余', rest);
}
show('a', 'b', 'c');            // 第一个 a 其余 ['b', 'c']

// 展开：摊开（Math.max 不接数组，这是最经典的用途）
const arr = [10, 5, 28, 3];
console.log(Math.max(...arr));  // 28

// 合并 + 浅拷贝
const arr1 = [1, 2];
const arr2 = [3, 4];
console.log([...arr1, ...arr2]);        // [1, 2, 3, 4]

const p1 = { name: '张三', age: 18 };
const p2 = { age: 20, city: '北京' };
console.log({ ...p1, ...p2 });          // { name:'张三', age:20, city:'北京' } —— 同名后者覆盖前者

// ⚠️ 浅拷贝的证据：嵌套对象还是共享的
const src = { info: { score: 1 } };
const copy = { ...src };
copy.info.score = 99;
console.log(src.info.score);            // 99 ← 原对象被改了！
```

## 3. 箭头函数改写（含"不能用"的反例）

```html
<!DOCTYPE html>
<html lang="zh-CN">
<head><meta charset="UTF-8"><title>箭头函数</title></head>
<body>
  <button id="a">用 this 改颜色</button>
  <button id="b">不改颜色</button>

  <script>
    // ✅ 能用：不关心 this 是谁
    const double = arr => arr.map(n => n * 2);
    console.log(double([1, 2, 3]));      // [2, 4, 6]

    setInterval(() => console.log('每秒一次'), 1000);

    // ❌ 不能用：这里的 this 本该是「被点击的那个按钮」
    document.querySelector('#b').addEventListener('click', () => {
      this.style.color = 'red';          // this 不是按钮！(严格看它是 window/undefined)
    });

    // ✅ 正确写法：普通函数才有自己的 this
    document.querySelector('#a').addEventListener('click', function () {
      this.style.color = 'red';          // this = 被点击的按钮
    });
  </script>
</body>
</html>
```

**自证实验**：把 `#a` 的回调也改成箭头函数 → 点击**不再变色**，而且 **Console 里也不报错**（静默失败）。这就是为什么"箭头函数"这一集必须和 `this` 那集一起记。

## 4. 把上一轮的循环绑事件改成箭头函数

```js
const btns = document.querySelectorAll('button');
for (let i = 0; i < btns.length; i++) {
  btns[i].addEventListener('click', () => {
    console.log('我原来是第 ' + (i + 1) + ' 个');   // 依然正确打印 1 / 2 / 3
  });
}
```

**行为完全不变** —— 因为这里**根本没用 `this`**，只用了 `i`（靠闭包捕获）。这正好印证了那句话：**箭头函数出问题的唯一原因，就是它没有自己的 `this`。**

| 集 | 一句话 |

| 156 | **同一个 `...`**：在左边是**收集**，在右边是**摊开**；摊开只做浅拷贝 |

## 2. ⭐ 收敛时刻一：155 给 152 的表补上了机制

上一轮 152 那张表里写了两条"结果"：`var` 提前访问得 `undefined`、`let` 提前访问抛 `ReferenceError`。**当时只是现象，155 给出了原因** —— 因为预解析阶段登记方式不同：`var` 只登记名字，`let` 登记完还锁进 TDZ。

> **TDZ 不是 JS 在找麻烦，它就是"把 `undefined` 换成明确报错"的一次补救。** 凡是遇到"JS 静默失败"的抱怨，这里是一个反例：**JS 自己也在往"早点报错"的方向改。**

## 3. ⭐ 收敛时刻二：箭头函数不是新机制

箭头函数没有自己的 `this` —— 那它的 `this` 从哪来？**从外层作用域链上取，跟取一个普通变量完全一样。** 所以：

> **箭头函数 = 闭包 + 简写 + 没有自己的 `this` / `arguments` / `prototype`。**
> 第 154 集那道"函数 + 出生地"的题，到这里第二次出现了。

## 5. 静默失败复述（本课程的暗线）

| 你写的 | 实际发生 |
|---|---|
| `console.log(a)` 在 `var a = 1` 之前 | 打印 `undefined`，**无报错** |
| `x => { n: x }` 想返回对象 | 返回 `undefined`，**无报错** |
| 事件回调用了箭头函数又要 `this` | `this` 悄悄变成了别的东西，**点击无反应也无报错** |
| `copy.info.score = 99` 改浅拷贝 | 原对象一起被改，**无报错** |

> 本轮**会报错**的有：`let` 提前访问（`ReferenceError`）、`var f = function(){}` 提前调用（`TypeError`）、剩余参数不在最后（`SyntaxError`）。**报错的三条都是"写错了"，静默的四条全是"逻辑错了"** —— 后者才需要你自己盯。
