## 1. 节流综合案例：记录视频播放时间（198）—— 🧪 实操，讲架构

### 1.1 需求与问题

**需求**：用户看视频看到一半关掉页面，下次打开要能**接着上次的位置继续播**。

**要实现它，只要两件事**：① 播放时**不断把当前时间存下来**；② 打开页面时**把存的时间读回去**。

**问题是第 ① 件的频率**：

```js
video.addEventListener('timeupdate', function () {
  // ⚠️ timeupdate 大约每 250ms 触发一次 —— 也就是每秒 4 次
  // 一个 10 分钟的视频，这里要执行 2400 次
  localStorage.setItem('videoTime', this.currentTime);
});
```

⭐ **这就是 197 集那个节流的完美实战场景** —— **它不需要每次触发都执行，只需要"每隔一段记一次"**。

### 1.2 核心代码

```js
// ⭐ 直接用 197 集写的节流（一个字都不用改）
function throttle(fn, interval) {
  let last = 0;
  return function (...args) {
    const now = Date.now();
    if (now - last >= interval) {
      last = now;
      fn.apply(this, args);          // ⭐ this 和参数都透传了
    }
  };
}

const video = document.querySelector('#video');

// ① 播放时：每 1 秒最多记录一次（而不是每 250ms）
const save = throttle(function () {
  localStorage.setItem('videoTime', this.currentTime);   // ⭐ 这里的 this 是 video
}, 1000);
video.addEventListener('timeupdate', save);

// ② 打开时：把上次的位置读回来
video.addEventListener('loadedmetadata', function () {
  const t = localStorage.getItem('videoTime');
  if (t) {
    this.currentTime = Number(t);    // ⚠️ localStorage 读出来是字符串
  }
});
```

### 1.3 ⭐ 这个案例值得单独看的三点

**① 它验证了 194 集的 `apply` 和 192 集的 `this` 真的有用**

```js
const save = throttle(function () {
  localStorage.setItem('videoTime', this.currentTime);   // this 是哪来的？
}, 1000);
```

**这个回调里的 `this` 能是 `video`，完全是因为节流函数内部写了 `fn.apply(this, args)`。** 如果当初那个 `apply` 写成 `fn()`，这里 `this` 就变成 `window`，`this.currentTime` 会是 `undefined` —— **而且不报错，只是"存不上"**。

⭐ **一个抽象的工具函数写对了，业务里就能直接用 —— 这就是"写工具"的价值。**

**② `localStorage` 只能存字符串（回扣第 11 轮）**

```js
localStorage.setItem('videoTime', this.currentTime);   // 存进去是数字，出来是字符串
const t = localStorage.getItem('videoTime');           // '123.456'
this.currentTime = Number(t);                          // ⚠️ 必须先转
```

**这是第 11 轮反复强调过的"强耦合"** —— **存进去的东西和读出来的东西不是同一个类型。** 不 `Number()` 也能跑（因为 `video.currentTime` 会自动转），**但这是靠运气** —— 该转就转。

**③ 它是"数据驱动"的一次自然应用（回扣第 08 轮）**

```
播放位置（数据）→ 节流存下来 → 下次读回来 → 设回 video
```

**这里的"数据"就是播放位置** —— `localStorage` 是它跨会话的落点。**三层分离的思路（数据是唯一真相）在这里依然成立。**

### 1.4 ⚠️ 一个真实的边界：节流会"丢掉最后一次"

**节流是"每隔一段执行一次"，所以它有个固有缺陷**：

> 用户看视频看到 10:00 关掉页面 —— **如果关掉的那一刻刚好不在"节流窗口"里，最后这不到 1 秒的进度就丢了。**

**这在大多数场景下可以接受**（丢 1 秒进度无所谓）。**但如果是"表单自动保存"，丢最后一次就很严重了** —— 那时要用 **"防抖 + `beforeunload` 兜底"** 或 "节流 + 失焦时强制存一次"。

⭐ **这个权衡值得记住**：**防抖和节流都是"用少量数据的丢失，换性能"** —— **什么时候能接受这个损失，是设计时要问自己的问题。**

## 2. 防抖 / 节流的场景选择

| 场景 | 用什么 | 理由 |
|---|---|---|
| 搜索框输入 | **防抖** | 只关心最终打了什么 |
| 窗口 resize / 滚动 | **节流** | 要过程中的持续反馈 |
| **视频播放进度记录** | **节流** | 每隔一段存一次就够 |
| 按钮防连点（提交订单） | **防抖** | 只认最后一次点击 |
| 鼠标移动轨迹 | **节流** | 要持续的坐标 |

## 节流案例完整实现（198）

```html
<!DOCTYPE html>
<html lang="zh-CN">
<head>
  <meta charset="UTF-8">
  <title>记录视频播放时间</title>
  <style>
    body { font-family: sans-serif; max-width: 640px; margin: 24px auto; }
    video { width: 100%; background: #000; }
    .tip { color: #666; font-size: 14px; margin-top: 12px; }
    code { background: #f0f0f0; padding: 1px 5px; border-radius: 3px; }
  </style>
</head>
<body>
  <h3>视频播放进度记忆</h3>
  <!-- 换成你自己能访问的视频地址 -->
  <video id="video" controls
         src="https://www.w3schools.com/html/mov_bbb.mp4"></video>
  <p class="tip">
    播放几秒后刷新页面 —— 会从上次的位置继续。<br>
    打开控制台看 <code>localStorage.getItem('videoTime')</code>，
    它每 1 秒才更新一次（不是每 250ms）。
  </p>

  <script>
    // ═══ 节流（197 集的原样复用）═══
    function throttle(fn, interval) {
      let last = 0;
      return function (...args) {
        const now = Date.now();
        if (now - last >= interval) {
          last = now;
          fn.apply(this, args);          // ⭐ this 和参数透传 —— 这一行让下面的 this 有用
        }
      };
    }

    const video = document.querySelector('#video');

    // ═══ ① 播放时记录（每 1 秒最多一次）═══
    video.addEventListener('timeupdate', throttle(function () {
      // ⭐ 这里的 this 就是 video —— 因为节流里调的是 fn.apply(this, args)
      localStorage.setItem('videoTime', this.currentTime);
      console.log('已记录：', this.currentTime.toFixed(1), '秒');
    }, 1000));

    // ═══ ② 打开时恢复 ═══
    video.addEventListener('loadedmetadata', function () {
      const saved = localStorage.getItem('videoTime');
      if (saved) {
        this.currentTime = Number(saved);     // ⚠️ 读出来是字符串
        console.log('从上次的位置继续：', Number(saved).toFixed(1), '秒');
      }
    });
  </script>
</body>
</html>
```

**三个自证实验：**

1. **打开控制台，播放几秒** —— 会看到"已记录"每 **1 秒**打印一次，**而不是疯狂的连续打印**（`timeupdate` 实际是每 250ms 一次）。**这就是节流生效。**
2. **刷新页面** —— 视频会从上次的位置继续。**这说明数据确实存下来了。**
3. **把节流里的 `fn.apply(this, args)` 改成 `fn()`** —— 再播放，控制台会打印"已记录：undefined"或者干脆报错。**这就是 194 集那个 `apply` 存在的意义。**

## 动手小练习（不留超纲作业）

**把这套"节流 + `localStorage`"搬到另一个场景**：给一个 `<textarea>` 做**草稿自动保存**。

1. 用户输入时（`input` 事件），**每 2 秒最多把内容存一次**到 `localStorage`
2. 页面加载时，**把草稿读回来填进 `textarea`**

**然后想一个问题**：如果把节流换成**防抖**，用户体验有什么不同？

（提示：**节流 → 输入过程中也在持续保存（最多丢 2 秒）；防抖 → 只有你停手 2 秒后才保存（如果一直打字不停手，一旦崩溃就全丢）。** 这个对比能让你真正理解两者的取舍。）

## 2. ⭐⭐ 三句最该带走的话

**① `this` 那句：** **看函数名前面有没有"点" —— 点前是谁，`this` 就是谁；没有点就是 `window`。箭头函数从不参与这套规则。**

**② 原型那句：** **数据住在实例自己身上，方法住在原型上被大家共享；找属性先找自己，找不到就顺着 `__proto__` 一层层往上，直到 `null`。**

**③ 拷贝那句：** **`b = a` 不是拷贝，是"同一个对象两个名字"；`{...a}` 只保护第一层；判据永远是 `===`。**

## 3. ⭐ 整个课程最大的收获，可能不是语法

**这 200 集真正的教学主线，是"静默失败"** —— 从第 1 集到第 200 集，反复出现的是同一件事：

| 你写错的 | JS 的反应 |
|---|---|
| `u1.eat === u2.eat`（方法挂 `this`） | 内存浪费，**不报错** |
| `const fn = obj.say; fn()` | `this` 丢了，**不报错** |
| `{...obj}` 以为深拷贝了 | 内层共享，**不报错** |
| `JSON` 方法拷 `Date` | 变字符串，**不报错** |
| `forEach` 里 `return` | 只当 `continue`，**不报错** |
| `findIndex` 的 `-1` 当真值 | 条件永远成立，**不报错** |
| `timer` 写在返回函数里面 | 防抖失效，**不报错** |
| 忘了 `render(cart)` | 界面不动，**不报错** |
| `dataset.id` 没 `Number()` | 永远不相等，**不报错** |

⭐ **C# 会编译不过或抛异常的，JS 多半一声不响。**

**所以这 200 集的收获可以浓缩成一句**：

> **写 JS 时，别问"这样写会报错吗"，要问"这样写的**行为**是我想要的吗"** —— **因为前一个问题的答案，经常是"不会"。**

**这就是你作为 C# 程序员学 JS，最需要换掉的那个直觉。**
