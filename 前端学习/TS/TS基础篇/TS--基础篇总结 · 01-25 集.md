==一：概念==

## 1. 这 25 集到底在讲什么（一句话）

> **把「变量的类型」从运行时搬到源码里，写下来，让编译器替你看着。**

JS 里类型跟着值走：

```js
let x = 1;      // 此刻是数字
x = 'hello';    // 下一秒是字符串，没人管
```

TS 里你要先声明，再赋值：

```ts
let x: number = 1;
x = 'hello';    // ❌ TS2322: Type 'string' is not assignable to type 'number'
```

**25 集，就是从这一个 `: number` 展开的全部内容。** 剩下的都是「不同类型的名字怎么写」。

---

## 2. 一条贯穿全篇的暗线：类型注解是「注释」，不是「代码」

这是你在 01-03 集该建立、在 07-25 集被反复验证的事实：

```ts
let age: number = 18;
```

`tsc` 处理完，产物是：

```js
let age = 18;
```

`: number` 这七个字符**从来没进过产物**。它不是运行时的东西，是给编辑器和编译器看的一张便签。

⭐ **所以这 25 集的所有类型，都有一个共同性质：它们只在「写代码的那几分钟」存在。** 一旦程序跑起来，全都消失了。

这就是为什么：

- 类型写错了，`node x.ts` 照样跑
- 类型标 `User`，后端返回 `null` 照样崩
- 你写 `p.name` 拼错了，编译器能拦你，**运行时拦不住**

## 3. 类型注解（07-10）

### 3.1 语法形状

```ts
let 变量名: 类型 = 值;
```

| | C# | TS |
|---|---|---|
| 写法 | `int age = 18;` | `let age: number = 18;` |
| 类型位置 | **在名字前面** | **在名字后面** |
| 常用叫法 | 声明 | 类型注解（type annotation） |

⭐ 记忆：像填表 —— **「年龄：18」**，先写名字，冒号，再写类型。

### 3.2 原始类型只有 7 个

| 类型 | 说明 | 坑 |
|---|---|---|
| `number` | 所有数字 | ⚠️ **只有一个**，涵盖 C# 的 `int`/`long`/`float`/`double`/`decimal` |
| `string` | 字符串 | 三种引号都行 |
| `boolean` | `true` / `false` | — |
| `undefined` | 没赋值 | 🔴 和 `null` 不是一回事 |
| `null` | 赋了空 | 🔴 同上 |
| `symbol` | 唯一值 | 用得少 |
| `bigint` | 大整数 | 课程基本没提 |

### 3.3 🔴 坑一：`number` 是全课程最大的精度陷阱

```ts
let id: number = 9007199254740993;   // 2^53 + 1
console.log(id);                     // 9007199254740992  ← 变了
```

TS 的 `number` 就是 JS 的 `number` = **IEEE 754 双精度**，只有 53 位有效整数位。超过 `2^53 - 1` 就丢精度。

⭐ **这条对你特别扎心**：你后端 C# 里 `long` 的雪花 ID（19 位）直接塞进 TS 的 `number`，**一定出错**，而且不报错。工程上的做法是：**接口里凡是 19 位的 ID，一律用 `string` 传。**

### 3.4 🔴 坑二：两个「空」

C# 只有一个 `null`。JS/TS 有两个：

| | 什么意思 | 什么时候出现 |
|---|---|---|
| `undefined` | **没赋值** | 声明了没初始化、函数没 `return`、访问不存在的属性 |
| `null` | **被赋成了空** | 有人主动写的，通常表示「查过了，没有」 |

```ts
let a: undefined = undefined;   // 没赋值
let b: null = null;             // 主动置空
```

⚠️ **`undefined` 更容易骗你**：它会在「属性名拼错」时出现 —— `user.nmae` 返回 `undefined`，不报错。

## 4. 数组 / 联合 / 别名（11-13）

### 4.1 数组两种写法，完全等价

```ts
let nums: number[] = [1, 2, 3];
let nums2: Array<number> = [1, 2, 3];   // 一样
```

| 写法 | C# 对照 |
|---|---|
| `number[]` | `int[]` ⭐⭐⭐⭐⭐ 直接迁移 |
| `Array<number>` | `List<int>` ⭐⭐ 长得像，但语义是「数组」不是「列表」 |

⭐ **选哪个**：日常一律 `number[]`，短、跟 C# 的直觉一致。`Array<T>` 只在跟泛型混写时更整齐。

### 4.2 🆕 联合类型 `A | B` —— TS 的日常

```ts
let id: string | number;
id = 'abc';    // ✅
id = 123;      // ✅
id = true;     // ❌
```

C# 里没有对应物，你得靠 `object` + 运行时判断，或者上泛型 + `Nullable<T>`，都笨重得多。

⭐ **为什么 TS 里到处都是它**：JS 的函数「可能返回字符串也可能返回 null」是常态，不是例外。

⚠️ **但记住一句，后面会一直用到**：**拿到联合类型，必须「收窄」才能用。**

```ts
let id: string | number = 'abc';
console.log(id.length);   // ❌ Property 'length' does not exist on type 'number'
```

因为 `number` 没有 `length`。你得先问一句「你是哪种」—— 这引出后面的 `typeof` 守卫（26-32 集）和类型断言（25 集）。

### 4.3 类型别名 `type`

```ts
type ID = string | number;
type Point = { x: number; y: number };

let uid: ID = 123;      // ✅
```

| | C# 对照 | 可用度 |
|---|---|---|
| `type ID = string \| number` | 无（`using X = ...` 只能起名，不能造联合） | ⭐ |
| `type Point = {...}` | 无（得写 class / record） | ⭐⭐ |

⚠️ **`type` 不是「定义一个新类型」，是「给一个已有的类型描述起个名」。** 编译后连名字都没了。

## 5. 函数类型 / void / 可选参数（14-17）

### 5.1 三种写法

**① 单独标参数和返回值**（最常用）

```ts
function add(a: number, b: number): number {
  return a + b;
}
```

**② 函数类型表达式**（把函数当成值来约束）

```ts
const add: (a: number, b: number) => number = (a, b) => a + b;
//        └────────── 这是「类型」──────────┘   └─ 这是「值」─┘
```

⚠️ 右边 `(a, b)` 不用再标类型 —— 左边已经说了，TS 会自动推。

**③ 用类型别名抽出来**

```ts
type AddFn = (a: number, b: number) => number;
const add: AddFn = (a, b) => a + b;
```

| | C# | 可用度 |
|---|---|---|
| `(a: number) => number` | `Func<int, int>` | ⭐⭐⭐⭐⭐ |
| `(a: number) => void` | `Action<int>` | ⭐⭐⭐⭐ ⚠️ 见下 |

⭐ **一个容易搞混的箭头**：类型里的 `=>` 是**类型语法**，跟写函数体的 `=>` 是两回事。看 `const add: (a) => number = (a) => a`，左边那个 `=>` 在类型里，右边那个才是代码。

### 5.2 🔴 坑：`void` 不强制

```ts
type Fn = () => void;
const f: Fn = () => 123;    // ✅ 合法！返回了数字也不报错
```

**C# 里 `Func<int>` 绝不能赋给 `Action`**，编译直接不给过。TS 偏偏允许。

⭐ 为什么？因为要兼容 JS：`[1,2,3].forEach(x => arr.push(x))` —— `push` 返回数字，但 `forEach` 的回调签名是 `void`，不放开就没法写。

⚠️ **所以 `void` 的含义不是「不许返回值」，是「我不用你的返回值」。** 这是「长得像 C# 但机制不同」的第一个实例。

### 5.3 🟡 三种「可以不传」，完全不是一回事

```ts
function a(x?: number) {}          // ① 可选参数：可以不传
function b(x: number = 1) {}       // ② 默认参数：不传就用 1
function c(x: number | undefined) {} // ③ 必须传，但可以传 undefined
```

| 写法 | `f()` | `f(undefined)` | 说明 |
|---|---|---|---|
| `x?: number` | ✅ | ✅ | **必须放参数列表最后** |
| `x: number = 1` | ✅ | ✅ | 有默认值时类型会推成 `number` |
| `x: number \| undefined` | ❌ | ✅ | 缺参数直接报错 |

⚠️ **顺序限制**：可选参数必须放最后，`function f(a?: number, b: number)` 直接编译不过。C# 里 `int? a = null` 也一样要在后面，这条能迁移。

## 6. 对象类型 / 接口（18-22）

### 6.1 三种写法，描述同一个东西

```ts
// ① 内联对象类型
let p: { name: string; age: number } = { name: 'pero', age: 20 };

// ② 类型别名
type Person = { name: string; age: number };

// ③ 接口
interface Person { name: string; age: number }
```

⭐ **这三种在「只有一个对象形状」时几乎没区别。** 区别在于能不能复用、能不能扩展。

### 6.2 对象可选属性

```ts
interface Person {
  name: string;
  age?: number;      // 可以有，可以没有
}

const a: Person = { name: 'pero' };              // ✅
const b: Person = { name: 'pero', age: 20 };     // ✅
```

⚠️ **`age?: number` 的类型是 `number | undefined`**，用它之前要判空（或者用 `?.`）。

### 6.3 🔴🔴 结构化类型：TS 全课程最大的一处「跟 C# 相反」

**这是 18-22 集埋下、43-48 集引爆的雷，现在只需要「听到」：**

```ts
interface Person { name: string; age: number }

const obj = { name: 'pero', age: 20, sex: 'm' };
const p: Person = obj;      // ✅ 多一个字段，照样能赋值！
```

**C# 是名义类型**：`A` 能赋给 `B`，前提是代码里写了 `A : B`。

**TS 是结构类型**：只要「长得够像」，就能赋值 —— **你根本不需要写 `implements`**。

⭐ 这一句现在只要记住形状，不用会用：

> **C# 问「你是不是我的子类」，TS 只问「你长得像不像」。**

⚠️ 但有一个**假象**要注意：直接写对象字面量时会报错。

```ts
const p: Person = { name: 'pero', age: 20, sex: 'm' };   // ❌ 报错：多余属性
```

这叫「多余属性检查（excess property check）」，**只在直接写字面量时生效**，先赋给变量就绕过去了（如上例）。**它不是类型安全保证，只是防手滑。**

### 6.4 🟡 `interface` vs `type` 怎么选

| 能力 | `interface` | `type` |
|---|---|---|
| 同名自动合并（声明合并） | ✅ | ❌ |
| 写联合 `A \| B` | ❌ | ✅ |
| 写元组 `[string, number]` | ❌ | ✅ |
| 给基本类型起别名 | ❌ | ✅ |
| `extends` 继承多个 | ✅ | 用 `&` |
| 被 class `implements` | ✅ | 对象形状可以 |

⭐ **工程上的默认选择**：**描述「对象形状」用 `interface`，其余（联合 / 元组 / 别名）只能 `type`。** 团队里通常就这么约定，不用纠结。

### 6.5 接口继承

```ts
interface Person { name: string; age: number }

interface Student extends Person {
  grade: string;
}

const s: Student = { name: 'pero', age: 20, grade: '大一' };
```

| | C# | 可用度 |
|---|---|---|
| `interface A extends B` | `interface A : B` | ⭐⭐⭐⭐⭐ 直接迁移 |
| 多继承 | `extends A, B` | ⭐⭐⭐⭐ |

## 7. 元组 / 类型推论 / 类型断言（23-25）

### 7.1 元组：定长、定序、定类型的数组

```ts
let pos: [number, number] = [39.5, 116.3];   // 经纬度
let entry: [string, number] = ['pero', 20];
```

| | 写法 | 区别 |
|---|---|---|
| 元组 | `[number, number]` | **长度固定，位置类型固定** |
| 数组 | `number[]` | 长度任意，每个元素同类型 |

```ts
pos[0] = 'abc';     // ❌ 第一个位置必须是 number
pos[2] = 1;         // ❌ 长度固定，不能加
```

| | C# | 可用度 |
|---|---|---|
| `[string, number]` | `(string, int)` ValueTuple | ⭐⭐⭐⭐ 很像 |
| 差别 | C# 元组有具名元素 `.Item1` / `.name`，TS 靠位置 | — |

### 7.2 类型推论：不写注解，TS 自己算

```ts
let age = 18;              // 推成 number
let name = 'pero';         // 推成 string
const add = (a: number) => a + 1;   // 返回值推成 number
```

**能省的地方就省** —— 变量声明并赋值时、函数返回值，这两处 TS 都算得出来。

#### 🔴 但有一个 C# 没有的差异

```ts
let a = 1;      // 类型是 number
const b = 1;    // 类型是 1  ← 字面量类型！
```

`const` 声明的原始类型会被推成**字面量**，因为它不许改，TS 干脆把「值」当类型。`let` 会「拓宽」成 `number`。

| | C# | TS |
|---|---|---|
| `var a = 1` | 一律 `int` | 无对应 |

⚠️ 这个差异现在看着没用，**26 集起的「字面量类型」全靠它**。它是下面那张「解锁边界」表里唯一被提前解锁的东西。

### 7.3 🔴🔴 类型断言 `as`：只骗编译器，不做任何事

```ts
const x = 'hello' as number;     // ✅ 编译通过
console.log(typeof x);           // string ← 运行时还是字符串
```

C# 的强转 `(T)x` 会在运行时执行 `castclass`，类型不对**当场抛 `InvalidCastException`**。

TS 的 `as` 编译后**一个字都不剩**，它只是对编译器说「听我的，别问了」。

```ts
const user = {} as Person;
console.log(user.name);     // undefined ← 不报错，静默失败
```

⭐ **这是「类型擦除」在 25 集里的第一次现形**：既然运行时根本没有类型，那断言就只可能是个「口头声明」。它甚至不能算「转换」，因为**没有东西可转**。

⚠️ **两种写法**：`x as number` 和 `<number>x`。**用前者** —— 后者在 `.tsx`（React 文件）里会被当成 JSX 标签，直接语法错误。

⭐ 工程上的规矩：**`as` 只在「你比编译器知道得更多」时用**（比如刚从 `localStorage` 读出来的 JSON）。**任何时候用它来「让报错消失」，都是在给未来的自己埋雷。**

## 1. 类型注解速查表（01-25 全集）

| 场景 | 写法 | C# 对照 |
|---|---|---|
| 变量 | `let n: number = 0` | `int n = 0` |
| 数组 | `let a: number[] = []` | `int[] a` |
| 数组（泛型式） | `let a: Array<number> = []` | `List<int>` |
| 联合 | `let x: string \| number` | ❌ 无 |
| 别名 | `type ID = string \| number` | ❌ 无 |
| 函数（声明） | `function f(a: number): string` | `string F(int a)` |
| 函数（类型） | `let f: (a: number) => string` | `Func<int, string>` |
| 无返回 | `function f(): void` | `void F()` |
| 可选参数 | `function f(a?: number)` | `int? a = null` |
| 对象内联 | `let p: { x: number; y: number }` | ❌ 无 |
| 对象可选属性 | `{ age?: number }` | `int? Age` |
| 接口 | `interface P { x: number }` | `interface IP` |
| 接口继承 | `interface S extends P` | `interface IS : IP` |
| 元组 | `[string, number]` | `(string, int)` |
| 断言 | `x as T` | `(T)x` ⚠️ 零检查 |

## 2. 「跑」和「查」命令对照

**这是你环境和课程差别最大的地方，必须背下来。**

| 目的 | 命令 | 查错 | 读 tsconfig | 产出文件 |
|---|---|---|---|---|
| **跑** | `node x.ts` | ❌ **不查** | ❌ 不读 | ❌ |
| **查** | `tsc --noEmit` | ✅ | ✅ | ❌ |
| 编译看产物 | `tsc x.ts` | ✅ | ✅ | ✅ `x.js` |

⚠️ **`node x.ts` 不查错** —— 它只是把类型当注释撕掉再执行。**跑得通 ≠ 写对了。**

## 3. 判断表：遇到这个情况该用哪个

| 情况 | 用什么 |
|---|---|
| 就是个数字 / 字符串 | 直接 `number` / `string` |
| 可能是 A 也可能是 B | 联合 `A \| B` |
| 同一个复杂类型要用很多次 | `type` 或 `interface` |
| 描述一个对象形状 | `interface` |
| 要写联合 / 元组 / 给基本类型起名 | `type`（interface 做不到） |
| 一组固定长度的数据 | 元组 |
| 类型 TS 猜得到 | **不写**，让它推 |
| 类型 TS 猜不到（比如外面来的） | 写注解，别 `as` |

## 1. 一篇代码覆盖 07-25 全部知识点

```ts
// ═══ 01 原始类型 ═══
let age: number = 20;
let name: string = 'pero';
let isStudent: boolean = true;
let empty: null = null;
let notYet: undefined = undefined;

// ═══ 02 数组 ═══
let scores: number[] = [90, 85, 77];
let tags: Array<string> = ['ts', 'js'];

// ═══ 03 联合 + 别名 ═══
type ID = string | number;
let uid: ID = 1001;
uid = 'u-1001';

// ═══ 04 函数类型 ═══
type Calc = (a: number, b: number) => number;
const add: Calc = (a, b) => a + b;

function greet(who: string, title?: string): string {
  return title ? `${title} ${who}` : who;
}

// ═══ 05 对象 / 接口 / 继承 ═══
interface Person {
  name: string;
  age: number;
  email?: string;         // 可选属性
}

interface Student extends Person {
  grade: string;
}

const s: Student = { name: 'pero', age: 20, grade: '大一' };

// ═══ 06 元组 ═══
let pos: [number, number] = [39.5, 116.3];

// ═══ 07 类型推论 ═══
let inferred = 18;            // number
const literal = 18;           // 18

// ═══ 08 断言 ═══
const raw = '{"name":"pero","age":20}';
const parsed = JSON.parse(raw) as Person;   // 这里 as 是合理的
console.log(parsed.name);

console.log(age, name, isStudent, empty, notYet);
console.log(scores, tags, uid, add(1, 2), greet('pero', '同学'));
console.log(s, pos, inferred, literal);
```

存成 `basics.ts`，两条命令：

```bash
tsc --noEmit          # 无输出 = 通过
node basics.ts        # 看输出
```

## 2. 两个必跑的反直觉实验

### 实验 A：`node` 不查错

```ts
// bad-type.ts
const n: number = 'hello';
console.log('node 输出 →', n);
```

```bash
node bad-type.ts            # → hello        ← 完全不报错
tsc --noEmit bad-type.ts    # → error TS2322 ← 才报
```

### 实验 B：`as` 不做任何检查

```ts
// bad-assert.ts
interface User { name: string }
const u = {} as User;
console.log('u.name →', u.name);   // undefined，不报错
```

```bash
node bad-assert.ts          # → undefined
tsc --noEmit bad-assert.ts  # → 通过（编译器完全认可）
```

⭐ **实验 B 是整篇最该记住的一条**：`as` 让编译器闭嘴了，也让你失去了唯一的保护。

## 动手小练习（不留超纲作业）

1. 定义一个 `interface Book { title: string; price: number; author?: string }`
2. 写 `function format(b: Book): string`，返回 `《书名》- 价格元`
3. 用 `type` 给 `format` 的函数类型起个别名，再用它约束一个变量
4. **故意传一个缺 `price` 的对象**，看 `tsc` 报什么；再**故意用 `as Book` 强转过去**，看 `tsc` 还报不报
5. 第 4 步做完不许删 —— 那是你亲手造的「静默失败」样本

==四：总结==

## 1. 一句话记住 6 段

| 集 | 一句话 |
|---|---|
| 01-06 | **TS = JS + 类型层，没有运行时**；编译后类型一个字不剩 |
| 07-10 | 类型写在名字**后面**；`number` **只有一个**，没有 int/long 之分 |
| 11-13 | 数组 `T[]`；联合 `A \| B` 是 TS 的日常；`type` 只是起名 |
| 14-17 | 函数类型 ≈ `Func`/`Action`；但 **`void` 不强制** |
| 18-22 | 对象靠**形状**匹配，不需要 `implements`（结构化类型，先记个影） |
| 23-25 | 元组像 ValueTuple；**`as` 零检查**，只骗编译器 |

## 2. ⭐⭐ 这一篇要背的

> **类型注解是给编译器的注释，运行时一个字节都不占。**
>
> 所以：`as` 不转换、`void` 不强制、接口不需要 `implements`、`number` 装不下 long。
> **每一条「跟 C# 不一样」，都能追到「因为它必须能跑在浏览器里」。**

**四问**（01-03 那张表）也要能默写：谁定义 / 谁检查 / **谁执行** / 编译后还在吗。

## 3. ⭐ 收敛时刻：这 25 集把 JS 的哪几条线接上了

| 前面哪一条 | 当时的话 | 现在怎么解释 |
|---|---|---|
| JS 基础篇：**动态类型** | 「JS 变量没有类型，类型跟值走」 | TS 把类型搬回源码，**但只搬到编译期**；运行时依旧跟值走 |
| JS 进阶：**「静默失败」暗线** | 「别问会不会报错，要问行为对不对」 | TS 就是这条暗线的护栏 —— **但护栏只在开发期，运行时没有护栏** |
| **JSDoc + `// @ts-check`** | 「≈ 一个不用改后缀名的 TS」 | 同一套类型系统；25 集的注解就是 JSDoc 的正式写法 |
| **`import type`**（今天刚撞的） | 「类型导不进来」 | 因为类型**从来就没被生成过** —— 01 集那句话的实物证据 |
| 你对 JS「不严谨」的长期抵触 | 「维护性差、改一处怕崩」 | 07-25 给的答案：**写完先 `tsc --noEmit`** |

⭐ **一句收口**：

> 你过去 200 集所有「JS 太松」的不适感，根都在「没有编译期」。
> **这 25 集补的是这一块 —— 而且只补这一块。**

## 4. 静默失败清单（TS 版，本篇 6 条）

> 老规矩：**这不是 TS 的 bug，是它的边界。**

| 你写的 | 实际发生 | 谁会拦 |
|---|---|---|
| 只跑 `node x.ts` 不跑 `tsc` | 类型全错也照样有输出 | ❌ 没人 —— **最容易犯** |
| `{} as User` 然后 `u.name` | 运行时 `undefined` | ❌ 没人，`tsc` 认为合法 |
| `const n: number = 'x'` | node 输出字符串 | ✅ `tsc` 会拦 |
| 19 位 `long` ID 塞进 `number` | 末几位被改掉 | ❌ 没人 —— **精度丢失** |
| 多传字段给接口（先赋变量） | 检查被绕过 | ⚠️ 只有直接写字面量才查 |
| 后端返回 `null`，但你标了非空 | 运行时 `Cannot read properties of null` | ❌ 没人 —— **TS 不知道数据来源** |

⭐ **第 6 条是这一篇最该带走的工程结论**：

> **TS 的类型是「你对数据的声明」，不是「对数据的保证」。**
> 接口、`localStorage`、用户输入 —— 这三处 TS 一律给不了保证，**校验必须自己写。**

## 5. C# 类比可用度（本篇汇总）

| TS 的做法 | C# 对应 | 档 | 说明 |
|---|---|---|---|
| 类型注解 `n: number` | `int n` | ⭐⭐⭐⭐ | 只差位置：类型在后 |
| `number` | `int`/`long`/`double`/`decimal` | ⭐⭐ | ⚠️ **只有一个**，全是 double |
| `null` / `undefined` | `null` | ⭐⭐ | C# 只有一个空 |
| `T[]` | `T[]` | ⭐⭐⭐⭐⭐ | 完全一致 |
| `Array<T>` | `List<T>` | ⭐⭐ | 长得像，语义是数组 |
| 联合 `A \| B` | 无 | ❌ | C# 表达不了 |
| `type X = ...` | 无 | ❌ | `using` 别名 ≠ 类型别名 |
| 函数类型 `(a) => b` | `Func` / `Action` | ⭐⭐⭐⭐⭐ | 直接迁移 |
| `void` 不强制 | — | ❌ | 🔴 C# 直觉在这里是**反的** |
| `x?: T` | `T? x = null` | ⭐⭐⭐ | 位置限制一样 |
| `interface` 不用 implements | — | ⭐ | 🔴 只有「形状」，没有「身份」 |
| `interface extends` | `interface : ` | ⭐⭐⭐⭐⭐ | 一致 |
| 元组 `[A, B]` | `(A, B)` | ⭐⭐⭐⭐ | 一致 |
| 类型推论 | `var` | ⭐⭐⭐ | ⚠️ 但 `const` 推字面量，`var` 没有 |
| `as` | `(T)x` | ⭐ | 🔴 **零检查**，最危险的一条 |

⭐ **本篇最大的可用度陷阱**：`as` 和 `(T)x` 长得像、用起来手感像，**但一个是运行时强转，一个是关掉编译器的嘴**。这一条必须建立条件反射。

**新解锁**

- ✅ 类型推论、类型断言（**会用，但要知道它是零检查**）
