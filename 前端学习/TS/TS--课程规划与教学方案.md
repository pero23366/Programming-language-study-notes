## 一、这份规划的三条判断依据

1. **C# 是你的加速器，也是你最大的陷阱源。** TS 和 C# 是同一个作者（Anders Hejlsberg）设计的，语法几乎照抄。但底层机制不同 —— 最大的那一处是：**TS 的类型在编译后全部消失，C# 的类型活在元数据里**。这一条会衍生出后面至少 15 个坑，全部是「C# 直觉反向」类型。
2. **JS 200 集是你的底盘，不是你的负担。** 你被 JS「静默失败」折磨过的每一处，TS 正好在补 —— 这门课对你不是新语言，是**给你已经会写的东西装一套编译期护栏**。
3. **课程的难度分布极不均匀。** 第 1-2 章（01-25 集）慢而碎，第 4 章（class）对你几乎是复习，第 5 章（泛型 + 工具类型 + 映射类型）**是全课程唯一的真正难点**，第 7 章（React）对你完全是另一门课。

### 2.2 为什么「快的部分」和「慢的部分」不能平均

用你机器上的实测说明（探针文件在 `_自测/`，可自己跑）：

```
tsc --noEmit 01-Csharp直觉陷阱.ts   → 0 error（全部合法）
node         01-Csharp直觉陷阱.ts   → 4 处行为与 C# 相反
```

| 实测输出 | C# 里的对应行为 |
|---|---|
| `[1] 多一个字段照样能传 → 1` | C# 里形状不同就是不同类，编译不过 |
| `[2] 声明 void 却返回了 123 → 123` | `Func<int>` 不能赋给 `Action` |
| `[3a] as 之后访问属性 → 运行时炸了` | `(T)x` 当场抛 `InvalidCastException`，不会拖到后面 |
| `[4] 能拿到 T 的类型吗 → number` | `typeof(T)` 随时能拿到 |
| `[6] 类原型上有 Speaker 的痕迹吗 → []` | `is ISpeaker` 能用 |

```
tsc --noEmit 02-private只是画线.ts  → error TS2341（说不许）
node         02-private只是画线.ts  → [A] 越过 private 读到了 → 42
```

**这就是「快不得」的真正原因**：这些点不难，恰恰相反 —— **它们太像 C# 了，所以你不会停下来看。**
一个 JS 零基础的人遇到 `private` 会问「这是什么」；你会直接跳过，因为你认识这个词。

> 认识 ≠ 正确。**速度的风险不在生疏处，在熟悉处。**

反过来说：M2 / M4 / M9 这 24 集，你确实可以在 1-2 次里推完 —— 那里没有「长得像但不一样」的陷阱，全是真的白送。**该快的地方就该快到不合理。**

### 第 1 章 · 认知地基（01-06 集）

#### R1 · 3 集 · 01-03 —— TS 是什么：一句话定生死

| 项 | 内容 |
|---|---|
| 知识点 | TS 是 JS 的超集 / 为什么要类型 / TS 相比 JS 的优势 |
| C# 对标 | 概念全对标，**机制完全不同** |
| 标签 | 🔴🔴 **类型擦除**（全课程地基）· 🔵「编译」 |

**必讲（这一轮讲不透，后面全歪）**

> C# 编译后，类型信息完整地留在 assembly 的 metadata 里 —— 你能反射、能 `typeof(T)`、能按类型分派。
> **TS 编译后，类型一行都不剩。** 产物是纯 JS，`let a: number = 1` 变成 `let a = 1`。
> 所以 TS 的类型只服务于「写代码时的那个人」，不服务于「跑起来的机器」。

这一条直接推出后面所有的高危坑：

| 推论 | 会砸在哪一轮 |
|---|---|
| 不能 `new T()`、不能 `default(T)` | R11 泛型 |
| `as` 不做运行时检查 | R6 类型断言 |
| `private` 运行时能访问 | R9 修饰符 |
| 不能按类型重载（只有一个实现） | R4 函数类型 |
| 不能靠 `instanceof` 判断接口 | R5 / R10 结构化类型 |

**⏭ 跳过 04-06 集**（安装 TS 工具包 / 编译并运行 / 简化运行）
理由：你已经装好 tsc 7.0.2 + Node 24 并实测通过。**但用一张对账表替代**（见 §0.3），并当场验证一件事：故意写错类型 → `node x.ts` 照样跑通、`tsc --noEmit` 才报错。这个对照实验比看三集视频有效。

**附带补丁（必须做，约 15 分钟）**：`import` / `export` 最小必要知识
你的 JS 200 集完全没讲模块化，但 TS 从第 13 轮起离不开它。补到「能看懂 `export type` / `import type` 是什么意思」就够，不用深入打包。

### 第 2 章 · 常用类型（07-25 集）

#### R2 · 4 集 · 07-10 —— 类型注解 + 原始类型

| 项 | 内容 |
|---|---|
| 知识点 | 常用类型概述 / 类型注解语法 / 类型分类 / 原始类型 |
| C# 对标 | `let a: number = 1` ↔ `int a = 1`（**类型写在名字后面**） |
| 标签 | ⚪ 白送 · 🔴 `number` 只有一个 · 🔴 两个「空」 |

**砸这两个坑**

1. **TS 的 `number` 涵盖 C# 的 `int` / `long` / `float` / `double` / `decimal`**，一律是 IEEE 754 双精度。没有 `int` 对应物 —— 这也是为什么你后端接口返回的 `long` id 到前端会精度丢失（跟你写 .NET 直接相关，值得点一句）。
2. **`null` 和 `undefined` 是两个不同的空**。C# 只有一个 `null`。`undefined` 是「没赋值」，`null` 是「赋了空」。

#### R3 · 3 集 · 11-13 —— 数组 / 联合 / 类型别名

| 项 | 内容 |
|---|---|
| 知识点 | `number[]` 与 `Array<number>` · 联合类型 `A \| B` · `type` 类型别名 |
| C# 对标 | 数组 ↔ `int[]`；联合 ↔ **无对应**（勉强 `object` + 运行时判）；别名 ↔ `using X = ...` |
| 标签 | 🆕 联合类型 · 🟡 `number[]` vs `Array<number>` |

**必讲**：联合类型是 TS 里出现频率最高的东西，因为 JS 变量没有类型，函数「可能返回字符串也可能返回 null」是常态而不是例外。C# 里你要靠泛型 + `Nullable<T>` 或者基类去表达，TS 一个 `|` 就完了。
**但要立刻埋一句**：拿了联合类型就必须**收窄**才能用 —— 这引出 `typeof` 守卫（R7）和类型断言（R6）。别在这里讲透。

---

#### R4 · 4 集 · 14-17 —— 函数类型 / void / 可选参数

| 项 | 内容 |
|---|---|
| 知识点 | 函数类型两种写法 · `void` · 可选参数 `?` |
| C# 对标 | `(a: number) => void` ↔ `Action<int>` / `Func<int, string>` |
| 标签 | 🔴 `void` 不强制 · 🟡 可选参数 vs 默认值 vs `\| undefined` |

**砸两个坑**

1. **TS 的 `void` 返回值不做强制**：`() => 1` 可以赋给 `() => void`。C# 里 `Func<int>` 绝不能赋给 `Action`。这条来自「TS 要求函数类型可赋值性放宽」，跟 JS 的 `forEach(fn)` 忽略返回值有关。
2. **三种「可以不传」不是一回事**：`a?: number` / `a: number = 1` / `a: number | undefined`。前者可缺省，中者有默认值（参数位置会被迫后移），后者**必须显式传 undefined**。

#### R5 · 5 集 · 18-22 —— 对象类型 / 接口 / 接口继承

| 项 | 内容 |
|---|---|
| 知识点 | 对象类型 `{ name: string }` · 可选属性 · `interface` · interface vs type · 接口继承 |
| C# 对标 | `interface` ↔ `interface`（**但不需要 `implements` 就兼容**） |
| 标签 | 🔴 **结构化类型首次登场** · 🟡 interface vs type |

**必讲（但只埋点，不讲透）**

> C# 是**名义类型**：`A` 能赋给 `B`，前提是 `A : B` 写在代码里。
> TS 是**结构类型**：只要「长的形状够」，就能赋值 —— 你根本不用写 `implements`。

这一句在这里只要让用户「听到」，不展开。**R10（43-48 集）才是它的主场**，那里有整整 6 集在讲。

**🟡 interface vs type 边界表**（当场给，别拖）

| 能力 | `interface` | `type` |
|---|---|---|
| 声明合并（同名自动合并） | ✅ | ❌ |
| 联合 / 交叉 / 元组 | ❌ | ✅ |
| `extends` 多个 | ✅ | 用 `&` |
| 给基本类型起别名 | ❌ | ✅ |
| 类 implements | ✅ | 对象形状可以，联合不行 |

#### R6 · 3 集 · 23-25 —— 元组 / 类型推论 / 类型断言

| 项 | 内容 |
|---|---|
| 知识点 | 元组 `[string, number]` · 类型推论 · 类型断言 `as` / `<T>` |
| C# 对标 | 元组 ↔ `(string, int)` ValueTuple；推论 ↔ `var`；断言 ↔ `(T)x` **但零检查** |
| 标签 | 🔴🔴 `as` 不是强转 · 🟡 `let` vs `const` 的推论差异 |

**两个必砸**

1. **`as` 只骗编译器，不做任何转换、不做任何检查。** C# 的 `(T)x` 会在运行时 `castclass`，类型不对抛 `InvalidCastException`。TS 的 `x as User` 编译后就没了 —— 你后面写 `x.name` 拿到的是 `undefined`，**不会报错**。这是你熟悉的「静默失败」暗线在 TS 里的再生。
2. **`let a = 1` 推成 `number`，`const a = 1` 推成 `1`。** C# 的 `var` 没有这个区别。这个差异直接决定 R7 的字面量类型能不能用。

### 第 3 章 · 字面量与枚举（26-32 集）

#### R7 · 7 集 · 26-32 —— 字面量 / 枚举 / any / typeof

| 项 | 内容 |
|---|---|
| 知识点 | 字面量类型 · 枚举类型 · 数字枚举与成员值 · 字符串枚举 · 枚举原理 · `any` · `typeof`（类型位置） |
| C# 对标 | 字面量 ↔ 无；枚举 ↔ `enum`（**完全不同**）；`any` ↔ `dynamic`；`typeof` ↔ `typeof(T)`（**撞名**） |
| 标签 | 🔴 enum 会生成运行时代码 · 🟡 字面量 vs 枚举 · 🔵 `typeof` |

**三个必砸**

1. **`enum` 是全课程唯一「会生成运行时代码」的类型**。编译后它是一个真实对象，还带**反向映射**：`E.A === 0` 且 `E[0] === "A"`。C# 的 `enum` 是 int 常量，没有对象、没有反向映射。
   ⚠️ 顺带一个你环境里已经踩过的坑：`node x.ts` 直接跑含 `enum` 的文件会报 `ERR_UNSUPPORTED_TYPESCRIPT_SYNTAX` —— 因为 enum 属于「要生成代码」的语法，Node 的类型擦除做不到。**这正好是「类型擦除有边界」的最好证据**。
2. **`typeof` 在类型位置和值位置是两个东西**。`typeof x` 当值用 = 你熟的 JS 运算符；`type T = typeof x` 是「取变量 x 的类型」。C# 的 `typeof(T)` 返回 `Type` 对象 —— 名字撞了，语义不撞。
3. **🎁 必补：`unknown`（课程没讲）**。`any` 是关掉检查（= `dynamic`），`unknown` 是安全版 —— 拿到手必须先收窄才能用。C# 里对应的是 `object` + 模式匹配。课程只讲 `any`，这一课不补，你会把 `any` 当万能药。

**🟡 字面量 vs 枚举怎么选**
| 场景 | 用哪个 |
|---|---|
| 一组固定字符串（`'left' \| 'right'`） | **联合字面量**，不要 enum |
| 需要反向查名字 / 要当对象遍历 | enum |
| 数值标志位 | enum（但你 C# 那边用 `[Flags]`，TS 没有对应） |

### 第 4 章 · class 与类型兼容性（33-48 集）

#### R8 · 6 集 · 33-38 —— class 全家桶 ⭐ 收敛时刻

| 项 | 内容 |
|---|---|
| 知识点 | class 基本 · 构造函数 · 实例方法 · `extends` 继承 · `implements` |
| C# 对标 | **完全对标** —— 这是全课程你最快的一轮 |
| 标签 | ⚪ 大面积白送 · ⭐ **收敛** · 🔴 `implements` 不生成代码 |

**⭐ 这一轮必须点名一次「收敛」**

你在 JS 进阶篇（178 / 182-183 / 186 集）学过：
- 每个实例不一样的放 `this`，一样的放 `prototype`
- 继承四行模板、`子.prototype === 父.prototype` 必须是 `false`

**`class` 就是把那一整套包起来的语法糖。** 构造函数体 = 原来写在 `function User(){}` 里的赋值；实例方法 = 自动搬到 `prototype`；`extends` = 自动接好原型链。

> 这不是新课，这是你 JS 进阶那笔账在这里结清。写 `class` 时脑子里该浮现的是 `__proto__` 那条链。

**🔴 一个 C# 没有的坑**：`implements` **只做编译期检查，不生成任何代码**。运行时没有任何东西记录「这个类实现了谁」，所以不能 `if (obj instanceof MyInterface)`。C# 里 `is IMyInterface` 是能用的。

#### R9 · 4 集 · 39-42 —— 可见性修饰符 + readonly 🔴🔴 全课程最高危

| 项 | 内容 |
|---|---|
| 知识点 | `public` / `protected` / `private` / `readonly` |
| C# 对标 | 语法一样，**执行者完全不同** |
| 标签 | 🔴🔴 最高危 · 🟡 `private` vs `#field` · 🟡 `readonly` vs `Readonly<T>` |

**这一轮是整门课最容易「以为自己会了」的地方**

> C# 的 `private` 是 **CLR 在执行**：反射能绕，但正常代码绝对越不过去。
> TS 的 `private` 是 **编译器在画红线**：编译产物里它就是一个普通属性，`obj.privateField` 在 JS 里照样读得到、写得进。

| 想要 | 写法 |
|---|---|
| 只是让编译器警告同事 | `private` |
| **真正的运行时私有** | `#field`（ECMAScript 私有字段，编译后也真的拿不到） |

**`readonly` 的三个层级**（🟡 极易混）

| 写法 | 锁住什么 | C# 对应 |
|---|---|---|
| `readonly name: string` | 这个属性不能再赋值（声明处 + constructor 内除外） | `readonly` 字段 |
| `readonly list: string[]` | **只锁引用**，`list.push()` 照样可以 | `readonly List<string>`（一模一样） |
| `readonly list: readonly string[]` | 锁到元素，`push` 报错 | `ReadOnlyCollection<string>` |
| `Readonly<T>` | 把 T 的所有属性变只读，**只有一层** | 无（要手写） |

#### R10 · 6 集 · 43-48 —— 类型兼容性 🔴 全课程最值钱

| 项 | 内容 |
|---|---|
| 知识点 | 类型兼容性说明 · 对象之间 · 接口之间 · 函数参数（两集）· 返回值 |
| C# 对标 | **完全反向** —— C# 名义类型，TS 结构类型 |
| 标签 | 🔴🔴🔴 本课最高价值 · 🟡 参数双变 |

**这是 6 集，也是全课程对你最有价值的 6 集。** 前面 R5 埋的那颗雷，在这里引爆。

| 场景 | C# | TS |
|---|---|---|
| `class A` 没继承 `B`，能赋给 `B` 吗 | ❌ 编译不过 | ✅ **只要形状够就行** |
| 多字段的对象 → 少字段的变量 | ❌ | ✅（宽赋窄，允许） |
| 少字段的对象 → 多字段的变量 | ❌ | ❌（缺字段） |
| 接口之间 | 必须 `: IOther` | 形状够就兼容 |

**函数参数是双变的**（🟡 这条最容易和 C# 混淆）
- TS 默认：方法参数**双变**（宽窄都能过），这是为了兼容 JS 数组方法的历史包袱。
- 开 `strictFunctionTypes` 后：函数类型位置变**逆变**（只能窄赋宽）。
- C# 的委托协变/逆变是用 `out` / `in` **显式声明**的，而且只有引用类型泛型才成立。

**收口一句话**：
> C# 问「你是不是我的子类」，TS 只问「你长得像不像」。前者是身份，后者是形状。

### 第 5 章 · 泛型与类型编程（49-68 集）🔥 全课程唯一真难点

#### R11 · 7 集 · 49-55 —— 交叉类型 + 泛型基础

| 项 | 内容 |
|---|---|
| 知识点 | 交叉类型 `A & B` · 交叉 vs 接口对比 · 泛型基本 · 简化泛型调用 · 泛型约束 · `extends` 约束 · 多个泛型变量 |
| C# 对标 | 泛型 ↔ 泛型（**90% 一样**）；约束 ↔ `where T : ...`（TS 用 `extends`）；交叉 ↔ **无** |
| 标签 | ⚪ 大面积白送 · 🔴 **泛型擦除** · 🆕 交叉类型 |

**你在这里会很舒服，但有一个坑能让 C# 人当场翻车**

> C# 的泛型是**具化的**：`List<int>` 和 `List<string>` 是两个真实的、不同的类型，各有自己的方法表和静态字段。
> **TS 的泛型是擦除的**：编译后只有一个函数，类型参数完全消失。

| C# 能写 | TS 不能写 | 替代 |
|---|---|---|
| `new T()` | ❌ | 传工厂函数 `(c: new () => T)` |
| `default(T)` | ❌ | 用 `T \| undefined` |
| `typeof(T)` | ❌ | 传一个值进来 |
| 按 `T` 做运行时分支 | ❌ | 传判别字段 |
| 静态字段每 `T` 一份 | ❌ | 无 |

**约束语法的迁移**：`where T : IComparable` ↔ `T extends IComparable`。注意 `extends` 这个词在 TS 里被复用了三次（类继承 / 泛型约束 / 条件类型），这是 🟡 易混点。

**🆕 交叉类型**：`A & B` 是「同时满足 A 和 B」，不是「继承」。用 `interface C extends A, B` 也能达到类似效果，但两者在**冲突属性**上表现不同（交叉会合并成 `never`，接口继承会直接报错）。

#### R12 · 7 集 · 56-62 —— 泛型接口/类 + 工具类型 🌟

| 项 | 内容 |
|---|---|
| 知识点 | 泛型接口 · 数组是泛型接口 · 泛型类 · `Partial` · `Readonly` · `Pick` · `Record` |
| C# 对标 | 泛型接口/类 ↔ `IEnumerable<T>` / `List<T>`；**工具类型 ↔ 无对应** |
| 标签 | ⚪ 泛型部分 · 🌟 工具类型 = TS 杀手锏 |

**这一轮的「工具类型」部分是 TS 相对 C# 的压倒性优势，必须重点讲**

| TS | 一句话 | C# 你得怎么做 |
|---|---|---|
| `Partial<User>` | 所有属性变可选 | 手写一个 `UpdateUserDto`，字段全 `?` |
| `Required<User>` | 全变必填 | 再手写一个 |
| `Readonly<User>` | 全变只读 | 手写 `readonly` 一堆 |
| `Pick<User, 'id' \| 'name'>` | 只取几个 | 手写 |
| `Omit<User, 'password'>` | 排除几个（课程可能略提） | 手写 |
| `Record<string, number>` | 键值对类型 | `Dictionary<string, int>` ✅ 这个能对上 |

> **在你 .NET 那套里，一个实体的 Create / Update / List / Detail DTO 要写四遍。TS 里一行 `Partial<T>` 就完了。**
> 这不是语法糖，这是「类型可以在编译期被计算」—— C# 做不到，因为 C# 的类型是运行时对象，不能拿来做编译期运算。

#### R13 · 6 集 · 63-68 —— 索引签名 / 映射类型 / keyof / 索引查询 🔴 抽象度最高

| 项 | 内容 |
|---|---|
| 知识点 | 索引签名类型 · 映射类型 · 映射类型 `keyof` · 分析 `Partial` 的实现 · 索引查询类型（单个 / 多个） |
| C# 对标 | **全无对应**（要反射 + 表达式树 + 源码生成器） |
| 标签 | 🔴 全课程最难 · 🟡 `keyof` vs `T[K]` vs `typeof` |

**这是全课程唯一「C# 完全帮不上忙」的一段。** 讲法建议：不要试图类比，直接讲「TS 的类型是一门可以计算的语言」。

| 语法 | 做什么 | 记忆抓手 |
|---|---|---|
| `[key: string]: number` | 任意字符串键都返回 number | 「这是个字典」 |
| `keyof T` | 取 T 所有键，变成一个**联合** | 「键的联合」 |
| `T[K]` | 按键取值的类型 | 「类型层面的下标访问」 |
| `{ [K in keyof T]: ... }` | 遍历键，逐个变换 | 「类型层面的 for 循环」 |

**这就是 `Partial` 的实现**（66 集专门拆它）：
```ts
type Partial<T> = { [K in keyof T]?: T[K] };
```
看懂这一行，你才算真正进入 TS。这一行也是整门课的分水岭。
