## 2. 字面量类型（26）🔥🔥

### 2.1 什么是字面量类型

**「某个具体的值」本身就可以当类型用。**

```ts
let str1: 'hello' = 'hello'
let age: 18 = 18
let flag: true = true
```

`'hello'` 既是值又是类型 —— TS 完全靠**位置**区分：写在冒号后面就是类型，写在等号后面就是值。

### 2.2 ⚠️ `let` 和 `const` 推出完全不同的类型

这是本集最反直觉的一条：

```ts
let a = 'hello'      // 类型：string        ← let 会「拓宽」(widening)
const b = 'hello'    // 类型：'hello'       ← const 保留字面量
```

**同一个初始化表达式，`let` 和 `const` 推出两个不同的类型。**

为什么？因为 `const` 变量**再也不可能被改成别的值**，编译器敢把类型收窄到具体值；`let` 明天可能变成 `'world'`，只能给 `string`。

🔵 **C# 对照：`var` 从来不拓宽。** `var a = "hello"` 永远是 `string`，跟 `var` / `const`（C# 的 `const string`）无关。这条差异纯属 TS 独有。

🛠️ **实用技巧：借报错看类型。** 不确定一个变量被推成什么类型时：

```ts
const b = 'hello'
const _check: 1 = b
// ❌ 不能将类型 "hello" 分配给类型 "1"
//       ↑ 报错信息直接告诉你 b 的真实类型
```

这个技巧整门课都好用，比鼠标悬停可靠（尤其是推断复杂的场景）。

### 2.3 用法：配合联合类型，做「枚举的轻量替代」

```ts
function changeDirection(direction: 'up' | 'down' | 'left' | 'right') {
  console.log(direction)
}

changeDirection('up')        // ✅
changeDirection('left')      // ✅
changeDirection('diagonal')  // ❌ 类型 "diagonal" 的参数不能赋给类型 "up" | "down" | "left" | "right"
```

对比 `direction: string`：`'diagonal'` 也合法，但业务上毫无意义。**字面量联合 = 把「合法输入」写在签名里。**

**优点**：精确、可选值一目了然、**零运行时开销**（编译后全删）。

### 2.4 C# 对照

C# 压根没有字面量类型。最接近的是 `enum`，但 `enum` 是**另一个类型**：`Direction.Up` 和 `0` 不是一回事（虽然可以强转）。

| | C# | TS |
|---|---|---|
| 表达「只能取这几个值」 | `enum Direction { Up, Down }` | `'up' \| 'down'` |
| 运行时存在吗 | ✅ 是值类型 | ❌ 编译后消失 |
| 能不能是任意字符串 | ❌ 成员名有标识符限制 | ✅ `'已下单' \| '已发货'` |
| 要不要额外定义类型 | ✅ 要 | ❌ 就地写 |

⚠️ **一处 C# 直觉会翻车**：C# 里想让枚举带中文/空格，得靠 `[Description]` + 反射查表。TS 里直接 `'已下单' | '已发货'`，**中文、空格、emoji 随便写**，编译器照单全收。

## 3. 枚举（27-30）🔥🔥 —— 全课程唯一会生成运行时代码的类型

### 3.1 三集的分工

| 集 | 讲什么 |
|---|---|
| 27 | 枚举基本写法、默认值从 0 自增 |
| 28 | 成员值可自定义；后面的成员继续自增 |
| 29 | 字符串枚举：每个成员必须有值，没有自增 |
| 30 | ⭐ 枚举的特点与**原理**（编译产物、反向映射） |

### 3.2 写法

```ts
enum Direction { Up, Down, Left, Right }   // 0, 1, 2, 3

function changeDirection(direction: Direction) {
  console.log(direction)
}
changeDirection(Direction.Up)   // ✅
```

**定义了枚举，就同时定义了「类型」和「值」。** 这一点和 §2 的字面量联合不同 —— 联合只有类型，没有值。

数字枚举可以自定值，**后面的成员继续自增**：

```ts
enum Direction { Up = 10, Down, Left, Right }   // 10, 11, 12, 13
```

字符串枚举：**每个成员都必须给值，没有自增**：

```ts
enum Direction { Up = 'UP', Down = 'DOWN', Left = 'LEFT', Right = 'RIGHT' }
```

### 3.3 ⭐⭐ 为什么说它是「唯一会生成运行时代码」的类型

其它所有类型标注（注解、联合、接口、别名、泛型），`tsc` 一编译就**删干净**。`enum` 不会 —— 它变成一个**真实的 JS 对象**。

所以你会撞上这个错：

```
node x.ts
→ SyntaxError [ERR_UNSUPPORTED_TYPESCRIPT_SYNTAX]: TypeScript enum is not supported in strip-only mode
```

**这不是环境坏了，这是「类型擦除有边界」的直接证据**：Node 的 type stripping **只会删、不会生成**。而 enum 需要「生成」一个对象出来。解法二选一：

```bash
node --experimental-transform-types x.ts   # 让它允许生成代码
tsc x.ts && node x.js                       # 或者老老实实编译
```

> **一句话记住：类型是注释，enum 是代码。** 这是整个 01-48 集里唯一违反「类型不占运行时」的例子。

编译产物见 §二·2，值得逐行看一遍。

### 3.4 数字枚举的反向映射

```ts
Direction.Up     // 0
Direction[0]     // 'Up'    ← 反着查也行（只有数字枚举有）
```

字符串枚举没有这个能力：`Direction['UP']` 是 `undefined`。

🛠️ **实测发现（TS 7.0.2，2026-10-19 验证）**：这一行现在**连编译期都过不去**：

```
error TS2551: Property 'HIGH' does not exist on type 'typeof Level'. Did you mean 'High'?
```

也就是说 TS 直接认为字符串枚举对象上**不存在以值命名的键**，比「运行时返回 undefined」更早拦住。想跑通得强制转一下：

```ts
console.log((Level as any)['HIGH'])   // undefined
```

这比课程讲的更彻底 —— 字符串枚举连「反查」这个动作本身都被类型系统否掉了。

| | C# | TS |
|---|---|---|
| 名字 → 值 | `Direction.Up`（强转 `(int)`） | `Direction.Up` |
| 值 → 名字 | `Enum.GetName(typeof(Direction), 0)` | `Direction[0]`，**对象下标** |
| 底层 | 一定是整数 | 数字或字符串都行 |

### 3.5 🔴 `enum` vs 字面量联合：工程上到底用哪个

课程只讲 `enum`，但真实项目里两条路都在用。这不是学术问题：

| | `enum` | 字面量联合 `'up' \| 'down'` |
|---|---|---|
| 运行时产物 | ✅ 有对象 | ❌ 完全消失 |
| 打包体积 | 有（小） | 零 |
| `node x.ts` 直接跑 | ❌ 报错 | ✅ 可以 |
| 反向映射 | ✅ 数字枚举有 | ❌ |
| 运行时校验后端数据 | ✅ `value in Direction` | ❌ 得自己写数组 |
| 遍历所有成员 | ✅ `Object.values` | ❌ 得另外维护数组 |
| 编译期提示 | 值显示为 `Direction.Up` | 值显示为 `'up'` |

**给你的选型判断**：

- 需要**运行时**用（拿后端返回的字符串做校验、遍历、反查名字）→ `enum`
- 只在类型层面用（函数参数、props、状态字段）→ 字面量联合 + `as const`，**更轻**
- Vue 3 / React 生态大量用后者；后端接口对齐、位标志组合用前者

> ⚠️ 课程外的补充：`const enum` 是「会内联、编译后被删光」的枚举，两边好处都占 —— 但它和 `isolatedModules`（Vite / esbuild 默认开）冲突，**新手别碰**。

## 4. `any`（31）🔥

### 4.1 它到底做了什么

```ts
let obj: any = { x: 0 }

obj.bar = 100        // ✅ 不报错
obj()                // ✅ 不报错
const n: number = obj // ✅ 不报错
```

四行全过。注意：**`any` 不是「类型是任意」，而是「这个值上的一切检查全部关闭」** —— 包括你往里塞什么、往外拿什么、能不能当函数调。

### 4.2 隐式 `any` 从哪来

```ts
let a              // 隐式 any
function f(x) {}   // 参数隐式 any → TS7006: 参数"x"隐式具有"any"类型
```

⚠️ 严格模式（`noImplicitAny`）下**函数参数**隐式 any 会直接报错 —— 这是好事，它会逼你把类型写全。变量不赋值不标注也会是 any，但只在 `strict` 下才提示。

### 4.3 🔵 `any` ↔ C# `dynamic`：长得像，本质相反

| | C# `dynamic` | TS `any` |
|---|---|---|
| 检查时机 | **运行时**（DLR binder） | **永不检查**（编译期直接放行） |
| 出错时 | 运行时抛 `RuntimeBinderException` | 运行时崩在别处（`obj is not a function`） |
| 有没有兜底 | ✅ 有，虽然晚 | ❌ 一点没有 |
| 性能开销 | 有（动态绑定） | **零**（擦完就是普通 JS） |
| VS 里的提示 | 无（但运行时能查） | 有（any 上什么提示都没有） |

> **`dynamic` 是「延迟检查」；`any` 是「放弃检查」。** 一个是晚点判，一个是不判。

### 4.4 🎁 必补：`unknown`（课程没讲，但你现在必须知道）

`unknown` 是 `any` 的**安全版**：能装任何值，但**不让你直接使用**。

```ts
let a: any = 1
a.toFixed()          // ✅ 不报错 —— 但 a 是字符串时这里就崩了

let u: unknown = 1
u.toFixed()          // ❌ 类型"unknown"上不存在属性"toFixed"

if (typeof u === 'number') {
  u.toFixed()        // ✅ 收窄成 number 之后才让用
}
```

⭐ **工程铁律（从今天起执行）**：

> **外部来的数据一律用 `unknown`** —— 后端响应、`JSON.parse`、`localStorage`、`postMessage`、`catch (e)`。
> 宁可多写一行 `typeof` / 类型守卫，**也别让一个 `any` 溜进业务代码**。
> `any` 只在你**明确要关掉检查**的逃生口用，并且当场写注释说明为什么。

（回扣基础篇第 6 条静默失败：TS 的类型是「你对数据的声明」，不是「对数据的保证」。`unknown` 就是这个事实的诚实表达。）

## 5. `typeof`（32）🔥 —— 一个词，三个身份

### 5.1 类型位置的 `typeof`

```ts
let p = { x: 1, y: 2 }

function formatPoint(point: typeof p) {
  console.log(point.x, point.y)
}
```

`typeof p` 在**类型位置**，干的事是：**根据一个「值」反推出它的「类型」**（课程叫「查询类型」）。

得到的类型是 `{ x: number; y: number }` —— 注意 `1` 被拓宽成了 `number`（因为 `p` 是 `let`，回扣 §2.2）。

### 5.2 🔵 三重撞名（这是本集最容易晕的地方）

| | 写在什么位置 | 输入 | 返回 |
|---|---|---|---|
| JS `typeof x` | 值位置 | 一个值 | **字符串** `'number'` / `'object'` |
| C# `typeof(T)` | 值位置 | **类型名** | `System.Type` 反射对象 |
| TS `typeof x` | **类型位置** | **变量名** | **一个类型**（编译期，零产物） |

**三者的输入、输出、时机全都不一样。**

最好记的一句：

> **C# 的 `typeof` 是「拿类型换运行时对象」；TS 的 `typeof` 是「拿值换编译期类型」。方向正好相反。**

⚠️ 限制：`typeof` 只能查**变量 / 属性**，不能查函数调用：

```ts
typeof p.x       // ✅
typeof getP()    // ❌ 不能对函数调用使用 typeof
```

### 5.3 实际用途（这才是它值钱的地方）

**① 少抄一遍类型**

```ts
const defaultUser = { name: '', age: 0 }
type User = typeof defaultUser    // 类型跟着值走，改值不用改类型
```

**② 配合 `as const` 拿字面量类型** —— 这是 TS 里「常量表」的标准写法：

```ts
const config = { url: '/api', method: 'GET' } as const
type Config = typeof config
// { readonly url: "/api"; readonly method: "GET" }
```

`as const` 干的事和 §2.2 里 `const b = 'hello'` 是**同一个机制**：告诉编译器「这个值不会变，别拓宽」。区别只是它作用于整个对象（递归、且全部变 `readonly`）。

## 6. `class`（34-38）—— 语法白送，语义有雷

### 6.1 基本使用（34）

```ts
class Person {
  age: number = 18
  gender: string = '男'
}

const p = new Person()
p.age = 19
```

⚠️ **属性必须先声明**（带类型）。这跟 JS 的 class 不一样（JS 里 constructor 里 `this.x =` 就算定义了），但**和 C# 完全一样** —— 对你零成本。

⚠️ 严格模式下未初始化会立刻报错：

```ts
class A {
  name: string   // ❌ 属性"name"没有初始值，且未在构造函数中明确赋值
}
```

三条解法，按优先级：给初始值 → 构造函数里赋值 → `name!: string`（明确断言，等于对编译器说「我保证会赋值」）。

### 6.2 构造函数 & 参数属性（35）

```ts
class Person {
  age: number
  gender: string
  constructor(age: number, gender: string) {
    this.age = age
    this.gender = gender
  }
}
```

构造函数**不写返回值类型**（C# 一样）。

TS 还给了个糖 —— **参数属性**，一行顶三行：

```ts
class Person {
  constructor(public name: string, readonly age: number) {}
}

const p = new Person('jack', 18)
p.name    // ✅
```

`public name: string` 同时完成「声明属性 + 声明参数 + 赋值」。

🔵 C# 对照：这几乎是 **C# 12 的 primary constructor**，但 C# 的 primary constructor 参数**不自动变属性**（要用还得写 `public string Name { get; } = name;`）。TS 这个更直接。

### 6.3 继承 `extends`（37）· 实现 `implements`（38）

```ts
class Animal { move() { console.log('moving') } }
class Dog extends Animal { bark() {} }

const d = new Dog()
d.move()   // ✅ 继承来的
d.bark()
```

```ts
interface Singable { sing(): void }

class Person implements Singable {
  sing() { console.log('lalala') }
}
```

一个类可以实现多个接口：`implements A, B`。

🔴 **三条和 C# 不一样的**：

| | C# | TS |
|---|---|---|
| 重写方法 | 父类必须 `virtual`/`abstract`，子类必须 `override` | **默认全部可重写**，不写 `override` 也能编过（TS 5 的 `override` 只是可选检查） |
| 接口是运行时类型吗 | ✅ `is` / 反射都能判 | ❌ 编译后消失，`instanceof` 完全无效 |
| 语法 | `: A, IB, IC` | `extends A implements IB, IC` |

⭐⭐ **最重要的一条**：`implements` 对 TS 来说**只是一次检查**，不建立任何运行时或类型层的关系。**删掉 `implements Singable`，只要形状对，照样能赋值** —— 这就是 §9 要讲的「结构化类型」。

## 7. 可见性修饰符（39-41）🔴 最高危

```ts
class Person {
  public name: string = 'jack'   // 默认，可省略
  protected age: number = 18
  private secret = 'xxx'
}
```

| 修饰符 | 谁能访问 |
|---|---|
| `public` | 任何地方（**默认**） |
| `protected` | 当前类 + 子类 |
| `private` | 只有当前类内部 |

### 7.1 🔴🔴 默认值是反的

| | C# | TS |
|---|---|---|
| 不写修饰符 | **private** | **public** |

**如果这 23 集只记一件事，就记这一条。**

你写了十年 C#，几乎没主动写过 `private`（因为是默认）。到 TS 里，**所有没写的成员全部变成 public**，而且：

- 不报错
- 不警告
- 编辑器不提示
- **是静默的**

这是一次纯粹由「习惯迁移」导致的权限泄漏。工程防线：ESLint 的 `explicit-member-accessibility` 规则，或者团队约定「成员一律显式写修饰符」。

### 7.2 `private` 是编译期的（不是真私有）

```ts
class Person { private age = 18 }

const p = new Person()
console.log(p.age)          // ❌ tsc 报错：属性"age"为私有属性，只能在类"Person"中访问
console.log((p as any).age) // ✅ 拿到 18 —— 一行就绕过
```

编译成 JS 之后，`age` 就是**一个普通属性**，跟 public 毫无区别。

| | C# | TS `private` | JS `#age` |
|---|---|---|---|
| 谁能访问 | 类内部 | 类内部（编译期约定） | 类内部（**真**） |
| 类外访问 | 编译错误 | 编译错误 | 语法错误 |
| `as any` 能绕吗 | ❌ 要反射 | ✅ **一行** | ❌ |
| 运行时存在吗 | ✅ 字段 | ✅ 普通字段 | ✅ 私有槽 |

**要真私有，用 `#age`（ES2022），别指望 `private` 关键字。**

### 7.3 构造函数上的修饰符（C# 也有，用途要知道）

```ts
class Singleton {
  private constructor() {}     // 不能 new，也不能被继承 → 单例模式
}

class Base {
  protected constructor() {}   // 不能 new，但能被继承 → 抽象基类
}
```

这两条和 C# **一模一样**，白送。

## 8. `readonly`（42）

```ts
class Person {
  readonly age: number = 18
}

interface IPoint {
  readonly x: number
  readonly y: number
}
```

规则两条：
1. **只能修饰属性**，不能修饰方法
2. 必须在**声明时**或**构造函数中**初始化

🔵 C# 对照：和 C# 的 `readonly` 字段**几乎完全一致**（也是声明或构造函数中赋值）。这条是白送的。

⚠️ 三个坑：

**① 浅层。** `readonly list: number[]` 只锁住**引用**，`list.push(1)` 完全合法。C# 的 `readonly List<int>` 也一样能 `Add` —— 老熟人了，不算新坑。

**② 编译期。** `(p as any).age = 20` 照样改得动。

**③ 真正的只读数组是另一个东西**：

```ts
readonly number[]          // 只读数组类型（不是 readonly 修饰属性）
ReadonlyArray<number>      // 等价写法
```

C# 对照：`readonly number[]` ≈ C#'s `IReadOnlyList<int>` —— **是类型层面的只读，不是字段层面的只读**。两个概念在两种语言里都存在，别混。

## 9. 类型兼容性（43-45）🔴🔴 全课程最值钱

### 9.1 一句话：TS 看**形状**，C# 看**名字**

- C# → **名义类型系统（nominal）**：必须显式 `implements` / 继承，**名字对不上就永远不兼容**
- TS → **结构化类型系统（structural）**：也叫**鸭子类型** —— 「走路像鸭子、叫起来像鸭子，那就是鸭子」

```ts
class Point   { x = 0; y = 0 }
class Point2D { x = 0; y = 0 }

let p: Point = new Point2D()   // ✅ TS 允许，两个类没有任何继承关系
```

**这一行在 C# 里永远编译不过。** 这是 TypeScript 和 C# 分岔最彻底的地方 —— 比你之前遇到的所有差异都深，因为它动的是**类型系统的根**。

### 9.2 对象 / 接口的规则：**成员多的可以赋给成员少的**

```ts
interface Point2D { x: number; y: number }
interface Point3D { x: number; y: number; z: number }

let p2: Point2D = { x: 1, y: 2 }
let p3: Point3D = { x: 1, y: 2, z: 3 }

p2 = p3   // ✅ 多 → 少：Point3D 里一定有 x 和 y
p3 = p2   // ❌ 少 → 多：类型 "Point2D" 中缺少属性 "z"
```

方向感和 C# 的「子类 → 父类」一致，**但不需要真的存在继承关系**，只要形状覆盖就行。

⚠️ 注意：这个规则是**单向**的。多 → 少可以，少 → 多不行。

### 9.3 🔴 多余属性检查（excess property check）—— 最容易懵的一坑

**同一件事，写法不同，结果不同：**

```ts
interface Point { x: number; y: number }

const p = { x: 1, y: 2, z: 3 }
const a: Point = p                        // ✅ 过了！因为有中转变量

const b: Point = { x: 1, y: 2, z: 3 }     // ❌ 对象字面量只能指定已知属性，"z"不在类型"Point"中
```

**为什么？** 因为**直接写字面量**时，多出来的属性 99% 是拼错或者手滑；**经过变量中转**说明你是有意为之（比如从一个更完整的对象里取子集）。

一句话记：

> **「新鲜的字面量」查得严，「已有的变量」查得松。**

官方管这叫 **freshness**（字面量类型的新鲜度）。这不是 bug，是 TS 特意设计的 —— 它在**拦错别字**，不是在拦赋值。

🛠️ 工程上的两个解法（都常见）：

```ts
// ① 中转一下（最常用）
const extra = { x: 1, y: 2, z: 3 }
const b: Point = extra

// ② 用类型断言（不推荐，会丢掉检查）
const c = { x: 1, y: 2, z: 3 } as Point
```

### 9.4 🔴 有 `private` / `protected` 成员时，退回名义类型

```ts
class A { private x = 1 }
class B { private x = 1 }

let a: A = new B()
// ❌ 类型具有私有属性"x"的单独声明
```

只要两边都有 `private` / `protected` 成员，TS 立刻要求它们**来自同一个声明**。这是结构化类型系统里的**名义化例外**，逻辑是：私有成员代表内部实现，长得一样也不代表能互换。

这条在写库、写框架、给第三方类做适配时会撞上。知道有这回事就行。

### 9.5 这一节真正的工程价值

理解了结构化类型，你就能解释前面好几件「莫名其妙」的事：

| 之前的疑问 | 现在的原因 |
|---|---|
| 为什么 `interface` 不写 `implements` 也能用？ | 结构化：形状对上就算 |
| 为什么多传一个字段有时候不报错？ | 变量中转绕过了 freshness（§9.3） |
| 为什么 `implements` 删掉代码照样跑？ | 它只是检查，不建立任何关系 |
| 为什么回调能塞进去一个「参数更少」的函数？ | 函数兼容性（§10） |

## 10. 函数之间的兼容性（46-48）

### 10.1 参数少的可以赋给参数多的（46）

```ts
type F1 = (a: number) => void
type F2 = (a: number, b: number) => void

let f1: F1 = a => {}
let f2: F2

f2 = f1   // ✅
f1 = f2   // ❌ 不能将类型"F2"分配给类型"F1"，目标需要 2 个参数但源只要 1 个…
```

**道理**：`f1` 根本不关心第二个参数，你按两个参数调它照样跑（JS 里多传参数本来就不报错 —— 回扣「JS 的静默失败」暗线）。

反方向不行：`f1(1)` 只给一个参数，而 `f2` 的实现里要用 `b`，`b` 会是 `undefined`。

### 10.2 参数类型：方向是**反**的（47）🔴

```ts
type Wide   = (a: number)  => void
type Narrow = (a: 1 | 2)   => void

let w: Wide
let n: Narrow

n = w   // ✅ 宽参数 → 窄参数：调用方保证只传 1|2，w 收 number，安全
w = n   // ❌ 调用方可能传 3，n 只认 1|2，会出事
```

记忆句：

> **返回值可以「窄」，参数必须「宽」。**
> （你要能接住别人给你的**所有**东西，但可以只还回去一部分。）

🔵 C# 对照：C# 委托的变体规则**方向和 TS 完全一致** —— `Action<object>` 可以赋给 `Action<string>`（参数逆变），`Func<string>` 可以赋给 `Func<object>`（返回值协变）。**这一节你的 C# 直觉是对的，可以直接迁移。**

（课程 46-47 只给了两条经验规则；上面这条原理能把那两条都推出来，也能推你没见过的第三种情况。）

### 10.3 返回值（48）

**原始类型：必须相同。**

```ts
type F5 = () => string
type F6 = () => number

let f5: F5 = () => ''
let f6: F6 = () => 1

f5 = f6   // ❌ 类型"F6"不能赋给"F5"，"number"不能赋给"string"
f6 = f5   // ❌
```

**对象类型：成员多的可以赋给成员少的**（就是 §9.2 的规则用在返回值上）。

```ts
type F7 = () => { x: number }
type F8 = () => { x: number; y: number }

let f7: F7 = () => ({ x: 1 })
let f8: F8 = () => ({ x: 1, y: 2 })

f7 = f8   // ✅ 返回 {x,y} 的函数，可以当「只返回 x」的函数用
f8 = f7   // ❌ 缺 y
```

⚠️ 小坑：`() => ({ x: 1 })` 外面的括号**不能省**。省了 `{` 会被解析成函数体，返回 `undefined`。

## 2. 编译产物对账：`enum` 是唯一的例外

**源码**

```ts
enum Direction { Up, Down, Left, Right }
```

**`tsc` 产物（数字枚举）**

```js
var Direction;
(function (Direction) {
    Direction[Direction["Up"] = 0] = "Up";
    Direction[Direction["Down"] = 1] = "Down";
    Direction[Direction["Left"] = 2] = "Left";
    Direction[Direction["Right"] = 3] = "Right";
})(Direction || (Direction = {}));
```

拆开看 `Direction[Direction["Up"] = 0] = "Up"` 这一句：

1. `Direction["Up"] = 0` —— 赋值语句的值是 `0`，所以外层是 `Direction[0]`
2. `Direction[0] = "Up"` —— 反向映射就这么来的

**一句话**：`Direction.Up === 0` 且 `Direction[0] === 'Up'`，**一个对象同时存了两个方向**。

**字符串枚举的产物**

```js
var Direction;
(function (Direction) {
    Direction["Up"] = "UP";
    Direction["Down"] = "DOWN";
})(Direction || (Direction = {}));
```

只有正向，**没有反向映射**（值 `'UP'` 不是合法下标，反查没意义）。

**对照：同一份文件里的其它类型**

```ts
interface IPoint { x: number }        // → 一行不剩
type Name = string                    // → 一行不剩
class Point { x: number = 0 }         // → class Point { x = 0 }（只剩运行时要用的部分）
```

## 3. 判断表：这个场景该用哪个

| 你要做的事 | 用什么 | 为什么 |
|---|---|---|
| 「只能取这几个字符串」 | 字面量联合 `'a' \| 'b'` | 零开销，够用 |
| 要遍历 / 反查 / 运行时校验 | `enum` | 有真实对象 |
| 值会跟着后端变、要断言合法性 | `enum` + `value in E` | 唯一能运行时校验的 |
| 一个对象长什么样 | `interface` | 可继承、可合并 |
| 一个对象或一个联合的别名 | `type` | 能表达联合、交叉、条件类型 |
| 要「数据 + 行为」打包 | `class` | 有构造函数、有方法 |
| 只想约束形状、不要实现 | `interface` + `implements` | 或者干脆不写 implements |
| 从已有值反推类型 | `typeof` | 少抄一遍 |
| 常量表（永远不变） | `as const` + `typeof` | 最精确 |

## 4. 兼容性规则总表（一条原理 + 三个方向）

| 比较的东西 | 规则 | 方向 |
|---|---|---|
| 对象 / 接口 | 成员多 → 成员少 | ✅ 单向 |
| 接口 → 接口（继承） | 子接口更「多」，可赋给父接口 | ✅ 单向 |
| 类 → 类 | 看形状，不看继承 | ✅ 双向可能 |
| 类（含 private） | 必须同一来源 | ❌ 名义化 |
| 函数参数**个数** | 少的 → 多的 | ✅ 单向 |
| 函数参数**类型** | 宽的 → 窄的（**逆变**） | 🔄 反着 |
| 函数**返回值** | 窄的 → 宽的（**协变**） | ✅ 顺向 |
| 字面量直接赋值 | 多一个属性就报错 | ❌ freshness |

## 2. 兼容性实验（43-48）：让 C# 直觉连续撞三次墙

```ts
// ═══ ① 没有任何继承关系的两个类，可以互相赋值 ═══
class Point   { x = 0; y = 0 }
class Point2D { x = 0; y = 0 }

let p1: Point = new Point2D()   // ✅ 形状一样就行 —— C# 里永远不行
console.log('① 结构化类型通过了', p1)

// ═══ ② 但 private 会让它退回名义类型 ═══
class A { private secret = 1 }
class B { private secret = 1 }

// let a: A = new B()           // ❌ 类型具有私有属性"secret"的单独声明

// ═══ ③ 多余属性：字面量严、变量松 ═══
interface P2 { x: number; y: number }

const extra = { x: 1, y: 2, z: 3 }
const ok: P2 = extra            // ✅ 中转变量，放行
// const no: P2 = { x: 1, y: 2, z: 3 }   // ❌ 字面量直接写，报错
console.log('③ freshness', ok)

// ═══ ④ 函数参数：少的 → 多的 ═══
const one = (a: number) => a
const two = (a: number, b: number) => a + b

const asTwo: (a: number, b: number) => number = one   // ✅
// const asOne: (a: number) => number = two           // ❌
console.log('④ 参数个数', asTwo(1, 2))                // 1（b 被忽略）

// ═══ ⑤ 函数参数：宽的 → 窄的（逆变） ═══
const wide   = (a: number) => a
const narrow = (a: 1 | 2) => a

const takeNarrow: (a: 1 | 2) => number = wide      // ✅
// const takeWide: (a: number) => number = narrow  // ❌
console.log('⑤ 参数逆变', takeNarrow(2))

// ═══ ⑥ 返回值：对象成员多的 → 少的（协变） ═══
const retXY = () => ({ x: 1, y: 2 })
const retX: () => { x: number } = retXY            // ✅
// const retY: () => { x: number; y: number } = () => ({ x: 1 })  // ❌
console.log('⑥ 返回值协变', retX())
```

## 3. 三个必跑的反直觉实验

**实验 1：`enum` 让「类型零开销」这条规则失效**

```bash
# 先删掉旧的 d1.js，确保跑的是 .ts
rm -f e1.js && printf 'enum E { A, B }\nconsole.log(E.A)\n' > e1.ts
node e1.ts
# → ERR_UNSUPPORTED_TYPESCRIPT_SYNTAX
npx tsc e1.ts && node e1.js
# → 0
```

结论：**Node 只会「删类型」，不会「生成代码」。enum 需要生成，所以它必须编译。**

**实验 2：`private` 挡不住 `as any`**

```ts
class User { private pwd = '123456' }
console.log((new User() as any).pwd)   // 123456
```

结论：**TS 的可见性修饰符是「给编译器的建议」，不是「给运行时的锁」。** 要真锁，用 `#pwd`。

**实验 3：`let` 和 `const` 推出来的类型真的不一样**

```ts
const s = 'hello'
let l = 'hello'

const checkS: 1 = s
// ❌ 不能将类型 "hello" 分配给类型 "1"   ← s 是字面量类型 "hello"
const checkL: 1 = l
// ❌ 不能将类型 "string" 分配给类型 "1"  ← l 是 string
```

两条报错信息里出现的类型不一样 —— 这就是 widening 的实物证据。

| 26 | **字面量也是类型**；`let` 拓宽、`const` 不拓宽 |
| 27-30 | **enum 是唯一会生成运行时代码的类型**；数字枚举有反向映射 |
| 31-32 | `any` 关掉检查；`unknown` 是安全版；`typeof` 在类型位置是「拿值换类型」 |
| 34-38 | class 语法白送；**`implements` 只是一次检查，不建立任何关系** |
| 39-42 | 🔴 **不写修饰符 = public**；`private` 只在编译期；`readonly` 是浅层 |
| 43-48 | 🔴🔴 **TS 看形状，C# 看名字**；参数逆变、返回值协变 |

## 2. ⭐⭐ 这一篇要背的

> **TS 的类型系统是按「形状」工作的，不是按「身份」工作的。**
>
> 这一句能解释：为什么不用 `implements`、为什么两个无关的类能互赋、为什么多传字段时灵时不灵、为什么函数参数是反着的。
> **C# 的整个类型体系建立在「名字」上 —— 这是你过去十年的地基，在 TS 里它不存在。**

**三条必须成为肌肉记忆的**：

1. **类的成员不写修饰符 = public**（C# = private）
2. **`enum` 会生成代码**，其它类型不会
3. **参数逆变、返回值协变**（这条你的 C# 直觉是对的，放心迁移）

## 3. ⭐ 收敛时刻：这 23 集把前面的哪几条线接到了同一个点

| 前面哪一条 | 当时的话 | 现在怎么解释 |
|---|---|---|
| 基础篇：**`interface` 不用 implements** | 「对象靠形状匹配，先记个影」 | 现在有名字了：**结构化类型系统**（§9.1） |
| 基础篇：**`as` 零检查** | 「只骗编译器」 | 同一个原因：TS 的类型没有运行时，所以断言不需要任何转换（§7.2 的 `as any` 是它的极端用法） |
| JS 进阶 176-181：**原型链 / `constructor` 不可信** | 「`constructor` 可改 → 不能当类型检查」 | 现在有了工业级替代：TS 的 `implements` 在**编译期**做这件事。但注意它也只是检查，不是身份 |
| JS 进阶 192-194：**`this` 看「点」** | 「点前是谁就是谁」 | class 方法里的 `this` 同样遵守 —— 所以 `setTimeout(this.move, 1000)` 会丢 `this`，得 `bind` 或箭头函数 |
| JS 进阶 167-169：**包装类型/装箱** | 「JS 里包装是一瞬间的事」 | `readonly` / `private` 也是「一瞬间的事」：编译完就没了 |
| 你对 JS「不严谨」的抵触 | 「改一处怕崩」 | 这一篇给的是**边界**：TS 不是把 JS 变严谨了，是把「编译期能管的」管住了，**管不到的（私有、只读、数据来源）一律没管** |

⭐ **一句收口**：

> 01-25 教你把类型写到明面上；26-48 教你**这套类型按什么规则互相认亲**。
> 规则只有一条 —— **看形状、不看名字** —— 但它的三个后果（多余属性、私有成员例外、函数逆变）每一个都会让你第一次遇到时愣住。

## 4. 静默失败清单（本轮 7 条）

> 老规矩：**这不是 TS 的 bug，是它的边界。**

| 你写的 | 实际发生 | 谁会拦 |
|---|---|---|
| 成员不写修饰符 | 全部变 public，外部随便改 | ❌ 没人 —— **本轮第一坑** |
| `private` 成员 + `as any` | 运行时照样读得到 | ❌ 没人 |
| `readonly arr: number[]` 然后 `arr.push()` | 内容被改 | ❌ 没人（只锁引用） |
| `let x = 'a'` 以为类型是 `'a'` | 实际是 `string`，后面赋值不报错 | ❌ 没人提示，靠悬停发现 |
| `any` 一路传下去 | 检查从源头就断了，后面全是 any | ⚠️ 只有 `noImplicitAny` 管隐式的 |
| 把 `unknown` 断言成具体类型 | 编译期放行，运行时可能 `undefined` | ❌ 没人 |
| 两个形状一样的类互赋 | 编译通过，但语义上可能是两个业务概念 | ❌ 没人 —— **结构化类型的代价** |

⭐ **最后一条是本轮最该带走的工程结论**：

> **结构化类型让代码更灵活，代价是「类型不再等于业务身份」。**
> `UserId` 和 `OrderId` 都是 `string`，TS 认为它们完全一样 —— **C# 里你能靠 `readonly struct UserId(string Value)` 区分，TS 里做不到（除非打品牌类型，属于进阶）。**

## 5. C# 类比可用度（本轮汇总）

| TS 的做法 | C# 对应 | 档 | 说明 |
|---|---|---|---|
| 字面量类型 `'a' \| 'b'` | 无 | ❌ | C# 表达不了；TS 的杀手级小特性 |
| `enum` 数字 | `enum` | ⭐⭐⭐⭐⭐ | 几乎一致 |
| `enum` 字符串 | 无 | ❌ | C# 只能靠 `[Description]` |
| `enum` 反向映射 | `Enum.GetName` | ⭐⭐⭐ | 手感不同，能力相似 |
| `any` | `dynamic` | ⭐ | 🔴 **延迟检查 vs 放弃检查** |
| `unknown` | `object` + 模式匹配 | ⭐⭐⭐ | 思路一致：先判断再用 |
| `typeof x`（类型位置） | `typeof(T)` | ⭐ | 🔵 输入输出全反，别硬套 |
| `as const` | `const` | ⭐⭐ | 保字面量类型，C# 没这概念 |
| class 字段声明 | 字段声明 | ⭐⭐⭐⭐⭐ | 完全一致 |
| 参数属性 `constructor(public x)` | C# 12 primary ctor | ⭐⭐⭐⭐ | TS 更直接（自动生成属性） |
| `extends` | `:` 继承 | ⭐⭐⭐⭐⭐ | 只差「不必写 virtual/override」 |
| `implements` | `: IInterface` | ⭐⭐ | 🔴 **TS 只是一次检查，没有运行时关系** |
| `public` / `protected` / `private` | 同名 | ⭐⭐⭐⭐ | 🔴 **默认值相反** |
| `#field` | 无 | ❌ | C# 没有「假私有」，一直是真的 |
| `readonly` 属性 | `readonly` 字段 | ⭐⭐⭐⭐⭐ | 一致（含浅层这个坑） |
| 结构化类型 | 无 | ❌ | 🔴🔴 **C# 全是名义类型，这条无法迁移** |
| 参数逆变 / 返回值协变 | 委托变体 | ⭐⭐⭐⭐⭐ | ✅ **方向完全一致，放心用** |

⭐ **本轮最大的可用度陷阱**：`public/private/readonly/implements` 这四个词长得和 C# 一模一样，**手感全不一样**。
凡是看到「熟悉的 C# 关键字」，先查一次默认值。

## 6. 解锁边界（本轮变更）

**新解锁**
- ✅ 字面量类型 + 联合（可以做「枚举替代」了）
- ✅ `enum`（含编译产物、反向映射、`node x.ts` 的坑）
- ✅ `any` / `unknown` / `typeof` / `as const`
- ✅ `class` 全套：字段、构造函数、参数属性、方法、`extends`、`implements`
- ✅ 三种可见性修饰符、`readonly`、`#` 私有字段
- ✅ 类型兼容性（结构化类型、freshness、函数逆变协变）

**仍然锁着（别提前用）**
- ❌ **交叉类型 `A & B`** —— 49-50 集
- ❌ **泛型 `<T>` / 泛型约束 / 泛型接口 / 泛型类** —— 51-58 集
- ❌ **工具类型 `Partial` / `Readonly` / `Pick` / `Record`** —— 59-62 集（这些正是「按形状改形状」的机器，学完 §9 才好懂）
- ❌ **索引签名 / 映射类型 / `keyof`** —— 63-68 集
- ❌ **`.d.ts` 类型声明文件** —— 69-75 集
- ❌ **`override` 关键字 / `abstract` / 抽象类** —— 课程不讲，需要时单独补
- ❌ **品牌类型（branded type）** —— 上面 §4 提到的 `UserId` 问题，要等泛型

⚠️ **下一轮三个必停的地方**

1. **`&` 和 `|` 是两套完全不同的运算** —— `A | B` 是「或」，`A & B` 是「且（合并）」。C# 里 `&` 是位运算，**这里它是类型合并**，别让眼睛骗你
2. **泛型 `<T>` 对你几乎零成本** —— C# 的泛型你熟到骨子里。唯一要重建的是「TS 的泛型在运行时不存在」（回扣 01 集），所以没有 `typeof(T)`、没有 `new T()`
3. **`extends` 在泛型里不是继承，是「约束」** —— `T extends { length: number }` 读作「T 必须长得像这样」。这和 §9 的结构化类型是同一条规则
