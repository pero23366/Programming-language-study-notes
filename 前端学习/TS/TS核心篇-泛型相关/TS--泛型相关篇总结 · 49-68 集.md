## 2. 一条主线：泛型是「类型的函数」，工具类型是「类型的 LINQ」

先把这条线立住，后面 20 集全是它的展开。四层递进：

```ts
// ═══ 第 0 层：写死 —— 一份代码只能服务一个类型 ═══
function idStr(value: string): string { return value }

// ═══ 第 1 层：泛型 = 把类型变成参数（51-58）═══
function id<T>(value: T): T { return value }

// ═══ 第 2 层：约束 = 给类型参数加「接口/基类要求」（53-54）═══
function len<T extends { length: number }>(v: T): number { return v.length }

// ═══ 第 3 层：类型级运算 = 用 keyof 拿键、用 in 遍历、用 T[K] 取值（64-68）═══
type Partial<T> = { [K in keyof T]?: T[K] }
```

**逐层对照 C#**：

| 层 | TS | C# 最接近的写法 | 差距 |
|---|---|---|---|
| 0 | 写死 | 写死 | 一样 |
| 1 | `<T>` | `<T>` | ⭐ **几乎一样** |
| 2 | `<T extends X>` | `where T : X` | 🟡 长相一样，**判定机制不同**（见 §4.4） |
| 3 | `keyof` / `[K in ...]` / `T[K]` | **无** | ❌ **C# 完全没有** |

⭐ **第 3 层值得单独说一句**：C# 里想做「把 T 的所有属性变可选 / 挑几个属性组成新类型」，只有三条路 —— 手写、反射（运行时）、Source Generator（另建项目 + 增量编译）。TS 里这是**一行类型别名**，且在编辑器里实时生效。

**用 LINQ 打个比方（只是比方，别当同一回事）**：

```csharp
// C# 在「值」上做：过滤、映射、投影
var names = users.Where(u => u.Age > 18).Select(u => u.Name);
```

```ts
// TS 在「类型」上做：挑键、映射值类型、全变可选
type Adult = Pick<User, 'name'>      // 相当于 Select 投影到某几个字段
type Opt = Partial<User>             // 相当于把所有字段变 nullable
```

**关键差异**：C# 的 LINQ 结果**运行时存在**；TS 的类型运算结果**只存在于编译器里，编译完连个字节都不剩**（回扣 TS--01 的「类型的生死四问」）。

## 3. 交叉类型 `&`（49-50）

### 3.1 什么是交叉类型

**定义**：`A & B` 表示「**同时具备** A 和 B 的所有成员」的类型。用 `&` 连接。

```ts
type Person = { name: string; age: number }
type Contact = { phone: string; email: string }

// 交叉类型：两边的成员全都要
type Employee = Person & Contact

const e: Employee = {
  name: '张三', age: 28,        // ← Person 的部分
  phone: '138xxxx', email: 'a@b.c'  // ← Contact 的部分
}

// 少一个就报错
const e2: Employee = { name: '张三', age: 28 }  // ❌ 缺 phone 和 email
```

**注意词的方向**：名字叫「交叉」，实际效果是「**并集**」—— 成员取**全部**，不是取交集。这是全课程最容易望文生义的地方。

> ⚠️ **「交叉」这个词骗了无数人**：数学里 `A ∩ B` 是取两者共有的部分；TS 的 `A & B` 是**两边成员全都要**。记法：**`&` 读作「并且」，不读作「交集」**。

### 3.2 🟡 交叉类型 vs 接口继承（50 集）

这是 50 集整整一集在讲的东西。**两者能写出完全相同的效果**：

```ts
// 写法一：交叉类型
type EmployeeA = Person & Contact

// 写法二：接口继承
interface EmployeeB extends Person, Contact {}
```

```ts
// 这两种类型在结构上完全等价，互相赋值都合法
const a: EmployeeA = { name: '', age: 1, phone: '', email: '' }
const b: EmployeeB = a   // ✅ 成立
```

**那到底差在哪？** 差在**「能组合什么」**：

| | 交叉类型 `&` | 接口继承 `extends` |
|---|---|---|
| 左边必须是 | 任意类型（`type` / `interface` / 字面量） | 只能 `interface` 或 `class` |
| 右边必须是 | 任意类型 | 只能 `interface` 或 `class` |
| 能不能组合联合类型 | ✅ `type X = (A \| B) & C` | ❌ 不行 |
| 能不能组合基本类型 | ✅ `string & {}`（少见但合法） | ❌ 不行 |
| 同名属性冲突时 | 类型变 **`never`** | **直接编译报错** |
| 声明合并 | ❌ 不支持 | ✅ 同名 interface 会自动合并 |
| 编译后 | 无 | 无 |

**工程选择建议（简单记住）**：

> **描述「对象长什么样」→ 用 `interface`（可继承、可合并、报错友好）。**
> **需要「拼装」已有类型 → 用 `&`。**

⭐ **50 集真正想说的是**：`&` 的价值不在「能做接口继承的事」，而在**「能对 type 别名做组合」**。你 JS 里学过的 `Object.assign(目标, 源)` 是**值**层面的叠加，`&` 是**类型**层面的叠加 —— 两者思路完全对应：

```ts
// 值层面（JS 学过）
const merged = Object.assign({}, person, contact)

// 类型层面（本集）
type Merged = Person & Contact
```

### 3.3 ⚠️ 同名属性冲突 → `never`

当两个类型有同名属性但**类型不同**时，交叉后那个属性的类型变成 `never`：

```ts
type A = { id: number; name: string }
type B = { id: string; age: number }

type AB = A & B
// AB 的 id 类型是 number & string = never

const x: AB = { id: 1, name: '', age: 1 }
// ❌ 报错：number 不能赋给 never
```

**为什么是 `never`**：`&` 要求「同时满足两边」，而一个值不可能既是 `number` 又是 `string`，所以这个属性的**类型集合为空**。空集类型就是 `never`。

> **坑在这里**：`number & string` 看起来像个奇怪的「交集类型」，但它不是 —— 它是**空集**。
> 编译器的报错信息会是 `Type 'number' is not assignable to type 'never'`，很多人看不懂这句在说什么。看到 `never` 就先想：**是不是 `&` 的两边撞名字了。**

### 3.4 交叉类型最常用的真实场景

```ts
// 场景：给一个类型「追加」额外字段，不改原类型
type User = { id: number; name: string }
type UserWithToken = User & { token: string }

// 场景：组件库里的 Props 合并
type ButtonProps = BaseProps & { onClick: () => void }
```

⭐ **这是 `&` 唯一的日常用途**：**在别人的类型上加东西**。改了库的类型会污染全局，`&` 造一个新的。

## 4. 泛型（51-58）🔥🔥

### 4.1 没有泛型的世界长什么样

这是理解泛型的唯一正确入口。假设要写「取数组第一个元素」：

```ts
// ═══ 方案 A：每个类型写一遍 —— 重复 ═══
function firstStr(arr: string[]): string { return arr[0] }
function firstNum(arr: number[]): number { return arr[0] }

// ═══ 方案 B：用 any —— 丢类型 ═══
function firstAny(arr: any[]): any { return arr[0] }
const n = firstAny([1, 2, 3])
n.toFixed(2)   // ✅ 能过（因为 any），但 n 可能是字符串，运行时才炸
```

**方案 B 的病根**：`any` 把「输入类型」和「输出类型」之间的**关系**弄丢了。函数内部知道「进什么出什么」，但**没法告诉编译器**。

```ts
// ═══ 方案 C：泛型 —— 保住这个关系 ═══
function first<T>(arr: T[]): T { return arr[0] }

const s = first(['a', 'b'])   // s: string  ← 关系保住了
const n2 = first([1, 2, 3])   // n2: number ← 关系保住了
```

> **泛型的本质 = 让「类型之间」也能建立函数关系。**
> `any` 让类型消失；泛型让类型**流动**。

⭐ **一句话概括**：泛型不是「让代码通用」，是**「让编译器记住输入和输出的关系」**。通用只是副产品。

### 4.2 语法：`<T>` 加在哪里

课程 51 集把三种位置一次讲完：

```ts
// ═══ ① 泛型函数：`<T>` 在函数名后面 ═══
function identity<T>(value: T): T { return value }

// ═══ ② 泛型接口：`<T>` 在接口名后面 ═══
interface IdFunc<T> {
  id: T
  ids: () => T[]
}

// ═══ ③ 泛型类：`<T>` 在类名后面 ═══
class Box<T> {
  constructor(public value: T) {}
}
```

**C# 对照 —— 这一块是「几乎一模一样」**：

| | C# | TS |
|---|---|---|
| 泛型函数 | `T Identity<T>(T value)` | `function identity<T>(value: T): T` |
| 泛型接口 | `interface IRepo<T>` | `interface IdFunc<T>` |
| 泛型类 | `class Box<T>` | `class Box<T>` |
| 调用时指定 | `Identity<string>("a")` | `identity<string>("a")` |
| **编译后还在吗** | ✅ **在 metadata 里，`typeof(T)` 能拿到** | ❌ **一个字都不剩** |

⭐ **最后一行决定了两边能干什么、不能干什么**。这就是 §4.6 要单独讲的「泛型擦除」。

### 4.3 ⭐ 类型参数推断（52 集）

`<T>` 可以**不写**，编译器能从实参推出来：

```ts
function identity<T>(value: T): T { return value }

identity<string>('abc')   // 显式指定
identity('abc')           // ✅ 推断为 string（推荐）
identity(123)             // ✅ 推断为 123（字面量类型！回扣 26 集）
```

**52 集的核心提醒**：**能推断就别写**。写多了不但啰嗦，还会**把类型写窄**：

```ts
const arr = ['a', 'b']
identity<string[]>(arr)   // 返回 string[]
identity(arr)             // ✅ 返回 string[]（一样）

// 但这里有区别：
const lit = identity<'a'>('a')   // 类型是 'a'（字面量）
const wide = identity('a')       // 类型是 string
```

> ⚠️ **推断不出时会静默变宽**：如果实参是 `null` / `undefined` / 空数组，`T` 可能被推成 `unknown` 或 `never`。
> **工程上怎么防**：看到类型莫名其妙变成 `unknown`，先检查调用处有没有传空值。

### 4.4 🟡🔴 泛型约束 `extends`（53-54 集）—— 本节是全篇最大撞名

**先看没有约束会发生什么**：

```ts
function getLength<T>(value: T) {
  return value.length   // ❌ 报错：类型 T 上不存在属性 length
}
```

**原因**：`T` 是「任意类型」，编译器不能假设任意类型都有 `length`（`number` 就没有）。这和 C# 一模一样 —— C# 里 `T` 不加约束也访问不了成员。

**解法 —— 加约束**：

```ts
function getLength<T extends { length: number }>(value: T): number {
  return value.length   // ✅ 现在编译器知道 T 至少有 length
}

getLength('abc')          // ✅ 3（string 有 length）
getLength([1, 2])         // ✅ 2（数组有 length）
getLength({ length: 10 }) // ✅ 10（对象结构匹配就行）
getLength(123)            // ❌ number 没有 length
```

**C# 对照**：

| | C# | TS |
|---|---|---|
| 语法 | `where T : IFoo` | `<T extends IFoo>` |
| 位置 | 参数列表**后** | 类型参数**内** |
| 可否多个 | `where T : A, B` | `<T extends A & B>` |
| 判定依据 | **名义**（是不是实现了这个接口） | **结构**（长得像不像） |

⭐ **第 4 行是全部重点**。回扣 43-48 集：

```ts
// TS 里，这个对象没有任何 interface 声明，但它「满足」约束
getLength({ length: 10 })   // ✅ 因为结构上匹配
```

```csharp
// C# 里同样的东西过不了编译
void GetLength<T>(T value) where T : IHasLength { }
GetLength(new { length = 10 });   // ❌ 匿名类型没实现 IHasLength
```

> **C# 问「你是不是这个家族的人」；TS 问「你身上有没有这些成员」。**
> 这是 43-48 集类型兼容性在同一件事上的第二次出现。**它会在后面每一轮反复出现，直到你不再觉得奇怪。**

**🔴 撞名警报：`extends` 这个关键字有 4 种身份**

这是本课程最容易搞混的地方，必须当场切开：

| # | 出现位置 | 含义 | 本课讲过吗 |
|---|---|---|---|
| ① | `class A extends B` | **继承**（真的有父类，有 `super`） | ✅ 37 集 |
| ② | `interface A extends B` | **接口继承**（扩展成员） | ✅ 22 集 |
| ③ | `<T extends X>` | **类型参数约束**（限制范围） | ✅ 53-54 集（本节） |
| ④ | `T extends U ? A : B` | **条件类型**（类型级三元表达式） | ❌ **本课没讲** |

> ⚠️ **③ 和 ④ 长得一模一样**，但 ③ 是「限制」，④ 是「判断」。你以后看别人代码看到 `<T extends ...>` 里的 `extends` 后面跟 `?`，那就是条件类型 —— 本课不涉及，遇到知道「这是另一回事」就行。

⭐ **53 和 54 两集其实是同一件事的两半**：53 集讲「为什么要约束」（不约束访问不了成员），54 集讲「怎么加约束」（`extends` 语法）。**两集合起来 = C# 的 `where` 子句**。

### 4.5 多个泛型变量（55 集）

一个类型参数不够时，逗号隔开：

```ts
// 经典例子：安全地取对象属性
function getProp<T, K extends keyof T>(obj: T, key: K): T[K] {
  return obj[key]
}

const user = { name: 'pero', age: 22 }

const n = getProp(user, 'name')   // n: string
const a = getProp(user, 'age')    // a: number
getProp(user, 'nmae')             // ❌ 报错：'nmae' 不在 'name' | 'age' 里
```

**这一行代码里塞了三个新语法**，55 集是它们的第一次合体：

| 语法 | 作用 | 本课首次出现 |
|---|---|---|
| `<T, K>` | 两个类型参数 | 55 集 |
| `K extends keyof T` | K 只能是 T 的键 | 55 集（`keyof` 详解在 65 集） |
| `T[K]` | 按 K 取 T 里的那个类型 | 55 集（详解在 67 集） |

⭐ **这行 `getProp` 是整篇的浓缩**：泛型 + 约束 + `keyof` + 索引访问，四种能力一句话。**建议直接背下来**，后面写工具库天天用。

> 💡 **业务价值**：这就是 `lodash.get` 的类型版。JS 里 `obj[key]` 写错键名只是返回 `undefined`（回扣 JS 静默失败暗线），TS 这里**编译期就红**。

### 4.6 🔴🔴 泛型擦除：C# 人最需要重新建立的一个认知

**这是 51 集一句话带过、但影响最深远的点。**

```ts
function identity<T>(value: T): T { return value }
```

编译后：

```js
function identity(value) { return value }
```

**`<T>` 完全消失。** 对比 C#：

```csharp
T Identity<T>(T value) => value;
// 编译后：metadata 里完整保留 T，
// 而且 typeof(T) 在运行时真的能拿到
```

**由此推出的四条「TS 做不到」（每一条 C# 都能做）**：

| C# 能做 | TS 能做吗 | 原因 |
|---|---|---|
| `new T()`（创建泛型实例） | ❌ | 运行时不知道 T 是谁 |
| `typeof(T)` | ❌ | 类型信息已销毁 |
| `default(T)` | ❌ | 同上 |
| 根据 `T` 做运行时分支 | ❌ | 同上 |
| `T` 有默认值 `<T = string>` | ⚠️ 本课没讲但 TS 支持 | 编译期用 |
| 用 `T` 做类型标注 | ✅ | **编译期就够了** |

```ts
// ❌ 编译不过：'T' only refers to a type, but is being used as a value here
function create<T>(): T { return new T() }
```

**替代方案（工程上怎么写）**：

```ts
// 把「造对象」这件事变成参数传进来 —— 显式传工厂
function create<T>(factory: () => T): T { return factory() }
create(() => ({ id: 1 }))   // ✅ 类型推断为 { id: number }

// 或者传构造函数
function create2<T>(Ctor: new () => T): T { return new Ctor() }
class User { constructor(public name = '') {} }
create2(User)   // ✅
```

> ⭐ **一句话收口**：**C# 的泛型是「运行时真的有一个 T」；TS 的泛型是「写代码时假装有一个 T」。**
> 所以 TS 里凡是需要「在运行时知道 T」的事，全部要改成**显式传参数**。

### 4.7 泛型接口 + 数组是泛型（56-57 集）

```ts
// 56 集：泛型接口
interface IdFunc<T> {
  id: T
  ids: () => T[]
}

const obj: IdFunc<number> = {
  id: 1,
  ids: () => [1, 2, 3]
}
```

**57 集的核心结论 —— 数组本身就是个泛型接口**：

```ts
let arr1: number[] = [1, 2, 3]
let arr2: Array<number> = [1, 2, 3]   // 完全等价

// Array 的真实形状（简化）
interface Array<T> {
  length: number
  push(...items: T[]): number
  map<U>(fn: (v: T) => U): U[]   // ← 注意：map 自己也是泛型
  [n: number]: T                  // ← 索引签名（63 集讲）
}
```

⭐ **这一集的价值不在语法，在「视角」**：`number[]` 那个 `[]` 只是 `Array<number>` 的糖。**所有集合类型都是泛型**，`Map<K, V>`、`Set<T>`、`Promise<T>` 全是同一个套路。

**C# 对照**：`List<int>` ↔ `Array<number>`，思路完全一样。差异只在 TS 里 `T[]` 这个简写没有 C# 对应物。

### 4.8 泛型类（58 集）

```ts
class GenericNumber<T> {
  defaultValue: T
  add: (x: T, y: T) => T

  constructor(defaultValue: T, add: (x: T, y: T) => T) {
    this.defaultValue = defaultValue
    this.add = add
  }
}

const myNum = new GenericNumber<number>(0, (x, y) => x + y)
const myStr = new GenericNumber<string>('', (x, y) => x + y)

myNum.add(1, 2)      // ✅ 3
myStr.add('a', 'b')  // ✅ 'ab'
myNum.add('a', 'b')  // ❌ string 不能赋给 number
```

**C# 对照**：一模一样，`class Box<T>`。**这是全篇 C# 复用度最高的一节，几乎不用学。**

> ⚠️ **一个差异**：TS 的泛型类**不能**在静态成员里用 `T`。
> ```ts
> class Box<T> {
>   static create(): T { }   // ❌ 静态成员不能引用类的类型参数
> }
> ```
> 原因还是擦除 —— 静态成员不依附实例，没有「实例化时的 T」。C# 里 `class Box<T>` 的静态成员同样不能用 `T`，**这条两边一致**。

## 5. 四个泛型工具类型（59-62 集）

**这四个是 TS 官方内置的「类型函数」**，全部定义在 `lib.es5.d.ts` 里。课程按顺序讲：`Partial` → `Readonly` → `Pick` → `Record`。

### 5.1 速记表

| 工具类型 | 一句话 | 效果 | 典型场景 |
|---|---|---|---|
| `Partial<T>` | 全变**可选** | `{ a: string }` → `{ a?: string }` | 更新接口的入参（只传要改的字段） |
| `Readonly<T>` | 全变**只读** | `{ a: string }` → `{ readonly a: string }` | 配置对象、常量表 |
| `Pick<T, K>` | **挑几个** | `{ a, b, c }` + `'a'\|'b'` → `{ a, b }` | 列表页只需要部分字段 |
| `Record<K, T>` | **造一个键值对象** | `'a'\|'b'` + `number` → `{ a: number, b: number }` | 枚举 → 文案映射表 |

### 5.2 逐个看

```ts
interface User {
  id: number
  name: string
  age: number
}

// ═══ Partial：全部可选 ═══
type PartialUser = Partial<User>
// { id?: number; name?: string; age?: number }

const patch: PartialUser = { name: '新名字' }   // ✅ 只传一个
function updateUser(id: number, data: Partial<User>) { /* ... */ }
updateUser(1, { age: 30 })   // ✅ 更新接口的标准写法

// ═══ Readonly：全部只读 ═══
type ReadonlyUser = Readonly<User>
const u: ReadonlyUser = { id: 1, name: 'a', age: 1 }
u.name = 'b'   // ❌ 报错：Cannot assign to 'name' because it is a read-only property

// ═══ Pick：挑属性 ═══
type UserSummary = Pick<User, 'id' | 'name'>
// { id: number; name: string }

// ═══ Record：造键值类型 ═══
type Page = 'home' | 'about' | 'contact'
type PageInfo = Record<Page, { title: string }>
// { home: {...}; about: {...}; contact: {...} }

const info: PageInfo = {
  home: { title: '首页' },
  about: { title: '关于' },
  contact: { title: '联系' }
}
// 少写一个键就报错 ✅ 这是 Record 最大的价值
```

### 5.3 ⚠️ 两个必须知道的边界

**① 全是「浅层」，不递归**

```ts
interface Nested {
  a: string
  b: { c: number }
}

type P = Partial<Nested>
// { a?: string; b?: { c: number } }   ← b 内部没变，c 还是必填
```

> **工程上怎么防**：需要深层可选得自己写递归工具类型（本课不讲，属于「类型体操」范畴）。记住 `Partial` 只削**一层**。

**② `Readonly` 只在编译期生效，运行时能改**

```ts
const u: Readonly<User> = { id: 1, name: 'a', age: 1 }
;(u as any).name = 'hacked'   // ✅ 运行时真的改了
console.log(u.name)           // 'hacked'
```

> ⚠️ **这不是 bug，是代价**（回扣「类型擦除」）。`readonly` 是**编译器约束**，`Object.freeze` 才是**运行时约束**。
> **工程上怎么防**：真正需要运行时不可变，用 `Object.freeze`；`Readonly<T>` 只防自己人手滑。

**③ `Record<string, T>` 是个「静默失败陷阱」**

```ts
const map: Record<string, number> = {}
map['随便什么键'] = 1     // ✅ 不报错
map.nmae                  // ✅ 也不报错（类型是 number）
const v = map.nmae        // undefined，但类型写着 number ← 💀
```

> 💀 **这是本篇最像 JS 的一处**：`Record<string, T>` 的键是「任意字符串」，**拼错键名编译器不管**。
> **工程上怎么防**：键有限就用联合类型 `Record<'a'|'b', number>`，别用 `string`。这一条记牢 —— 它把 TS 的收益直接抹平了。

### 5.4 61 集的一个细节：`Pick` 的 K 有约束

```ts
type Bad = Pick<User, 'nmae'>   // ❌ 报错：'nmae' 不在 keyof User 里
```

因为 `Pick` 的定义是：

```ts
type Pick<T, K extends keyof T> = { [P in K]: T[P] }
```

**`K extends keyof T` 就是 §4.4 的泛型约束**。**四个工具类型的定义全部长这样** —— 这就是 66 集要拆的东西。

## 6. 索引签名类型（63 集）🆕

### 6.1 解决什么问题

有些对象的**键是不确定的**：

```ts
// 这个对象有几个键？不知道，取决于用户
const scores = {
  math: 90,
  english: 85,
  // ... 可能还有 20 个科目
}
```

手写 interface 写不全。索引签名解决这个：

```ts
interface ScoreMap {
  [key: string]: number
}

const s: ScoreMap = { math: 90, english: 85 }   // ✅ 任意键都行
s.physics = 77                                   // ✅
s.chem = 'A'                                     // ❌ 值必须是 number
```

**语法形状**：`[任意变量名: 键的类型]: 值的类型`

- 键的类型只能是 `string` / `number` / `symbol`（或其联合）
- 那个变量名（`key`）只是占位，随便叫，**不能真的用**

### 6.2 ⚠️ 最容易踩的坑：索引签名会「管住」所有具名属性

```ts
interface Wrong {
  name: string        // ← 想放字符串
  [key: string]: number
}
// ❌ 报错：Property 'name' of type 'string' is not assignable to 'string' index type 'number'
```

**原因**：`[key: string]` 意思是「**所有**字符串键的值都是 number」，`name` 也是字符串键，所以必须是 number。

**正确写法 —— 用联合类型让所有成员都合规**：

```ts
interface Right {
  name: string
  [key: string]: string | number   // ← 值类型放宽到「涵盖所有成员」
}
```

> ⚠️ **这个坑每次都会遇到**，因为直觉上会以为「具名属性优先」。不是 —— 索引签名**统管一切**。

### 6.3 数组就是索引签名

```ts
// 57 集说数组是泛型接口，63 集补上它的「形状」
interface MyArray<T> {
  [n: number]: T
  length: number
}

const arr: MyArray<string> = ['a', 'b']
arr[0]     // string
arr.length // number
```

⭐ **两个视角对接起来了**：`Array<T>` = 泛型参数 `<T>` + 索引签名 `[n: number]: T`。**这就是 57 + 63 两集的合体。**

### 6.4 C# 对照：`Dictionary` 只能算「半个」

| | C# | TS |
|---|---|---|
| 写法 | `Dictionary<string, int>` | `{ [key: string]: number }` |
| 键类型 | 任意类型（含自定义类型） | 只能 `string`/`number`/`symbol` |
| 编译期检查键 | ✅ 类型安全 | ❌ **任意 string 都合法** |
| 运行时结构 | 哈希表（真容器） | **普通对象**（没有额外结构） |

> ⭐ **关键差异**：`Dictionary` 是**运行时容器**；索引签名只是**对普通对象的形状描述**，编译完什么都没有。
> **所以别把索引签名当 Dictionary 用** —— 它不提供 `ContainsKey`、不保证 O(1)、不隔离原型链。

## 7. 映射类型 + `keyof`（64-66 集）🔥🔥 全篇最难

### 7.1 `keyof` 是什么（65 集）

**`keyof T` = 取 T 的所有键，组成一个联合类型。**

```ts
interface Person {
  name: string
  age: number
}

type PersonKeys = keyof Person
// 'name' | 'age'   ← 一个字符串字面量联合类型

let k: PersonKeys = 'name'   // ✅
k = 'age'                    // ✅
k = 'address'                // ❌ 不在联合里
```

**C# 对照**：❌ **没有直接对应物**。最接近的是 `typeof(T).GetProperties().Select(p => p.Name)`，但那是**运行时反射**，返回 `string[]`，**丢失字面量类型**。

> ⭐ **这就是「类型级编程」的第一个特征**：`keyof` 的结果是一个**类型**，不是一个值。它在编译期就被算完了。

**`keyof` 的三个变体（值得知道）**：

```ts
type K1 = keyof { a: 1; b: 2 }        // 'a' | 'b'
type K2 = keyof any                    // string | number | symbol
type K3 = keyof string[]               // number | 'length' | 'push' | ...
```

> 💡 `keyof any` = `string | number | symbol`，这正是 `Record<K, T>` 里 `K` 的默认约束。

### 7.2 映射类型是什么（64 集）

**定义**：`[K in Keys]` 遍历一个**联合类型**，为每个成员生成一个属性。

```ts
// ═══ 最基础的映射类型 ═══
type Keys = 'a' | 'b' | 'c'
type Obj = { [K in Keys]: number }
// { a: number; b: number; c: number }
```

**读法**：把 `in` 读作 **「对于 Keys 里的每一个 K，生成一个属性」**。

**🔵 撞名警报：这个 `in` 不是 JS 的 `in`**

| | JS 的 `in` | TS 映射类型的 `in` |
|---|---|---|
| 位置 | `'a' in obj`（表达式） | `[K in Keys]`（类型内） |
| 作用 | **判断**键在不在对象里 | **遍历**联合类型 |
| 求值时机 | 运行时 | 编译期 |

> ⚠️ 不要用 JS 的 `in` 的语义去理解它。这里的 `in` 是「**遍历**」，更像 C# 的 `foreach`。

**和索引签名的区别（这是 63/64 两集的分界）**：

| | 索引签名 `[key: string]: T` | 映射类型 `[K in Keys]: T` |
|---|---|---|
| 键从哪来 | 任意（不枚举） | **枚举一个联合类型** |
| 键的数量 | 无限 | **确定的**（联合里有几个就是几个） |
| 能不能加修饰符 | ❌ | ✅ `?`、`readonly`、`-?`、`-readonly` |
| 类比 C# | `Dictionary` | 手写的固定类 |

### 7.3 66 集：拆开 `Partial` 看内脏

**这是 66 集的全部内容，也是本篇最重要的一个瞬间。**

你以为 `Partial<T>` 是个神秘内置物，其实它的源码只有一行：

```ts
type Partial<T> = {
  [K in keyof T]?: T[K]
}
```

**逐段翻译成人话**：

| 片段 | 意思 | C# 类比 |
|---|---|---|
| `type Partial<T>` | 定义一个泛型类型 | `class Partial<T>`（但零运行时） |
| `[K in keyof T]` | **遍历 T 的每一个键** | `foreach (var K in typeof(T).GetProperties())` |
| `?` | 每个属性加「可选」 | `int?`（但语义不同） |
| `T[K]` | 取原类型里 K 对应的类型 | ❌ 无 |

**同类拆解：四个工具类型的真身**

```ts
// 这些全部是 TS 源码级别的一行（lib.es5.d.ts）
type Partial<T>  = { [K in keyof T]?: T[K] }
type Required<T> = { [K in keyof T]-?: T[K] }       // -? 去掉可选
type Readonly<T> = { readonly [K in keyof T]: T[K] }
type Pick<T, K extends keyof T> = { [P in K]: T[P] }
type Record<K extends keyof any, T> = { [P in K]: T }
```

⭐ **66 集的真正意义**：**把你对「内置功能」的敬畏，换成「我也能写」**。

**自己写一个工具类型试试**：

```ts
// 目标：把 T 的所有属性变成「可选 + 只读」
type MyOptionalReadonly<T> = {
  readonly [K in keyof T]?: T[K]
}

interface User { id: number; name: string }
type R = MyOptionalReadonly<User>
// { readonly id?: number; readonly name?: string }
```

**修饰符的加减法（🔥 值得单独记）**：

| 写法 | 作用 |
|---|---|
| `[K in T]` | 原样 |
| `[K in T]?` | 加上可选 |
| `[K in T]-?` | **去掉**可选（= `Required`） |
| `readonly [K in T]` | 加上只读 |
| `-readonly [K in T]` | **去掉**只读 |

> 💡 `-?` 和 `-readonly` 那个**减号**，只能用在映射类型里。这是 TS 独有的语法，C# 完全没有。

### 7.4 ⚠️ 映射类型的两个坑

**坑一：`keyof` 只取「自有属性」的键，不含索引签名展开**

```ts
interface WithIndex {
  a: string
  [key: string]: string
}
type K = keyof WithIndex   // string | number  ← 被索引签名吞了
```

索引签名存在时，`keyof` 返回的是宽泛的 `string | number`，**不是 `'a'`**。这会让映射类型失去精确性。

**坑二：映射类型不能「增加」或「删除」键**

```ts
type Add<T> = { [K in keyof T]: T[K]; extra: string }
// ❌ 报错：映射类型里不能用分号追加成员
```

想加字段只能用交叉 `&`（回扣 §3.4）：

```ts
type Add<T> = { [K in keyof T]: T[K] } & { extra: string }   // ✅
```

## 8. 索引查询类型 `T[K]`（67-68 集）

### 8.1 基本使用（67 集）

**`T[K]` = 「取 T 里键为 K 的那个属性的类型」。** 注意这是**类型层面**的取值，不是在取值。

```ts
interface Person {
  name: string
  age: number
  address: { city: string }
}

type NameType = Person['name']       // string
type AgeType = Person['age']         // number
type AddrType = Person['address']    // { city: string }
type CityType = Person['address']['city']   // string ← 可以连续取

type Bad = Person['nmae']            // ❌ 报错：'nmae' 不在 keyof Person 里
```

**C# 对照**：❌ 无。C# 里「取某属性的类型」只能靠反射 `typeof(Person).GetProperty("Name").PropertyType`，返回 `Type` 对象，**不能当类型用**。

⭐ **一句话**：`Person['name']` 的结果是**一个类型**，可以直接拿去声明变量、当函数返回值、做泛型实参。

### 8.2 一次查多个（68 集）

**关键结论：`T[A | B]` = `T[A] | T[B]`** —— 查多个键，得到它们类型的**联合**。

```ts
type Person = { name: string; age: number; vip: boolean }

type V1 = Person['name' | 'age']
// string | number   ← 自动合并成联合类型

type V2 = Person['name'] | Person['age']
// string | number   ← 和上面完全等价
```

**组合 `keyof` 的写法（最常见）**：

```ts
type AllTypes = Person[keyof Person]
// string | number | boolean  ← 取「所有属性类型」的联合
```

**这行是本篇的「啊哈时刻」**：`Person[keyof Person]` = 用「所有键」去查「所有值类型」。**一句话拿到一个对象所有属性类型的并集。**

### 8.3 最实用的技巧：`T[number]` 取数组元素类型

```ts
type Arr = string[]
type Item = Arr[number]   // string

// 更常见：函数参数数组 → 元素类型
function fn(a: string, b: number) {}
type Params = Parameters<typeof fn>       // [a: string, b: number]
type First = Params[number]               // string | number

// 取元组的某一项
type Tuple = [string, number, boolean]
type T0 = Tuple[0]   // string
type T1 = Tuple[1]   // number
type TN = Tuple[number]  // string | number | boolean（所有项）
```

> 💡 **为什么 `Arr[number]` 是 string**：数组的索引签名是 `[n: number]: T`（63 集），用 `number` 去查，得到的就是 `T`。**63 集的知识在这里结账。**

### 8.4 工程上的真实用途

```ts
// 场景一：从接口里提取某个字段的类型，不用重复声明
interface ApiUser {
  id: number
  profile: { avatar: string; bio: string }
}
type Avatar = ApiUser['profile']['avatar']   // string

// 场景二：配合泛型，写「按字段名取值」的函数（回扣 §4.5）
function pluck<T, K extends keyof T>(list: T[], key: K): T[K][] {
  return list.map(item => item[key])
}
const users = [{ name: 'a', age: 1 }, { name: 'b', age: 2 }]
pluck(users, 'name')   // string[]
pluck(users, 'age')    // number[]

// 场景三：定义「状态机」的合法值
type Status = 'pending' | 'done'
type StatusMap = Record<Status, { label: string }>
type StatusLabel = StatusMap[Status]['label']   // string
```

## 2. C# ↔ TS 语法对照

| 目的 | C# | TS |
|---|---|---|
| 泛型方法 | `T F<T>(T x)` | `function f<T>(x: T): T` |
| 泛型约束 | `where T : IFoo` | `<T extends IFoo>` |
| 多约束 | `where T : A, B` | `<T extends A & B>` |
| 泛型接口 | `interface I<T>` | `interface I<T>` |
| 泛型类 | `class C<T>` | `class C<T>` |
| 实例化 | `new C<int>()` | `new C<number>()` |
| 类型形参默认值 | `where T : new()` | `<T = {}>`（少用） |
| 取属性类型 | 反射（运行时） | `T['key']`（编译期） |
| 取所有属性名 | 反射（运行时） | `keyof T`（编译期） |
| 遍历属性构造类型 | Source Generator | `[K in keyof T]` |
| 全部变可选 | 手写 / 反射 | `Partial<T>` |

## 3. 判断表：什么时候用什么

**遇到问题先问三个问题，按顺序：**

| 问题 | 答「是」→ 用什么 |
|---|---|
| ① 需要「同时具备两个类型的成员」？ | `A & B`（或接口 `extends`） |
| ② 需要「同一份逻辑服务多种类型，且要保住类型关系」？ | 泛型 `<T>` |
| ③ 泛型里要访问某个成员，编译器不让？ | 加约束 `<T extends {...}>` |
| ④ 需要「基于已有类型生成新类型」？ | 工具类型：`Partial` / `Pick` / `Record` |
| ⑤ 内置工具类型不够用？ | 自己写映射类型 `[K in keyof T]` |
| ⑥ 只想要某个字段的类型？ | 索引访问 `T['字段名']` |

**反向判断（什么时候**不**用）**：

| 症状 | 说明 | 该怎么办 |
|---|---|---|
| 泛型参数只出现一次 | `<T>(x: T) => T` 里 T 出现了 2 次才算必要 | 只出现一次 → 直接用具体类型或 `unknown` |
| 泛型参数永远是 `any` | `<T = any>` | 说明你在用 `any` 装样子，删掉泛型 |
| 索引签名键写成 `string` | 拼错键不报错 | 换成联合类型 |
| 工具类型用了三层嵌套 | 阅读成本爆炸 | 抽成具名 `type`，写注释 |

## 4. 判断表：`extends` 的四种身份（必须分清）

| 写法 | 身份 | 出现在 | 本课 |
|---|---|---|---|
| `class A extends B` | 类继承 | 类声明 | ✅ 37 集 |
| `interface A extends B` | 接口继承 | 接口声明 | ✅ 22 集 |
| `<T extends X>` | 类型参数约束 | 泛型列表 | ✅ 53-54 集 |
| `T extends U ? A : B` | 条件类型 | 类型别名内 | ❌ 未讲 |

> ⚠️ **③ 和 ④ 的唯一区别是后面跟不跟 `?`**。看到 `?` 就是条件类型，属于另一套机制。

## 2. 三个必跑的反直觉实验

### 实验 A：泛型编译后完全消失

```ts
// gen.ts
function identity<T>(value: T): T { return value }
```

```bash
npx tsc gen.ts
cat gen.js
```

**你会看到**：

```js
function identity(value) { return value }
```

**`<T>` 一个字都不剩**。这就是为什么 `new T()` 不可能实现。对照 C# 反编译一个 `Identity<T>`，`T` 完完整整躺在 metadata 里。

### 实验 B：`Readonly` 拦不住运行时

```ts
const u: Readonly<User> = { id: 1, name: 'a', age: 1 }
// u.name = 'b'                    // ❌ 编译期拦住
;(u as any).name = 'b'             // ✅ 运行时真的改了
console.log(u.name)                // 'b'
```

**结论**：`Readonly<T>` 是**编译器约束**，不是**运行时约束**。要真不可变得用 `Object.freeze`。

### 实验 C：`Record<string, T>` 让拼写错误静默通过

```ts
const m: Record<string, number> = {}
m.nmae = 1            // ✅ 不报错（键名随便写）
console.log(m.name)   // undefined，但类型写着 number 💀
```

对比 `Record<'name', number>`：

```ts
const m2: Record<'name', number> = { name: 0 }
// m2.nmae = 1        // ❌ 报错
```

**结论**：`Record` 的收益**完全取决于 K 有多窄**。`Record<string, T>` 约等于放弃检查。

==四：总结==

## 1. 一句话记住三段

> **① 交叉 `&` = 两份成员全都要（不是取交集）。**
> **② 泛型 `<T>` = 类型当参数；`extends` 是约束，不是继承。**
> **③ `keyof` 取键、`[K in ...]` 遍历键、`T[K]` 取值的类型 —— 这三件是 C# 完全没有的能力。**

## 2. ⭐⭐ 这一篇要背的

**背 5 条，其他都可以查表：**

1. **`A & B` 的成员是并集不是交集**；同名不同型 → `never`。
2. **`<T, K extends keyof T>(obj: T, key: K): T[K]`** —— 这一行含四种能力，当口诀背。
3. **`extends` 在泛型里 = C# 的 `where`**，但判定用**结构**不用**名义**。
4. **`Partial<T>` = `{ [K in keyof T]?: T[K] }`** —— 拆开看过一次，就再也不会觉得它神秘。
5. **`T['a' | 'b']` 得联合；`T[keyof T]` 得「所有值类型的并集」；`T[number]` 得数组元素类型。**

## 3. ⭐ 收敛时刻：这一篇把前面的哪几条线接到了同一个点

**四线合一，这是本篇最重要的收获：**

| 前面学过 | 在本篇的落点 |
|---|---|
| **43-48 类型兼容性（结构化）** | 泛型约束 `T extends { length: number }` 用的就是结构判定 → **不用实现接口也能过** |
| **57 数组是泛型接口** | `T[]` = `Array<T>`，`Array` 内部靠 `[n: number]: T` → 引出 63 集的索引签名 |
| **63 索引签名** | `string[][number]` 能取到 `string`，因为数组有 `[n: number]: T` → **63 和 68 是同一件事的两面** |
| **62 `Record<K,T>`** | `Record` = `[P in K]: T`，就是映射类型的特例 → **工具类型不是魔法，是普通语法** |

⭐ **最深的一条**：**「结构化类型」这个 43-48 集的概念，在本篇从「奇怪」变成了「好用」**。

C# 里你写 `where T : IHasLength`，调用方必须真的实现那个接口 —— 你得为了约束去改别人的类。
TS 里 `T extends { length: number }`，**任何有 length 的东西自动满足** —— 不用改、不用声明、不用注册。

> **同一件事，C# 里是「负担」，TS 里是「便利」。这是两套类型系统最本质的分歧。**

**第二条收敛**：**TS 的类型系统能「计算」，所以它能自我描述。**

```ts
type Partial<T> = { [K in keyof T]?: T[K] }   // 一个类型定义了另一个类型
```

C# 里类型不能这样互相定义（只能在 `class` 里手写）。这解释了一个现象：**为什么 TS 的库类型定义能那么精确** —— 它们不是手写的，是算出来的。

## 4. 静默失败清单（TS 版，本篇 7 条）

| # | 场景 | 症状 | 怎么防 |
|---|---|---|---|
| 1 | `Record<string, T>` | 键名拼错不报错，类型写着 T 实际 `undefined` | 用联合类型当键，别用 `string` |
| 2 | 索引签名 `[key: string]: any` | 吞掉所有拼写错误 | 值类型别写 `any`，尽量写联合 |
| 3 | `Readonly<T>` | 运行时能改（`as any` / JS 侧调用） | 真不可变用 `Object.freeze` |
| 4 | `Partial<T>` 传给需要完整 `T` 的字段 | 编译期过，运行时 `undefined` | 只在「更新入参」用，别当数据模型 |
| 5 | `Partial` / `Readonly` 是浅层 | 嵌套对象以为也变了 | 记住只削一层，深层要自己写递归 |
| 6 | 泛型推断出 `unknown` | 后面所有访问都报错，找不到源头 | 检查调用处是否传了 `null` / 空数组 |
| 7 | `A & B` 同名冲突 → `never` | 报错说「不能赋给 never」，看不懂 | 看到 `never` 先查 `&` 两侧有没有重名 |

> ⚠️ **注意 1-5 条的性质**：它们不是「TS 检查失败」，而是**「TS 的检查在这条路上覆盖不到」**。
> 这就是 TS--01 那句话的延伸：**TS 让你早犯错，但不保证覆盖全部错误**。
> **新增一条工程习惯**：每用一次「宽类型」（`string` 键、`any`、`Record<string, T>`），就问一句「**这层检查我是不是白丢了**」。
