## 1. 90 集：用类型声明文件复用类型（4'08"）

### 1.1 起点：类型到处复制

```tsx
// App.tsx
type Task = { id: number; name: string; done: boolean }

// TaskItem.tsx
type Task = { id: number; name: string; done: boolean }   // ← 又一份

// TaskList.tsx
type Task = { id: number; name: string; done: boolean }   // ← 又一份
```

**问题**：加一个字段要改三处，改漏了就出现**两个"同名但不同形状"的类型** —— 编译器会报一个你完全看不懂的错。

### 1.2 解法：抽到一个共享位置（三种，回扣 73 集）

| 方案 | 文件 | 好处 | 代价 |
|---|---|---|---|
| **A · `types.ts`** | `src/types.ts` + `export` | 显式、安全、可 tree-shake | 每个文件要 `import type` |
| **B · `types.d.ts`（全局）** | `src/types.d.ts`，**无 `export`** | 全项目免 import | ⚠️ 一个 `export` 都不能有 |
| **C · `declare global`** | `src/types.d.ts`，`export {}` + `declare global` | 免 import 且是模块 | 语法绕 |

### 1.3 ⭐ 课程走 B，我建议你走 A

**课程写法**（B）：

```ts
// src/types.d.ts —— 注意：一个 import/export 都没有
interface Task {
  id: number
  name: string
  done: boolean
}
```

```tsx
// 任何 .tsx 里直接用，不用 import
const tasks: Task[] = []
```

**为什么它能全局生效**：进阶篇01 §4 那条规则 —— **没有 `export` 的 `.d.ts` 是"全局脚本"**。

⚠️ **但 B 有一个隐形炸弹**：

```ts
// 某天你想加一个类型别名，顺手写了 export
export type TaskId = number
```

**这一行 `export` 会让整个文件的 `Task` 一起变成模块** —— 全项目瞬间报 `Cannot find name 'Task'`。

> ⭐ **这就是进阶篇01 静默失败 #2 的实战后果。** 课程里不会遇到这个问题，是因为它文件很短、从不加 `export`。**真实项目里这个坑每年都有人踩。**

### 1.4 我推荐的工程写法（A + `import type`）

```ts
// src/types.ts
export interface Task {
  id: number
  name: string
  done: boolean
}

export type Filter = 'all' | 'active' | 'done'
```

```tsx
// 用的时候
import type { Task, Filter } from './types'
```

⭐ **三个好处**：

| 好处 | 原因 |
|---|---|
| **F12 能跳转** | 显式 import，IDE 知道去哪 |
| **不污染全局** | 不会和库的类型撞名 |
| **`import type` 零运行时** | 编译后这行消失（`isolatedModules` 要求） |

⚠️ **`import type` vs `import`**：

```tsx
import type { Task } from './types'   // ✅ 明确"只引类型"，编译后被删
import { Task } from './types'        // ⚠️ 可能被当成"引值"，有些配置会报错
```

**规则**：**只当类型用，就写 `import type`。** 这是 `isolatedModules` 时代的硬规矩。

### 1.5 什么时候该抽、什么时候不该

| 该抽 | 不该抽 |
|---|---|
| 被 2 个以上文件用 | 只在一个组件内部用 |
| 是领域模型（`Task` / `User`） | 是组件内部的临时类型 |
| 会被 API 层复用 | 纯 UI 状态 |

⭐ **判据一句话**：**「名字有意义、会被反复提起」→ 抽；「只在某个组件里用一次」→ 就地写。**

## 2. 91 集：添加任务功能（16'51"）🔥🔥

### 2.1 核心概念：受控组件（Controlled Component）

**这是 91 集的全部内容，也是最容易理解错的一个概念。**

```tsx
const [text, setText] = useState<string>('')

<input
  value={text}                    // ← ① 显示什么，由 state 决定
  onChange={e => setText(e.target.value)}   // ← ② 改的时候，写回 state
/>
```

⭐ **一句话**：**输入框里显示什么，完全由 React 的 state 说了算 —— 用户改的不是 DOM，是 state。**

| | 受控 | 非受控 |
|---|---|---|
| 写法 | `value` + `onChange` | `defaultValue` 或 `ref` |
| 谁是数据源 | **React state** | **DOM 自己** |
| 取值 | 直接读 `text` | 要 `ref.current.value` |
| 校验 / 格式化 | ✅ 实时可控 | ❌ 难 |
| 课程用哪个 | ✅ **受控** | — |

⚠️ **只写 `value` 不写 `onChange` 会怎样**：

```tsx
<input value={text} />       // ← 只读输入框！打不进字
```

**控制台会警告**：

```
You provided a `value` prop to a form field without an `onChange` handler.
This will render a read-only field.
```

⭐ **这不是 bug，是设计**：**值由 state 决定，用户输入没有渠道改变 state，所以输入框"冻住"了。**

### 2.2 添加任务的完整逻辑

```tsx
function handleAdd() {
  if (!text.trim()) return                         // ① 空值拦截
  setTasks(prev => [
    ...prev,                                       // ② 不可变：造新数组
    { id: Date.now(), name: text.trim(), done: false },
  ])
  setText('')                                      // ③ 清空输入框
}
```

⭐ **三个动作，每一行都有讲究**：

| 行 | 为什么 |
|---|---|
| `if (!text.trim()) return` | 防止添加空白任务；`.trim()` 顺便处理"全是空格" |
| `[...prev, newTask]` | **不可变更新**（回扣 JS 187 集：`push` 改的是原数组，React 检测不到） |
| `setText('')` | **受控组件必须手动清空** —— 因为没有 DOM 自己管值，你不清它就永远是旧值 |

⚠️ **第 3 行最容易漏**：非受控组件里 `input.value = ''` 是"清 DOM"，受控组件里必须"清 state"。

### 2.3 `id` 怎么生成

| 写法 | 问题 |
|---|---|
| `Date.now()` | ⚠️ **同一毫秒内连续添加会重复**（快速点击/回车） |
| `tasks.length + 1` | ❌ 删除后会重复 |
| `crypto.randomUUID()` | ✅ 现代浏览器都支持，最稳 |
| 自增计数器（`useRef`） | ✅ 稳，但要额外维护 |

```tsx
// 课程用
{ id: Date.now(), … }

// 更稳
{ id: crypto.randomUUID(), … }      // ⚠️ 需要把 Task.id 改成 string
```

⭐ **如果 `id` 重复会发生什么**：`key` 冲突 → **React 渲染错乱**（控制台警告 `Encountered two children with the same key`）。**这是真实项目里的事故源。**

### 2.4 `useState<string>('')` 的泛型要不要写

```tsx
const [text, setText] = useState('')          // 推断为 string ✅ 够了
const [text, setText] = useState<string>('')  // 显式，也行
```

⭐ **初始值是 `''` 时能推断出 `string`，泛型可省。** 但写上也**不亏**，读起来更明确。

⚠️ **什么时候必须写**：初始值是 `null` / 空数组 / 空对象时。

```tsx
useState<Task[]>([])        // ✅ 必须
useState<Task | null>(null) // ✅ 必须
useState([])                // ❌ never[]
```

## 3. 92 集：添加任务优化（9'25"）

### 3.1 五个优化点（课程讲的 + 我补的）

| # | 优化 | 为什么 |
|---|---|---|
| 1 | **回车也能添加** | 输入完不用去点按钮 |
| 2 | **空值不添加** | 防脏数据 |
| 3 | **添加后清空 + 保持焦点** | 连续录入体验 |
| 4 | **抽成 `TaskInput` 组件** | 职责单一 |
| 5 | **类型收敛到 `types.ts`** | 回扣 90 集 |

### 3.2 回车提交：`onKeyDown` 的典型用法

```tsx
function handleKeyDown(e: React.KeyboardEvent<HTMLInputElement>) {
  if (e.key === 'Enter') {
    handleAdd()
  }
}
```

⚠️ **为什么用 `onKeyDown` 不用 `onKeyPress`**：`onKeyPress` **已废弃**（React 18+ 和浏览器都不推荐），**新代码一律 `onKeyDown`**。

### 3.3 更好的做法：用 `<form>` 包起来

```tsx
function handleSubmit(e: React.FormEvent<HTMLFormElement>) {
  e.preventDefault()          // ← 阻止页面刷新
  handleAdd()
}

return (
  <form onSubmit={handleSubmit}>
    <input value={text} onChange={e => setText(e.target.value)} />
    <button type="submit">添加</button>
  </form>
)
```

⭐ **`form` 的三个白拿好处**：

| 好处 | 说明 |
|---|---|
| **回车自动提交** | 不用写 `onKeyDown` |
| **手机键盘"前往"键** | 移动端体验好 |
| **语义正确** | 屏幕阅读器知道这是一个表单 |

⚠️ **别忘了 `e.preventDefault()`** —— 否则表单会**刷新整个页面**（默认行为），你的 state 全丢。

> **这就是进阶篇06 §1.4 讲 `FormEvent<HTMLFormElement>` 的实战用途。**

### 3.4 抽成 `TaskInput` 组件（类型怎么传）

```tsx
// src/TaskInput.tsx
import { useState } from 'react'

type Props = {
  onAdd: (name: string) => void
}

export function TaskInput({ onAdd }: Props) {
  const [text, setText] = useState('')

  function handleSubmit(e: React.FormEvent<HTMLFormElement>) {
    e.preventDefault()
    const name = text.trim()
    if (!name) return
    onAdd(name)
    setText('')
  }

  return (
    <form onSubmit={handleSubmit} style={{ marginBottom: 12 }}>
      <input
        value={text}
        onChange={e => setText(e.target.value)}
        placeholder="输入任务，回车添加"
      />
      <button type="submit">添加</button>
    </form>
  )
}
```

```tsx
// App.tsx 里
function handleAdd(name: string) {
  setTasks(prev => [...prev, { id: Date.now(), name, done: false }])
}

<TaskInput onAdd={handleAdd} />
```

⭐ **注意类型设计的两条原则**：

| 原则 | 体现 |
|---|---|
| **子组件不知道父组件的状态结构** | `onAdd` 只要 `name: string`，**不传 `Task`** |
| **父组件决定怎么造 `Task`** | `id` / `done` 都在父组件里填 |

> **这是"接口最小化"** —— 子组件要的越少，复用性越强。**C# 里就是"参数类型越窄越好"，同一个道理。**

**④ `src/App.tsx`**

```tsx
import { useState } from 'react'
import { TaskInput } from './TaskInput'
import { TaskItem } from './TaskItem'
import type { Task } from './types'

export default function App() {
  const [tasks, setTasks] = useState<Task[]>([
    { id: 1, name: '学 TS 声明文件', done: true },
    { id: 2, name: '学 React 类型', done: false },
  ])

  function handleAdd(name: string) {
    setTasks(prev => [...prev, { id: Date.now(), name, done: false }])
  }

  function handleToggle(id: number) {
    setTasks(prev =>
      prev.map(t => (t.id === id ? { ...t, done: !t.done } : t))
    )
  }

  const unfinished = tasks.filter(t => !t.done).length

  return (
    <div style={{ padding: 20, fontFamily: 'sans-serif' }}>
      <h2>任务列表（未完成 {unfinished}）</h2>
      <TaskInput onAdd={handleAdd} />
      {tasks.length > 0 ? (
        <ul style={{ padding: 0 }}>
          {tasks.map(task => (
            <TaskItem key={task.id} task={task} onToggle={handleToggle} />
          ))}
        </ul>
      ) : (
        <p>暂无任务</p>
      )}
    </div>
  )
}
```

## 2. 实验一：证明"只写 value 不写 onChange"会冻住

```tsx
function Bad() {
  const [text] = useState('abc')
  return <input value={text} />
}
```

**现象**：输入框显示 `abc`，**但你怎么打字都打不进去**。

**控制台警告**：

```
You provided a `value` prop to a form field without an `onChange` handler.
This will render a read-only field.
```

⭐ **这个实验值得亲手做一遍** —— 它让你彻底理解"受控"两个字的含义。

## 3. 实验二：`push` vs 展开运算符（不可变更新的必要性）

```tsx
// ❌ 错：改的是原数组
function handleAddBad(name: string) {
  tasks.push({ id: Date.now(), name, done: false })
  setTasks(tasks)          // ← 传的是同一个引用
}
```

**现象**：**界面不更新**（或偶发更新）。

⭐ **原因**：`setTasks(tasks)` 传的数组和原来是**同一个引用**，React 判断"没变"就跳过渲染。

```tsx
// ✅ 对：造一个新数组
function handleAddGood(name: string) {
  setTasks(prev => [...prev, { id: Date.now(), name, done: false }])
}
```

> **这条回扣 JS 187 集**：`b = a` 不是拷贝；**判据永远是 `===`**。React 的更新判断用的就是这个 `===`。

## 4. 实验三：`id` 重复导致 `key` 冲突

```tsx
// 快速连续添加两条（用 Date.now()）
setTasks(prev => [...prev, { id: Date.now(), name: 'a', done: false }])
setTasks(prev => [...prev, { id: Date.now(), name: 'b', done: false }])
```

**可能的结果**：两条记录 `id` 相同。

**控制台警告**：

```
Encountered two children with the same key, `1759...`.
Keys should be unique so that components maintain their identity across updates.
```

⭐ **症状不是报错，是"勾选一条，另一条也变了"** —— 因为 React 认为它们是同一个组件。

## 5. 实验四：`preventDefault` 忘写的后果

| 92 | **用 `<form onSubmit>` + `preventDefault` 白拿回车提交；空值拦截 + 不可变追加。** |

## 2. ⭐⭐ 本篇要背的（5 条）

1. **`import type`** —— 只引类型就写 `type`，编译后这行消失。
2. **受控组件必须成对**：`value` + `onChange`，缺一个就冻住。
3. **清空输入框要 `setText('')`**，不是 `input.value = ''`。
4. **追加用 `[...prev, new]`**，`push` 改的是原数组，React 检测不到。
5. **`<form onSubmit>` 里第一行永远是 `e.preventDefault()`**。

## 4. 静默失败清单（本篇 4 条）

| # | 陷阱 | 表现 | 怎么防 |
|---|---|---|---|
| 1 | 全局 `.d.ts` 里手滑加 `export` | 全项目 `Cannot find name 'Task'` | 用 `types.ts` + `import type` |
| 2 | 受控组件忘 `onChange` | **输入框打不进字**（有警告） | `value` 与 `onChange` 成对写 |
| 3 | 添加时用 `push` + 传原数组 | **界面不更新**（无报错） | `[...prev, new]` |
| 4 | `id: Date.now()` 快速添加 | 同毫秒重复 → **勾一条两条都变** | `crypto.randomUUID()` |

> ⚠️ **第 3 条是全篇最阴的**：没有报错、没有警告、值也确实进了数组 —— **就是界面不动**。
> **这是 JS 187 集「`b = a` 不是拷贝」在 React 里的直接后果**，也是「静默失败」这条暗线的最后一站。

## 5. C# 类比可用度（本篇新增）

| 概念                              | C# 对应                                   | 可用度 | 说明               |
| ------------------------------- | --------------------------------------- | --- | ---------------- |
| `types.ts` + `import type`      | 一个 `.cs` 文件里的 `public class` + `using`  | ⭐⭐⭐ | **几乎一样**         |
| 全局 `.d.ts`                      | 全局命名空间的类                                | ⭐   | 能用但危险            |

| `onAdd: (name: string) => void` | `Action<string>`                        | ⭐⭐⭐ | **完全对应**         |
| `[...prev, new]`                | `list.Append(x).ToList()`               | ⭐⭐⭐ | 都是"造新集合"         |
| `key`                           | WPF 的 `x:Name` / `ItemsControl` 的容器回收   | ⭐⭐  | 都是"认人"           |
| `<form onSubmit>`               | `asp:Button` 的 `OnClick` + `IsPostBack` | ⭐   | 神似，但 React 是 SPA |
| `e.preventDefault()`            | `e.Handled = true`（WPF 路由事件）            | ⭐⭐  | 都是"阻止默认行为"       |
