## 1. 84 集：事件与事件对象（9'30"）🔥🔥

### 1.1 先看清一件事：不写类型也能过

```tsx
function App() {
  return (
    <button onClick={(e) => console.log(e)}>
      点我
    </button>
  )
}
```

**把鼠标悬停在 `e` 上，你会看到完整的类型**：

```
e: React.MouseEvent<HTMLButtonElement, MouseEvent>
```

⭐ **为什么不用写？** 因为 `<button>` 的 `onClick` 属性**自带类型**（来自 `@types/react` 里 `DOMAttributes` 接口）。**你在 JSX 里内联写回调，TS 会"上下文推断"出来。**

> **一句话**：**内联写，白拿类型；提取出去，自己补。**

### 1.2 ⭐ 什么时候必须手写

```tsx
// ❌ 提取成独立函数 → 类型全丢，e 变 any
function handleClick(e) {           // TS7006: Parameter 'e' implicitly has an 'any' type
  console.log(e.currentTarget)
}
<button onClick={handleClick}>
```

**修法**：手写类型。

```tsx
function handleClick(e: React.MouseEvent<HTMLButtonElement>) {
  console.log(e.currentTarget.disabled)
}
```

⚠️ **注意 `strict` 模式下这**不是"可选优化"，**是必须**（`noImplicitAny` 会直接报错）。

### 1.3 🔴 最核心的一条：泛型参数是「元素类型」，不是「事件类型」

**这是 90% 的人搞反的地方。**

```tsx
React.MouseEvent<HTMLButtonElement>
//                       ↑
//            这里是「哪个元素上发生的」
```

| 你想要的 | 写法 | 结果 |
|---|---|---|
| 按钮的点击事件 | `React.MouseEvent<HTMLButtonElement>` | ✅ 能 `e.currentTarget.disabled` |
| 输入的变更事件 | `React.ChangeEvent<HTMLInputElement>` | ✅ 能 `e.target.value` |
| 表单提交 | `React.FormEvent<HTMLFormElement>` | ✅ 能 `e.currentTarget.reset()` |
| 键盘事件 | `React.KeyboardEvent<HTMLInputElement>` | ✅ 能 `e.key`（`e.key` 本来就有） |

⚠️ **写错的典型症状**：

```tsx
// 元素类型写错
e: React.MouseEvent<HTMLDivElement>
e.currentTarget.value        // ❌ Property 'value' does not exist on type 'HTMLDivElement'
```

**报错说的是"属性不存在"**，而不是"类型写错了" —— 所以**新手会去查 `value` 为什么不存在，而不是回头检查泛型参数**。

### 1.4 ⚠️ `e.target` 与 `e.currentTarget`：必须分清

```tsx
function onChange(e: React.ChangeEvent<HTMLInputElement>) {
  e.target.value          // ✅ 能用
  e.currentTarget.value   // ✅ 也能用
}
```

看起来一样，但**类型不同**：

| | 类型 | 含义 | 安全性 |
|---|---|---|---|
| `e.target` | **触发事件的最内层元素** | 你点的那一下真正落在谁身上 | ⚠️ 可能是子元素 |
| `e.currentTarget` | **绑定监听器的那个元素** | 你写 `onChange` 的那个元素 | ✅ 确定 |

**最容易出事的地方 —— 事件委托**：

```tsx
// 你绑在 <ul> 上，但用户点在 <li> 上
<ul onClick={(e) => {
  e.target                        // ← 是 <li>，不是 <ul>！
  e.currentTarget                 // ← 才是 <ul>
}}>
```

⭐ **你在 JS 阶段学的"事件委托"（173-175 集），在这里变成了一个类型问题**：

| | JS 阶段 | TS 阶段 |
|---|---|---|
| `e.target` | 就是个 DOM 元素 | `EventTarget`，**没有 `dataset` / `value`** |
| 想要具体属性 | 直接点 | 得**断言**或改用 `currentTarget` |

```tsx
// 事件委托里的正确写法
function onClick(e: React.MouseEvent<HTMLUListElement>) {
  const target = e.target as HTMLLIElement   // ← 必须断言
  console.log(target.dataset.id)
}
```

⚠️ **为什么 `e.target` 在 `MouseEvent<T>` 里是 `EventTarget`**：React 的类型定义里，`SyntheticEvent<T>` 把 `target` 写成了 `EventTarget`（因为理论上任何元素都能触发），而 `currentTarget` 才是 `EventTarget & T`。

⭐ **但 `ChangeEvent<T>` 是个例外** —— 它**重定义了 `target`**：

```ts
// @types/react 里（简化）
interface ChangeEvent<T = Element> extends SyntheticEvent<T> {
  target: EventTarget & T;      // ← 特地把 target 收紧成具体元素
}
```

**所以**：
- `ChangeEvent<HTMLInputElement>` → `e.target.value` ✅ **不用断言**
- `MouseEvent<HTMLButtonElement>` → `e.target.disabled` ❌ **要断言或用 `currentTarget`**

> ⭐ **记住这个不对称**：**表单事件能直接 `e.target.value`，鼠标事件不行。** 这是 React 类型定义里的历史设计。

### 1.5 常用事件类型速查

| JSX 属性 | 类型 |
|---|---|
| `onClick` | `React.MouseEvent<T>` |
| `onChange` | `React.ChangeEvent<T>` |
| `onSubmit` | `React.FormEvent<T>` |
| `onKeyDown` / `onKeyUp` | `React.KeyboardEvent<T>` |
| `onFocus` / `onBlur` | `React.FocusEvent<T>` |
| `onMouseEnter` / `onMouseLeave` | `React.MouseEvent<T>` |
| `onScroll` | `React.UIEvent<T>` |
| `onDragStart` | `React.DragEvent<T>` |

⭐ **命名规律**：`React.` + **原生事件名首字母大写** + `<元素类型>`。**记不住时按这个规律猜，八九不离十。**

## 2. 85 集：类组件的类型（1 组件类型，7'52"）

### 2.1 为什么还要学类组件

**2026 年了，类组件已经不用写新的了**。但：

| 理由 | 说明 |
|---|---|
| 存量项目 | 2019 年前的项目**全是类组件** |
| 面试 | 会问 `Component` vs `PureComponent` |
| 理解 hooks | `useState` 就是在"模拟类组件的 state" |
| 读老库源码 | 很多库还是 class |

> **定位**：**这一段是"能读懂老代码"，不是"要这样写新代码"。**

### 2.2 类组件的基本形状

```tsx
import React from 'react'

type Props = { name: string }
type State = { count: number }

class Hello extends React.Component<Props, State> {
  state: State = { count: 0 }

  render() {
    return (
      <h1>
        你好，{this.props.name}，点了 {this.state.count} 次
      </h1>
    )
  }
}
```

⭐ **`React.Component<P, S>`** 两个类型参数：

| 参数 | 是什么 | 可省吗 |
|---|---|---|
| `P` | props 类型 | 省略 = `{}` |
| `S` | state 类型 | 省略 = `{}`（**这时 `this.state` 是空对象，写任何属性都报错**） |

⚠️ **省略 `S` 的后果**：

```tsx
class Hello extends React.Component<Props> {   // ← 没给 State
  state = { count: 0 }                          // ❌ 报错
}
```

因为基类的 `state` 类型是 `Readonly<{}>`，你赋一个 `{count: number}` 上去不兼容。

### 2.3 `render()` 的返回类型

**不用手写**。`React.Component` 已经把 `render` 声明成返回 `ReactNode`，你重写时 TS 会自动检查。

⚠️ **但有一条例外**：如果 `render` 里 `return` 了**不是节点**的东西：

```tsx
render() {
  return { a: 1 }        // ❌ 报错
}
```

### 2.4 `Component` vs `PureComponent`

```tsx
class A extends React.Component<Props> {}       // 每次父组件渲染都跟着渲染
class B extends React.PureComponent<Props> {}   // props/state 浅比较，没变就跳过
```

| | `Component` | `PureComponent` |
|---|---|---|
| 更新判断 | 总是更新 | **浅比较** props + state |
| 对应 hooks | `useState` | `React.memo` + `useMemo` |
| 坑 | — | **嵌套对象变了但引用没变 → 不更新**（回扣 JS 187 集：`b = a` 不是拷贝） |

⭐ **`PureComponent` 的坑和你 JS 阶段学的一模一样**：

```ts
// JS 187 集：浅拷贝只保护第一层
const next = { ...state }
next.list.push(item)        // ← 数组还是同一个引用！
this.setState(next)         // PureComponent 认为"没变"，不渲染
```

> **这就是为什么 React 要求"不可变更新"** —— 不是风格问题，是**引用比较**机制决定的。

## 3. 86 集：类组件的属性（9'00"）

### 3.1 `props` 是只读的

```tsx
class Hello extends React.Component<Props> {
  render() {
    this.props.name = 'x'      // ❌ Cannot assign to 'name' because it is a read-only property.
  }
}
```

⭐ **`Readonly<P>` 被内建在 `Component` 定义里**：

```ts
// @types/react（简化）
class Component<P, S> {
  constructor(props: Readonly<P>);
  readonly props: Readonly<P>;
  state: Readonly<S>;
}
```

⚠️ **`state` 也是 `Readonly<S>`** —— 只能通过 `setState` 改，不能 `this.state.count++`。

### 3.2 构造函数写法（容易写错的模板）

```tsx
class Hello extends React.Component<Props, State> {
  constructor(props: Props) {      // ← 显式写 Props，不是 Readonly<Props>
    super(props)                    // ← 必须第一行
    this.state = { count: 0 }
  }
}
```

⚠️ **三个坑**：

| 坑 | 报错 |
|---|---|
| 忘了 `super(props)` | `'super' must be called before accessing 'this'` |
| `super()` 不传 props | 父类里 `this.props` 是 `undefined` |
| `constructor` 参数没写类型 | `TS7006`（`noImplicitAny`） |

⭐ **能不能不写构造函数？** 能。用**类字段**更简洁：

```tsx
class Hello extends React.Component<Props, State> {
  state: State = { count: 0 }        // ← 直接初始化，不用构造函数
}
```

### 3.3 `static defaultProps`（类组件还行）

```tsx
class Hello extends React.Component<Props> {
  static defaultProps = { name: '陌生人' }
  render() { return <h1>{this.props.name}</h1> }
}
```

⭐ **和函数组件不同：类组件的 `defaultProps` 在 React 19 里仍然支持。** 因为它走的是"类静态属性 + 基类合并"的机制，不受函数组件移除的影响。

⚠️ **但类型上有个坑**：

```tsx
type Props = { name?: string }       // ← 必须先声明成可选
class Hello extends React.Component<Props> {
  static defaultProps = { name: '陌生人' }
}
```

如果不写 `?`，`defaultProps` 会被认为"给必填字段兜底"，TS 会报 `defaultProps` 的类型不匹配。

### 3.4 `strictPropertyInitialization` 与类字段

**进阶篇04 §2.5 提过 `strict` 里的这一项**，在类组件里它是常客：

```tsx
class Hello extends React.Component<Props, State> {
  state: State          // ❌ Property 'state' has no initializer
}
```

**三种修法**：

```tsx
// ① 直接初始化
state: State = { count: 0 }

// ② 构造函数里赋值（TS 能识别）
constructor(props: Props) {
  super(props)
  this.state = { count: 0 }
}

// ③ 确定赋值断言（下策）
state!: State
```

⭐ **这就是 `!` 在类里的用法** —— 和 `document.getElementById('x')!` 是同一个道理。

## 1. 事件类型速查表

| JSX | 事件类型 | `e.target` 能用吗 | 推荐 |
|---|---|---|---|
| `onClick` | `React.MouseEvent<T>` | ⚠️ 是 `EventTarget` | 用 `e.currentTarget` |
| `onChange` | `React.ChangeEvent<T>` | ✅ 是 `EventTarget & T` | `e.target.value` |
| `onSubmit` | `React.FormEvent<T>` | ⚠️ 同上 | `e.preventDefault()` |
| `onKeyDown` | `React.KeyboardEvent<T>` | ⚠️ 同上 | `e.key` 本来就有 |
| `onFocus` | `React.FocusEvent<T>` | ⚠️ 同上 | — |
| `onScroll` | `React.UIEvent<T>` | ⚠️ 同上 | — |
| `onDragStart` | `React.DragEvent<T>` | ⚠️ 同上 | — |
| `onDrop` | `React.DragEvent<T>` | ⚠️ 同上 | — |

> ⭐ **`T` 写什么**：写**绑定事件的那个元素**的 `HTMLxxxElement`（`HTMLButtonElement` / `HTMLInputElement` / `HTMLFormElement` / `HTMLUListElement` / `HTMLDivElement`…）。

## 2. 类组件骨架模板（存下来直接用）

```tsx
import React from 'react'

type Props = { name?: string }
type State = { count: number }

class Hello extends React.Component<Props, State> {
  static defaultProps = { name: '陌生人' }

  state: State = { count: 0 }

  handleClick = () => {                     // ← 箭头函数属性，this 不用 bind
    this.setState({ count: this.state.count + 1 })
  }

  render() {
    return (
      <div>
        <h1>{this.props.name}：{this.state.count}</h1>
        <button onClick={this.handleClick}>+1</button>
      </div>
    )
  }
}

export default Hello
```

## 3. 函数组件 vs 类组件对照

| | 函数组件 | 类组件 |
|---|---|---|
| 类型写法 | `function X(props: P)` | `class X extends Component<P, S>` |
| props | 参数 | `this.props`（只读） |
| state | `useState<T>()` | `this.state` + `setState` |
| 默认值 | 默认参数 ✅ | `static defaultProps` ✅ |
| 事件 | `(e: React.MouseEvent<T>)` | 同左 |
| 现在推荐 | ✅ | ❌ 只维护存量 |

## 4. `e.target` vs `e.currentTarget` 默认对照

| 场景 | `target` | `currentTarget` |
|---|---|---|
| 按钮点击 | 可能是里面的 `<span>` | ✅ 一定是 `<button>` |
| 输入变化 | ✅ 一定是 `<input>`（`ChangeEvent` 特例） | ✅ 同上 |
| 列表委托 | 具体被点的 `<li>` | ✅ 绑定的 `<ul>` |
| 表单提交 | 表单 | ✅ 表单 |

## 2. 实验二：泛型参数写错的报错长什么样

```tsx
type Props = { onAdd: (name: string) => void }

function Input({ onAdd }: Props) {
```

## 3. 实验三：`e.target` vs `e.currentTarget` 在委托里的差别

```tsx
type Task = { id: number; name: string }

function TaskList({ tasks }: { tasks: Task[] }) {
  function handleClick(e: React.MouseEvent<HTMLUListElement>) {
    // ❌ 直接 e.target.id —— EventTarget 上没有 id
    // console.log(e.target.id)

    const id = Number((e.target as HTMLLIElement).dataset.id)
    console.log('被点的任务 id =', id)

    console.log('绑定事件的 ul =', e.currentTarget.tagName)   // UL
  }

  return (
    <ul onClick={handleClick}>
      {tasks.map(t => (
        <li key={t.id} data-id={t.id}>{t.name}</li>
      ))}
    </ul>
  )
}
```

⭐ **三个知识点在一段代码里**：
1. `MouseEvent<HTMLUListElement>` → `e.currentTarget` 是 `HTMLUListElement`
2. `e.target` 是 `EventTarget`，**要断言才能拿 `dataset`**
3. `dataset.id` 的类型是 `string | undefined` → `Number()` 转换

> **这正好是你 JS 阶段 173-175 集"事件委托"的 TS 版本** —— 当时你会写，但不知道"为什么 `e.target` 不能直接点属性"。**现在编译器替你解释了。**

## 4. 实验四：类组件完整跑一遍

```tsx
// ClassCounter.tsx
import React from 'react'

type Props = { step?: number }
type State = { count: number }

class ClassCounter extends React.Component<Props, State> {
  static defaultProps = { step: 1 }

  state: State = { count: 0 }

  handleAdd = () => {
    this.setState(prev => ({ count: prev.count + (this.props.step as number) }))
  }

  render() {
    return (
      <div>
        <p>count = {this.state.count}</p>
        <button onClick={this.handleAdd}>+{this.props.step}</button>
      </div>
    )
  }
}

export default ClassCounter
```

⚠️ **三个易错点**：

| 点 | 说明 |
|---|---|
| `handleAdd = () => {}` | **类字段箭头函数** → `this` 自动绑定，不用 `bind(this)` |
| `setState(prev => …)` | 用函数式更新，**避免连续点击时读到旧 state** |
| `this.props.step as number` | `step?` 是可选 + `defaultProps` 兜底，TS 仍认为可能 `undefined` |

⭐ **最后一条是类组件的一个小痛点**：`defaultProps` 在**类型层面不会**帮你把 `step?: number` 变成 `number`。**函数组件的默认参数才会。**

## 5. 实验五：`props` 只读的验证

```tsx
class X extends React.Component<{ name: string }> {
  render() {
    this.props.name = 'y'
    return <div>{this.props.name}</div>
  }
}
```

**预期报错**：

```
Cannot assign to 'name' because it is a read-only property.
```

⭐ **这条报错是"设计意图"的体现** —— **props 从父组件来，子组件无权改。**

==四：总结==

## 1. 一句话记住三集

| 集 | 一句话 |
|---|---|
| 84 | **`React.MouseEvent<HTMLButtonElement>` —— 尖括号里写"哪个元素"，不是"什么事件"。** |
| 85 | **`Component<P, S>` 两个参数：props 和 state，省了 `S` 就存不了状态。** |
| 86 | **`props` 是只读的，`state` 只能靠 `setState` 改，构造函数能省就省。** |

## 2. ⭐⭐ 本篇要背的（5 条）

1. **内联回调自动推断，提取出去必须手写类型**（`noImplicitAny` 会逼你）。
2. **泛型参数 = 事件发生的元素类型**，写错时报错指向**属性不存在**，不指向类型。
3. **`e.target` vs `e.currentTarget`**：前者是 `EventTarget`（要断言），后者是 `EventTarget & T`。
4. **`ChangeEvent<T>` 是唯一可以直接 `e.target.value` 的**（它重定义了 `target`）。
5. **`Component<P, S>` 的 `S` 不能省**，省了 `state` 就废了。

## 3. ⭐ 收敛时刻：84 集把"事件"这条线彻底接上

**你在 JS 200 集里学了三层事件知识，今天全部汇到一个类型上**：

| JS 阶段（77-150 Web APIs） | TS 阶段（84 集） |
|---|---|
| `addEventListener('click', fn)` | `onClick={fn}` |
| `e.target` 是"真正被点的元素" | `e.target: EventTarget`（要断言） |
| `e.currentTarget` 是"绑定的元素" | `e.currentTarget: EventTarget & T` ✅ |
| 事件委托 | 泛型写到**容器**上（`HTMLUListElement`） |
| `preventDefault()` | `FormEvent<HTMLFormElement>` |

> ⭐ **一句话收口**：
> **你以前知道"target 和 currentTarget 不一样"，但不知道为什么；现在编译器用 `Property 'value' does not exist` 告诉你 —— 因为 `EventTarget` 根本不是元素。**

**再收一层**（回扣 187 集深拷贝 + 85 集 `PureComponent`）：

| JS 187 集 | React 的后果 |
|---|---|
| `b = a` 不是拷贝 | `PureComponent` 认为"引用没变 = 没变"，**不重渲染** |
| `{...a}` 只保护第一层 | 深层改了，`PureComponent` 检测不到 |
| 判据是 `===` | React 的浅比较就是 `===` 逐个字段 |

⭐ **这不是巧合**：**React 的更新机制建立在 JS 的引用语义上**，你在 JS 阶段学的那条"不是拷贝"，在这里变成了**"为什么必须不可变更新"的根源**。

## 4. 静默失败清单（本篇 4 条）

| # | 陷阱 | 表现 | 怎么防 |
|---|---|---|---|
| 1 | 提取回调忘写类型 | `TS7006`（strict 下）／非 strict 下 **静默 `any`** | 提取就写类型 |
| 2 | 泛型参数写错元素 | 报"属性不存在"，**让你以为是 DOM API 记错了** | 排查先回头看泛型 |
| 3 | `e.target` 直接用 | 报错或**运行时 `undefined`** | 用 `currentTarget` 或断言 |
| 4 | 类组件里 `this` 没绑 | **运行时报 `Cannot read property of undefined`** | 用类字段箭头函数 `handle = () => {}` |

> ⚠️ **第 4 条是 JS 192-194 集"`this` 看调用方式"的直接后果** —— `onClick={this.handle}` 把方法**脱开对象**传出去，`this` 就丢了。**这是类组件时代最大的坑，也是 hooks 出现的原因之一。**
