==一：概念==

## 1. 72 集：第三方库的类型声明（14'58"）🔥🔥

这一集是第 8 章最长的，因为它是**日常开发里最高频的动作**：装一个库，然后让 TS 认识它。

### 1.1 两条路，只有两条

| 路                  | 谁维护                 | 长什么样                                            | 例子                                                |
| ------------------ | ------------------- | ----------------------------------------------- | ------------------------------------------------- |
| **A · 包自带**        | 库作者                 | 包里有 `.d.ts`，`package.json` 里 `types` 字段指向它      | `axios` / `react` / `vue` / `zod`                 |
| **B · `@types/*`** | 社区（DefinitelyTyped） | 单独发布一个 `@types/xxx` 包，装在 `node_modules/@types/` | `@types/jquery` / `@types/lodash` / `@types/node` |

⭐ **判断一个库属于哪条路**，一行命令：

```bash
npm view jquery types          # 空 → 走 @types
npm view axios types           # "index.d.ts" → 自带
```

或者直接看 `node_modules/<pkg>/package.json` 里有没有 `types` / `typings` 字段。

### 1.2 ⭐ TS 的查找顺序（必须背下来）

```ts
import $ from 'jquery'
```

编译器按这个顺序找类型：

| 步骤 | 找什么 | 找到就用 |
|---|---|---|
| 1 | `node_modules/jquery/package.json` 的 `types` 字段 | ✅ 停止 |
| 2 | `node_modules/jquery/index.d.ts` | ✅ 停止 |
| 3 | `node_modules/@types/jquery/` 目录 | ✅ 停止 |
| 4 | 都没有 | ❌ 报 `TS7016`（strict 下）/ 静默当 `any`（非 strict） |

⚠️ **关键点**：**`@types/jquery` 不需要你在代码里 `import` 任何东西**。只要它在 `node_modules/@types/` 下，TS **自动**把它纳入全局。这是"约定优于配置"。

> **C# 对照**：`@types/*` ≈ 社区给一个只有 `.dll` 没有 XML 文档的库补的**外部 XML 注释 + 扩展方法声明**。区别是 C# 的元数据你不能补，TS 的类型可以**完全从外部补写** —— 因为类型本来就不在 `.js` 里。

### 1.3 为什么装 `-D`（devDependencies）

```bash
npm i -D @types/jquery
```

| 疑惑 | 答案 |
|---|---|
| 类型不是运行时需要吗？ | ❌ **不需要**。`.d.ts` **零产物**（进阶篇01 实验一已证） |
| 那生产环境缺了会怎样？ | 什么都不发生。**打包后的 JS 里没有类型** |
| 为什么还留在依赖里？ | 别人 clone 你的项目要 `build`，`build` 要 `tsc`，**`tsc` 要类型** → 所以没装就编译不过 |

⭐ **一句话**：**`@types/*` 是"编译期依赖"，不是"运行期依赖"。** 这就是 `-D` 的全部理由。

### 1.4 ⚠️ 版本对齐坑（踩过的人都疼）

```
react@18.2.0
@types/react@17.0.68      ← 版本错位
```

后果不是"报错"，而是**报一堆你根本没写的错**：属性不存在、事件类型不匹配、组件类型不兼容。

**规则**：`@types/xxx` 的**大版本要跟被描述的东西对齐**。

```bash
npm i -D @types/react@18     # 跟 react@18 对齐
```

⚠️ **反直觉点**：有些库的 `@types` 版本号**故意**跟原库不同（比如 `@types/node` 跟 Node 版本走）。遇到冲突先看 `npm view @types/xxx versions`。

### 1.5 实在没有类型：`declare module 'xxx'`（裸声明）

```ts
// shims.d.ts
declare module 'jquery'
```

**实测结果**：`tsc --noEmit --strict use.ts shims.d.ts` → **exit 0，一行错都没有**。

⭐ **为什么？** 裸声明等于告诉 TS：「这个模块存在，里面**所有东西都是 `any`**」。**检查彻底关掉**。

> ⚠️ **这行代码是"止痛药"不是"解药"**：它让你编译通过，但丢掉了这个库的**全部**类型保护。
> **工程上只在前两条路都走不通时用，并且要在 `.d.ts` 里注释原因。**

### 1.6 ⚠️ 更精细的补救：给某个子路径单独声明

```ts
// 只给样式文件声明（最常见的真实用法）
declare module '*.css'
declare module '*.svg' {
  const content: string
  export default content
}
```

⭐ 这两行几乎是**每个 React + TS 项目的标配** —— 因为 `import './App.css'` 在 TS 看来是"引用了一个 JS 模块"。

## 2. 73 集：项目内共享类型（5'20"）

### 2.1 场景：同一个 `User`，五个文件都要用

```ts
// userList.ts
interface User { id: number; name: string }

// userDetail.ts
interface User { id: number; name: string }     // ← 复制粘贴

// userForm.ts
interface User { id: number; name: string }     // ← 又一份
```

改一个字段要改五处 —— 这是**所有语言的共同问题**，TS 给了三种解法。

### 2.2 三种做法（重点在对比）

| 做法                       | 文件                         | 用法                                    | 优点                      | 缺点                                |
| ------------------------ | -------------------------- | ------------------------------------- | ----------------------- | --------------------------------- |
| **A · `types.ts` 导出**    | `types.ts`                 | `import type { User } from './types'` | 显式、无污染、能享受 tree-shaking | **每个文件都要 import**                 |
| **B · 全局 `.d.ts`**       | `types.d.ts`（**无 export**） | 直接用 `User`，不用 import                  | 零 import，最省事            | **污染全局命名空间**；一旦有人加 `export` 就集体失效 |
| **C · `declare global`** | `types.d.ts`（**有 export**） | 直接用 `User`                            | 既是模块又能全局                | 语法最绕，新手常写错                        |

### 2.3 ⭐ 做法 C 的正确写法（最容易写错）

```ts
// types.d.ts
export {}                    // ← 这一行必须有！让文件变成模块

declare global {             // ← 在这个块里的东西才进全局
  interface User {
    id: number
    name: string
  }
}
```

⚠️ **两个必须知道的点**：

1. **`declare global` 只能在"模块"里用**。所以上面那行 `export {}` 不是可有可无的装饰 —— **删掉它，`declare global` 直接报错**（`TS2669: Augmentations for the global scope can only be directly nested in external modules or ambient module declarations.`）。
2. **`declare global` 里不能写 `type` 以外的"值"**。想声明全局变量要用 `var`：

```ts
declare global {
  interface Window { __APP_CONFIG__: { api: string } }   // ✅
  var __VERSION__: string                                 // ✅ 用 var 不用 let/const
}
```

### 2.4 那到底该用哪个

| 场景 | 选择 | 理由 |
|---|---|---|
| 业务项目（90% 情况） | **A · `types.ts`** | 显式依赖最安全，改的时候一搜就找到 |
| 需要给 `Window` 加属性 | **C · `declare global`** | 必须全局 |
| 全局常量 / 全局类型（如 `Task` 到处用） | **B 或 C** | 看团队习惯；**别混用** |
| 库 / 组件库对外发布 | **A** | 全局是"污染"，库不能污染用户 |

> ⭐ **课程用 B（全局 `.d.ts`），理由是"少写 import"。**
> **我的建议：业务项目用 A，只在真的要改全局对象时用 C。** 原因：全局声明**没有引用关系** —— 你在 `UserList.tsx` 里看到 `User`，F12 跳不过去，只能靠搜。

### 2.5 C# 对照

| TS | C# | 说明 |
|---|---|---|
| `types.ts` + `export` + `import` | 一个 `.cs` 文件里的 `public class` + `using` | ⭐⭐ 几乎一样 |
| 全局 `.d.ts` | 无命名空间的 `public class`（全局命名空间） | ⭐ 能用但没人这么干 |
| `declare global` | `global using`（C# 10） | ⭐⭐ 思路像：都是"让某些东西自动可见" |
| 类型只在编译期存在 | 类型在运行时也在 | ❌ 本质差异 |

## 3. 74 集：为已有 JS 文件提供类型声明（概述，12'33"）

### 3.1 病：老项目迁移

```
一个 5 年前的项目：
  utils.js        2000 行，纯 JS
  api.js          800 行
  main.js         300 行
```

想上 TS，但**不可能一天重写完**。TS 给了**三条并行路线**：

| 路线               | 做法                                           | 侵入性             | 适合         |
| ---------------- | -------------------------------------------- | --------------- | ---------- |
| **① 同名 `.d.ts`** | `utils.js` 旁边放 `utils.d.ts`                  | 🟢 零侵入（JS 一行不改） | 稳定、不想动的老代码 |
| **② 集中声明**       | 一个 `shims.d.ts` 里 `declare module './utils'` | 🟢 零侵入          | 零散的第三方/内部库 |
| **③ JSDoc 注释**   | 在 JS 里写 `/** @param {number} a */`           | 🟡 要改 JS（只加注释）  | 还在活跃开发的文件  |

### 3.2 路线 ①：同名 `.d.ts`

```
src/
├── utils.js        ← 不动
└── utils.d.ts      ← 新加，描述 utils.js 的导出
```

```ts
// utils.d.ts
export function formatDate(d: Date): string
export const VERSION: string
```

⚠️ **必须同目录、同名（只换扩展名）**。TS 会自动配对 —— 这就是 TS 版的"partial class"。

⭐ **注意与进阶篇01 的坑区别**：

| 情况 | 结果 |
|---|---|
| `utils.ts` + `utils.d.ts` | ❌ 冲突，`.d.ts` 被忽略 |
| `utils.js` + `utils.d.ts` | ✅ **这是正确姿势**，TS 用 `.d.ts` 描述 `.js` |

**一字之差**，前者是重复定义，后者是"给没有类型的东西补类型"。

### 3.3 路线 ②：集中 `declare module`

```ts
// shims.d.ts
declare module './legacy/utils' {
  export function formatDate(d: Date): string
}

declare module 'some-old-lib' {
  const lib: {
    init(opts: { key: string }): void
  }
  export default lib
}
```

⚠️ **`declare module './legacy/utils'` 里的路径必须跟 import 路径完全一致**（包括扩展名省略方式）。写错了不报错，只是不生效。

### 3.4 路线 ③：JSDoc —— 你其实早就学过

**这是本篇和 JS 阶段的接口**。你在 JS 200 集里学过 JSDoc：

```js
/**
 * 计算两数之和
 * @param {number} a 第一个数
 * @param {number} b 第二个数
 * @returns {number}
 */
export function add(a, b) {
  return a + b
}
```

**打开这两个开关**（`tsconfig.json`）：

```json
{
  "compilerOptions": {
    "allowJs": true,
    "checkJs": true
  }
}
```

**然后 TS 就会真的检查这个 JS 文件**（实测）：

```ts
// main.ts
import { add } from "./calc"
const n = add("x", 2)
```

```
main.ts(2,15): error TS2345: Argument of type 'string' is not assignable to parameter of type 'number'.
```

⭐ **这是本组最震撼的一个实验**：**JS 文件一个字没改语法，只是补了 JSDoc 注释，就获得了完整的类型检查。**

### 3.5 三条路线怎么选（工程判断表）

| 你的处境          | 选                                 |
| ------------- | --------------------------------- |
| 库是老代码，很稳定，不想碰 | ① 同名 `.d.ts`                      |
| 第三方库没类型，也不想改它 | ② `declare module`                |
| 文件还在频繁改，渐进迁移  | ③ JSDoc（边改边补）                     |
| 要打包发布给别人用     | ①（`.d.ts` 是标准做法）                  |
| 只是想先让它编译过     | 裸 `declare module 'xxx'`（⚠️ 最后手段） |

> ⭐ **课程的顺序是 ① → ②，74 集只提 JSDoc 一句带过。**
> **但对你来说 ③ 最重要** —— 你 JS 阶段专门做过 JSDoc 速查表，那是这条路的入场券。

==二：格式==

## 1. TS 查找类型声明的完整顺序（速查）

```
import x from 'pkg'
    │
    ├─ 1. node_modules/pkg/package.json → "types" / "typings"
    ├─ 2. node_modules/pkg/index.d.ts
    ├─ 3. node_modules/@types/pkg/
    ├─ 4. tsconfig "paths" 别名映射
    └─ 5. 都没有 → TS7016（strict）/ 隐式 any
```

## 2. `typeRoots` / `types` 两个冷门但重要的字段

```json
{
  "compilerOptions": {
    "typeRoots": ["./node_modules/@types", "./src/types"],
    "types": ["node", "jest"]
  }
}
```

| 字段 | 作用 | 默认 |
|---|---|---|
| `typeRoots` | **去哪里找**类型包（只影响"自动加载的全局类型包"） | `["node_modules/@types"]` |
| `types` | **只加载哪几个**（白名单） | 全部 |

⚠️ **`types: []` 是个常用技巧** —— 关掉所有自动加载的全局类型包，**避免 `@types/node` 的全局 `setTimeout` 覆盖浏览器的 `setTimeout`** 这类冲突。

## 3. 三种共享类型方案对照

|                | A `types.ts` | B 全局 `.d.ts` | C `declare global` |
| -------------- | ------------ | ------------ | ------------------ |
| 文件内需要 `export` | ✅            | ❌ 一个都不能有     | ✅ 必须有 `export {}`  |
| 使用时要 `import`  | ✅            | ❌            | ❌                  |
| 会不会污染全局        | ❌            | ✅ 会          | ✅ 会（但可控）           |
| F12 能跳转        | ✅            | ⚠️ 勉强        | ⚠️ 勉强              |
| 适合做库           | ✅            | ❌            | ❌                  |
| 课程推荐           | —            | ✅            | —                  |
| **我推荐**        | ✅ 业务首选       | 团队约定         | 改全局对象时             |

## 4. 三条补声明路线对照

| | ① 同名 `.d.ts` | ② `declare module` | ③ JSDoc |
|---|---|---|---|
| 要改 JS 吗 | ❌ | ❌ | ✅（只加注释） |
| 需要 `allowJs` | ❌ | ❌ | ✅ **必须** |
| 需要 `checkJs` | ❌ | ❌ | ✅ 想查错就要 |
| 类型写在哪 | `.d.ts` | `.d.ts` | **JS 里面** |
| 适合 | 稳定老代码 | 第三方 | 活跃文件 |

## 5. 命令对照

| 目的 | 命令 |
|---|---|
| 查包有没有自带类型 | `npm view <pkg> types` |
| 装社区类型 | `npm i -D @types/<pkg>` |
| 查 @types 有哪些版本 | `npm view @types/<pkg> versions` |
| 看当前项目加载了哪些声明 | `tsc --explainFiles` |
| 看最终生效配置 | `tsc --showConfig` |

## 1. 实验一：一个没有类型的库会报什么（TS7016 原文）

准备一个"有 JS 没类型"的假包：

```bash
mkdir -p node_modules/jquery/dist
echo '{"name":"jquery","version":"3.7.0","main":"dist/jquery.js"}' > node_modules/jquery/package.json
echo 'export default function $(){}' > node_modules/jquery/dist/jquery.js
```

```ts
// use.ts
import $ from "jquery"
$(function () {
  console.log("ready")
})
```

```bash
tsc --noEmit --strict use.ts
```

**实测输出（逐字）**：

```
use.ts(1,15): error TS7016: Could not find a declaration file for module 'jquery'.
  'D:/.../node_modules/jquery/dist/jquery.js' implicitly has an 'any' type.
  Try `npm i --save-dev @types/jquery` if it exists or add a new declaration
  (.d.ts) file containing `declare module 'jquery';`
```

⭐ **注意最后两行**：TS **自己把两条出路都告诉你了** —— 这正是 72 集（`@types`）和 74/75 集（写 `.d.ts`）的内容。
**读得懂这条报错，这一章你就过关了。**

## 2. 实验二：裸声明 `declare module` 有多"止痛"

```ts
// shims.d.ts
declare module 'jquery'
```

```bash
tsc --noEmit --strict use.ts shims.d.ts
```

**实测输出**：**无任何输出，exit 0。**

⭐ **一行代码，所有错误消失** —— 但你也从此失去了 jQuery 的**全部**类型提示。`$(...)` 是 `any`，写错了也不会报。

> ⚠️ **这就是"止痛药"的含义**：症状（报错）没了，病（没有类型）还在。

## 3. 实验三：JSDoc 让纯 JS 拥有类型检查（本组王牌）

```js
// calc.js —— 注意：扩展名是 .js，语法也是纯 JS
/**
 * 计算两数之和
 * @param {number} a 第一个数
 * @param {number} b 第二个数
 * @returns {number}
 */
export function add(a, b) {
  return a + b
}
```

```ts
// main.ts
import { add } from "./calc"
const n = add("x", 2)
console.log(n)
```

```bash
tsc --noEmit --allowJs --checkJs --strict main.ts
```

**实测输出**：

```
main.ts(2,15): error TS2345: Argument of type 'string' is not assignable to parameter of type 'number'.
```

⭐ **`calc.js` 里一个类型注解都没有**（`@param {number}` 是注释），但 TS 精确地拦住了 `add("x", 2)`。

**把 `--checkJs` 去掉再跑一次**：错误消失，`n` 变成 `number`（仍能推断，但不检查 JS 内部）。

> ⭐ **这就是你 JS 阶段那份 JSDoc 速查表的兑现时刻**：当时写的 `@param` / `@returns`，今天变成了**真正的类型**。

## 4. 实验四：`declare global` 的正确与错误写法（73 集）

**❌ 错误写法**（想在模块里用全局块，但没加 `export {}`）：

```ts
// types.d.ts
declare global {
  interface G { id: number }
}
```

```
error TS2669: Augmentations for the global scope can only be directly nested
in external modules or ambient module declarations.
```

**✅ 正确写法**：

```ts
// types.d.ts
export {}
declare global {
  interface G { id: number }
}
```

```ts
// use.ts
const x: G = { id: 1 }        // ✅ 不用 import
```

```bash
tsc --noEmit use.ts types.d.ts
```

**实测**：exit 0。

⚠️ **注意这里的反直觉**：`export {}` 让文件变成模块（本来会让全局失效），**但 `declare global` 又把它"送回"全局**。这是 TS 里唯一一个「既是模块又能全局」的口子。

## 5. 实验五（选做）：`types: []` 避免全局类型打架

```json
// tsconfig.json
{ "compilerOptions": { "types": [] } }
```

**什么时候需要**：项目里同时装了 `@types/node`，但你是**浏览器项目** —— `@types/node` 的 `setTimeout` 返回 `NodeJS.Timeout`，跟浏览器的 `number` 打架，`clearTimeout(timer)` 就报错。

```ts
// 症状
const timer = setTimeout(() => {}, 1000)   // 类型是 NodeJS.Timeout
clearTimeout(timer)                         // 有时报错
```

⭐ **`"types": []` 一行解决**。这是**实战里出现频率很高**的一条。

   再跑一次，然后故意写 `$(123)` 看会不会报错。
3. 给 `calc.js` 加一个 `@deprecated` 标签（`@deprecated 请用 add2`），在 `main.ts` 里调用 `add`，看 VS Code 有没有删除线。
4. 建 `types.d.ts`，先写不带 `export` 的 `interface User`，在 `.ts` 里直接用；然后加 `export`，看错误变化。
5. 用 `declare global` 修好上一步，确认又能直接用了。

==四：总结==

## 1. 一句话记住三个

| 集 | 一句话 |
|---|---|
| 72 | **有 `types` 字段就用包的，没有就装 `@types/xxx`，都没有就 `declare module` 止疼。** |
| 73 | **`export` 决定生死：想全局就一个都别加，想两者兼得就 `declare global`。** |
| 74 | **老 JS 补类型有三条路：同名 `.d.ts` / `declare module` / JSDoc + `checkJs`。** |

## 2. ⭐⭐ 本篇要背的（5 条）

1. **查找顺序**：`pkg/package.json#types` → `pkg/index.d.ts` → `@types/pkg` → 报 `TS7016`。
2. **`@types/*` 是编译期依赖**，所以 `-D`。它零运行时体积。
3. **`@types` 大版本必须跟原库对齐**，否则报一堆你没写的错。
4. **`declare module 'xxx'`（裸） = 把整个模块变成 `any`** —— 止疼不止病。
5. **JSDoc + `allowJs` + `checkJs` = 纯 JS 也能被类型检查**（接你 JS 阶段的 JSDoc）。

## 3. ⭐ 收敛时刻：72-74 三集其实是"同一个动作"的三种变体

表面上三集讲三件事，其实是**同一句话的三个主语**：

| 集 | 主语 | 动作 | 谁写 `.d.ts` |
|---|---|---|---|
| 72 | **别人**（npm 包） | 用现成的 | 库作者 / DefinitelyTyped |
| 73 | **我和同事** | 共享一份 | 我 |
| 74 | **过去的我**（老 JS 代码） | 事后补上 | 现在的我 |

> ⭐ **一句话收口**：**类型声明文件的本质，是"给一段不属于你的实现配名片" —— 只不过 72 集名片是别人印的，73 集是自己人共用的，74 集是给老代码补印的。**

**再往回收**（接进阶篇01）：

| 进阶篇01 学的 | 本篇用它干的事 |
|---|---|
| `.d.ts` 零产物 | 所以 `@types` 能装 `-D` |
| `.d.ts` 只有签名 | 所以能给 `.js` 补类型 |
| `export` 决定全局/模块 | 所以有 A/B/C 三种共享方案 |
| `lib` 决定"世界有什么" | 和 `typeRoots` 是同一个思想：**控制类型从哪里来** |

## 4. 静默失败清单（本篇 5 条）

| # | 陷阱 | 表现 | 怎么防 |
|---|---|---|---|
| 1 | `@types` 版本错位 | 报一堆**你没写过**的错 | 对齐大版本 |
| 2 | `declare module 'xxx'` 裸声明 | 编译通过，**类型全丢**，运行时才炸 | 只当临时措施，加注释说明 |
| 3 | `declare module './utils'` 路径写错 | **不报错**，只是不生效 | 用同目录同名 `.d.ts`（路线①）更稳 |
| 4 | 全局 `.d.ts` 里手滑加了 `export` | 全局声明**集体失效**，报 `TS2304` | 全局文件里禁止出现 `import`/`export` |
| 5 | 没开 `checkJs` 就以为 JS 被检查了 | JS 里写错**不报错** | 想要检查必须 `allowJs` + `checkJs` 同时开 |

> ⚠️ **第 1 条最阴**：它不是"没类型"，是"**错的类型**"。没类型你会警惕；错的类型你会**信任它然后写错代码**。

## 5. C# 类比可用度（本篇新增）

| 概念 | C# 对应 | 可用度 | 说明 |
|---|---|---|---|
| 包自带 `types` | `.dll` 自带元数据 | ⭐⭐⭐ | 一样：引用即用 |
| `@types/xxx` | 外部 XML 文档 + 手工补的元数据 | ⭐⭐ | C# 不能给别人的 `.dll` 补类型，TS 可以 |
| `npm i -D @types` | 只装 `Ref` 包 | ⭐⭐ | 都是编译期 |
| 同名 `.d.ts` 描述 `.js` | `partial class`（跨文件补定义） | ⭐⭐ | 思路像：都给已有东西"贴"上定义 |
| `declare module 'xxx'` | `DllImport` 声明 | ⭐ | 都是"我保证存在" |
| 全局 `.d.ts` | 全局命名空间的 `public class` | ⭐ | 能用但不推荐 |
| `declare global` | `global using` | ⭐⭐ | 都是"自动可见" |
| JSDoc 驱动检查 | `/// <summary>` XML 注释 | ⭐⭐ | **但 C# 的注释不参与类型检查，TS 的参与** —— 这是关键差异 |

⭐ **统计：8 项里 1 项 ⭐⭐⭐、5 项 ⭐⭐、2 项 ⭐。**
