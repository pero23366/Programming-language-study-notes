## 4. ⚠️ React 零基础补丁（必看，否则 78 集开始掉线）

你学过 JS（DOM 操作、事件、模块化），也学过 C#（WPF / 可能听过 Blazor）。先建立**四个心智模型**，后面 17 集全靠它们。

### 4.1 从「命令式」到「声明式」—— 这是 React 的全部

```js
// ═══ 你在 JS 阶段写的（命令式）：一步步指挥 DOM ═══
const list = document.querySelector('#list')
list.innerHTML = tasks.map(t => `<li>${t.name}</li>`).join('')
// 数据变了 → 你得自己再跑一遍这段 → 忘了就不同步

// ═══ React 里写的（声明式）：只说「长什么样」═══
return <ul>{tasks.map(t => <li key={t.id}>{t.name}</li>)}</ul>
// 数据变了 → React 自己重跑这个函数 → 自己算差异 → 自己更新 DOM
```

⭐ **一句话**：**JS 里你操作 DOM；React 里你描述 DOM，让 React 去操作。**
这正好是你在 JS 173-175 集学的「**改完数据必须重新渲染**」那条铁律的**自动化版本** —— 你再也不用记得手动 `render()` 了，React 替你记。

### 4.2 组件 = 一个返回 JSX 的普通函数

```tsx
function Hello(props: { name: string }) {
  return <h1>你好，{props.name}</h1>      // ← 这就是「界面」
}
```

没有 `new`、没有 `this`、没有生命周期钩子。**输入 props，输出界面**。纯函数。

### 4.3 JSX 不是 HTML，是语法糖

```tsx
const el = <h1 className="t">hi</h1>
// 编译后（React 17+，jsx: "react-jsx"）
const el = _jsx("h1", { className: "t", children: "hi" })
```

三个立刻能记住的差异：

| | HTML | JSX |
|---|---|---|
| class | `class="x"` | `className="x"` |
| 属性名 | `onclick` / `for` | `onClick` / `htmlFor`（驼峰） |
| 闭合 | `<br>` 可不闭合 | **必须闭合** `<br />` |

### 4.4 ⭐ 最贴切的 C# 类比：Blazor

这是全篇**可用度最高**的一个类比，值得你记一辈子：

| React | Blazor（.NET） | 差异 |
|---|---|---|
| 函数组件 `function App(props)` | `ComponentBase` 子类 | React 是函数，Blazor 是类 |
| `props` | `[Parameter]` 属性 | 都是「父传子」 |
| `useState` | 字段 + `StateHasChanged()` | React 自动，Blazor 手动 |
| JSX | Razor（`.razor`） | 都是「标记 + 表达式」 |
| 重新渲染 | 重新执行 `BuildRenderTree` | 思路几乎一致 |
| 单向数据流 | 单向数据流 | 一样 |

> ⭐ **结论：你会 Blazor 的话，React 的心智模型你已经有一半了。剩下的全是语法。**

⚠️ **但有一个本质差异**：Blazor 的 `StateHasChanged` 是你**手动**喊的，React 的 `setState` **自动**触发重渲染 —— 而且 React 要求你**不能用普通变量存状态**（改了不重渲染，这是本篇 §8 要讲的静默失败之一）。

## 1. 一根贯穿 24 集的探针代码

后面 8 篇每一篇都会回来改这段代码。它把「声明文件 → tsconfig → 组件类型」串成一条线：

```ts
// ═══ ① 类型从哪来（69-72）：Task 这个类型你一行没写，却能 import ═══
import type { Task } from './types'        // ← 73 集：项目内共享
// Task 的定义住在 types.d.ts，编译后不产生任何 JS

// ═══ ② 定义文件长什么样（70）：只有形状，没有实现 ═══
// types.d.ts:
//   export interface Task { id: number; name: string; done: boolean }

// ═══ ③ 在 React 里用（82）：props 的类型就是接口 ═══
function TaskItem({ task }: { task: Task }) {
  return <li>{task.name}</li>
}

// ═══ ④ 状态（91）：useState<Task[]> 让 state 有了类型 ═══
const [tasks, setTasks] = useState<Task[]>([])

// ═══ ⑤ 不可变更新（91）：不是 push，是造新数组 ═══
setTasks([...tasks, { id: Date.now(), name: text, done: false }])
```

⭐ **这五行代码，就是这 24 集的全部骨架。** 后面每一篇都在放大其中某一行。

## 2. 现在就能跑的一次验证

不需要新建项目，验证「`.d.ts` 不产出 JS」这件事：

```bash
# 建两个文件（同一个目录）
# a.d.ts  →  export interface A { x: number }
# a.ts    →  export const a: A = { x: 1 }

tsc --outDir out a.ts
ls out/          # ← 只有 a.js，没有 a.d.ts 的产物
```

**结论**：`.d.ts` 是**纯描述**，编译器读它，但不为它生成任何东西。这就是它能当"类型容器"的原因。

## 3. 全课 92 集收口（看完这 24 集，回头看 TS--01）

回到第 01 集那句话：**TS 的类型在运行时全部消失。**

走完 92 集，你会有三层理解，从浅到深：

| 层 | 说法 | 什么时候懂 |
|---|---|---|
| ① 表面 | 类型只是编译期检查，跑起来什么都没有 | 第 01 集 |

| ③ 深处 | **正因为会消失，才需要一个不产生代码的载体来存类型 —— `.d.ts`** | **本篇 69-75** |

> ⭐ **这是整门课最漂亮的一次闭环**：你以为 `.d.ts` 是"额外学的一个新东西"，其实它是「类型擦除」这个前提**推导出来的必然结果**。
>
> **C# 不需要 `.d.ts`，因为 `.dll` 里本来就带着元数据。JS 没有元数据，所以类型必须另外找地方住。**
