## 五、笔记模板（固定五段）

````markdown
==零：补充==
为什么要这个功能 / 它解决什么现实问题 / 没有它会怎样 /
在你自己的项目里它落在哪一行 / 以及什么时候其实用不上它。

==一：概念==
这个知识点是什么、为什么需要它、解决什么问题。
（能类比 WPF / 前端直觉的地方一定要写类比）

==二：格式==
API 签名 / 命令 / 写法的"骨架"，只留形状不留逻辑。
```csharp
父类类型 变量名 = new 子类类型();
```

==三：代码==
能跑通的完整示例，带输出结果或注释说明"为什么这么写"。

==四：总结==
表格 + 记忆口诀 + 易错点。
````

**笔记分成两个阶段**：笔记阶段可以几节合并一篇；练习阶段一节一篇。

## 六、避坑提示

1. **批次 07（表达式树 P91–96）不要死磕**：动态构建表达式树在实际项目里出现率极低，听懂"Expression 是数据结构、Func 是委托"这一句就够，剩下当故事听。
2. **批次 06 的并发令牌（3-39/3-40）要手打**：这是唯一能在面试里讲出"我处理过高并发覆盖"的素材。
3. **批次 11（P110–113）和批次 16 的 4-47（中间件 vs Filter）是高频面试题**，务必形成自己的对照表。
4. **Part6 不要试图全手打**：DDD 的价值在"分层为什么这么分"，代码敲 6-13、6-24~6-29 即可，其余画图理解。
5. **每个批次结束后回头看一次**：把本批 3 条结论补进对应 Part 索引文件的顶部，形成自己的"考前 10 分钟速览"。
