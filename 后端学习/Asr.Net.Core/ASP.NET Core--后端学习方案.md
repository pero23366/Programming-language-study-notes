```
① 看视频      一遍，不倍速，不边看边敲
② 关视频      只看笔记「二：格式」，自己从零敲一遍 → 报错再回看视频

⑤ 每批结束    合上笔记，口述这一批的 3 个核心结论
```

**为什么先看再关视频敲**：跟着视频敲＝抄写，肌肉记忆归零；关掉视频独立复现＝遇到卡点才会真正记住 API 名字。卡住的那次，就是笔记里要重点标红的那条。

## 六、避坑提示

1. **批次 07（表达式树 P91–96）不要死磕**：动态构建表达式树在实际项目里出现率极低，听懂"Expression 是数据结构、Func 是委托"这一句就够，剩下当故事听。
2. **批次 06 的并发令牌（3-39/3-40）要手打**：这是唯一能在面试里讲出"我处理过高并发覆盖"的素材。
3. **批次 14 的 4-47（中间件 vs Filter）是高频面试题**，务必形成自己的对照表。
4. **Part6 不要试图全手打**：DDD 的价值在"分层为什么这么分"，代码敲 6-13、6-24~6-29 即可，其余画图理解。
5. **每个批次结束后回头看一次**：把本批 3 条结论补进对应 Part 索引文件的顶部，形成自己的"考前 10 分钟速览"。
