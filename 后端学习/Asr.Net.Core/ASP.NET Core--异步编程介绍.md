==零：补充==


- **线程负责“发指令”和“算数据”**：CPU 其实只负责逻辑运算（比如 `1+1=2`、循环、判断）。
    
- **硬件负责“干重体力活”**：网卡负责传数据，硬盘负责读文件，数据库服务器负责查数据。这些物理动作，线程不需要参与

类比：
线程：服务员
（传单给后厨，和听完客户需求）
硬件：后厨

**注意：**
如果客户太啰嗦，光是“听需求”就听了 10 分钟（比如你写了一个死循环，或者极其耗时的 CPU 计算），那这个服务员就一直被占着，无法去服务其他桌。  
这就印证了上一轮说的：**`async/await` 只能解决“等后厨做菜（I/O）”的问题，解决不了“听客户啰嗦（CPU 计算）”的问题。** 遇到极其耗时的计算，还得靠多雇几个服务员（多线程）。



==一：概念==
**1. 什么是异步？**

杨中科老师用了一个很形象的词来解释：**“不等”**。同步编程中，代码是一行一行执行，上一行没完成，下一行就得等着。而异步编程的核心思想是：当一个操作耗时较长（比如读取文件、请求网络）时，先不等它完成，而是去做其他事情，等它完成后再回来处理结果[](https://www.e-com-net.com/article/1744650216327364608.htm#1)。

**2. 异步编程的核心价值是什么？**

这是本节课最重要的认知：**异步编程并不能加快单个请求的处理速度，但可以让 Web 服务器处理更多的请求，从而提高系统的并发量**[](https://www.e-com-net.com/article/1744650216327364608.htm#1)[](https://blog.csdn.net/weixin_43371831/article/details/134131462#1)。

**3. 异步不是多线程**

这是一个非常关键的澄清。**async/await 不等于多线程**，但它可以简化多线程程序的开发[](https://www.e-com-net.com/article/1744650216327364608.htm#1)。异步的本质是“不阻塞当前线程”，而不是“新开一个线程去干活”。
==二：格式==
异步编程有一套标准的“语法格式”，核心就是 **`async` 和 `await` 两个关键字**[](https://www.e-com-net.com/article/1744650216327364608.htm#1)：

**1. 方法定义格式**

- 用 **`async`** 关键字修饰的方法，就是异步方法。
    
- 异步方法的返回值一般是 **`Task`** 或 **`Task<T>`**（T 是真正的返回值类型）。
    
- 即使方法没有返回值，也最好将返回值写为 `Task`，**不要写成 `void`**，写成 void 容易出现问题。
    
- 异步方法的命名惯例是以 **`Async`** 结尾，比如 `GetDataAsync`。
    

**2. 方法调用格式**

- 调用异步方法时，一般会在方法前加上 **`await`** 关键字。
    
- 加上 `await` 后，拿到的返回值就是泛型指定的 T 类型。例如 `int i = await FuncAsync();` 中，`await` 把 `Task<int>` 中的 `int` 解析出来了。
    

**3. 规则约束**

- **如果一个方法中有 `await`，则这个方法也必须被 `async` 关键字修饰**[](https://www.e-com-net.com/article/1744650216327364608.htm#1)。
    
- 如果方法被 `async` 修饰，但内部调用异步方法不写 `await` 也可以执行，编译器只会给出警告[](https://www.e-com-net.com/article/1744650216327364608.htm#1)。
==三：代码==
这节课以概念和基本用法为主，代码部分展示了最基础的异步方法定义与调用模式。

**1. 定义一个异步方法**

```csharp

// 异步方法命名以 Async 结尾，返回 Task<int>
public async Task<int> GetNumberAsync()
{
    // 模拟耗时操作
    await Task.Delay(1000); 
    return 42;
}
```

**2. 调用异步方法**

```csharp

// 在另一个异步方法中调用
public async Task UseAsync()
{
    // 使用 await 等待结果
    int result = await GetNumberAsync(); 
    Console.WriteLine(result); // 输出 42
}
```

==四：总结==

这节课是异步编程的“总纲”，核心要点如下：

1. **理解“不等”**：异步 = 不等待耗时操作完成，先去干别的。
    
2. **记住核心价值**：异步不能加快单个请求，但能**提高服务器并发量**。
    
3. **分清概念**：异步 **不等于** 多线程，`async/await` 不等于多线程。
    
4. **掌握格式**：`async` 修饰方法，返回 `Task`/`Task<T>`，调用时用 `await`。
    
5. **守住规则**：有 `await` 的方法必须用 `async` 修饰；无返回值也写 `Task` 而不是 `void`。
