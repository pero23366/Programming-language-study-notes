# 性能分析：执行频次、慢查询、profiles

> 来源：P75–P77《18–20. 进阶-索引-性能分析-查看执行频次 / 慢查询日志 / show profiles》 · 档位 C 全新
> 与我已知的关系：EF Core 有 `ToQueryString()` 和日志，但**它不会告诉你"这句 SQL 慢在哪"**——这三个工具才是答案

==一：意义与概念==

优化前必须先定位问题。三个工具，从粗到细：

| 工具 | 回答什么问题 | 精度 | 代价 |
|---|---|---|---|
| `SHOW GLOBAL STATUS`（执行频次）| 增删改查各执行了多少次 | 全局计数 | 无 |
| 慢查询日志 `slow_query_log` | **哪几条 SQL 慢** | 语句级，可设阈值 | 有磁盘写入 |
| `SHOW PROFILES` | 一条 SQL 各阶段耗时 | 语句内阶段 | 只影响当前会话 |

### 1. 执行频次：先看"忙在哪种操作"

```sql
SHOW GLOBAL STATUS LIKE 'Com_______';   -- 七个下划线，匹配 Com_select 等
```

`Com_select` / `Com_insert` / `Com_update` / `Com_delete` 分别计数。用途：判断这张库是"读多"还是"写多"，决定该优化索引（读）还是优化批量写入（写）。

注意 `Com_______` 是 7 个下划线，少写一个就匹配不到，这是课程里最容易敲错的一行。

### 2. 慢查询日志：抓现行

```sql
SHOW VARIABLES LIKE 'slow_query_log';      -- 是否开启
SHOW VARIABLES LIKE 'long_query_time';     -- 阈值（默认 10 秒）
SET GLOBAL slow_query_log = 'ON';
SET GLOBAL long_query_time = 1;            -- 超过 1 秒记下来（只对新连接生效）
```

日志文件位置由 `slow_query_log_file` 指定，默认在数据目录下 `hostname-slow.log`。

**关键补充**：只记录"超过阈值"的语句会漏掉一类问题——**执行次数极多、单次不慢**的语句（循环里查了 10 万次的 SQL，每次 5ms，总共 500 秒）。这类要靠 `log_queries_not_using_indexes`（记录没走索引的语句）或第 18 章的 `performance_schema` / `sys` 库来看。课程没展开，但这是真实排查里最常被忽略的一点。

配套工具 `mysqldumpslow` 可以按"总耗时/执行次数"排序汇总：

```bash
mysqldumpslow -s t -t 10 /var/lib/mysql/*-slow.log   # 按总时间排序取前 10
```

### 3. show profiles：一条 SQL 花在哪

```sql
SET profiling = 1;              -- 开启（8.0 需要）
-- 执行几条 SQL
SHOW PROFILES;                  -- 列出最近语句及总耗时
SHOW PROFILE FOR QUERY 3;       -- 看第 3 条的各阶段耗时
```

阶段里最值得看的是 `Sending data`（实际是"读数据 + 处理"）、`Sorting result`、`Creating tmp table`。出现 `Creating tmp table` 往往意味着用了临时表（`GROUP BY` 无索引、子查询未被优化）。

> 💡 8.0 起 `SHOW PROFILE` 已被标记为**废弃**，官方推荐用 `performance_schema`。课程讲它是因为 5.7 时代它是主力工具。你在 8.0 上还能用，但别在新项目里依赖。

和 EF Core 的关系：EF Core 的日志能看到 `Executed DbCommand (123ms)`，这给你"哪条慢"，但不给"为什么慢"。把那条 SQL 复制到客户端，`EXPLAIN` 一下（下一篇），才知道是没走索引还是走了但回表太多。**EF Core + EXPLAIN 是排查性能问题的标准组合**，`.ToQueryString()` 就是取 SQL 的工具。

==二：使用格式==

```sql
-- 执行频次
SHOW GLOBAL STATUS LIKE 'Com_______';

-- 慢查询
SET GLOBAL slow_query_log = 'ON';
SET GLOBAL long_query_time = 1;
SHOW VARIABLES LIKE 'slow_query_log_file';

-- profiles
SET profiling = 1;
SHOW PROFILES;
SHOW PROFILE FOR QUERY n;
```

==三：代码实践==

```sql
-- 模拟慢查询：大表上做无索引的条件过滤
SELECT * FROM emp WHERE name = '张三';   -- name 无索引，100 万行扫一遍

SHOW PROFILES;
-- Query_ID  Duration  Query
-- 1         2.813451  SELECT * FROM emp WHERE name = '张三'
```

==四：总结归纳==

- 三条：`Com_______` 看读写比例；慢查询日志抓超阈值语句（但漏"高频小慢"）；profiles 看单条语句各阶段耗时。
- 记忆锚：执行频次是体温计，慢查询日志是体检报告，profiles 是 CT。
- 自测：① `Com_______` 里有几个下划线？② 为什么"每次 5ms 但执行 10 万次"的 SQL 可能不被慢查询日志记录？
