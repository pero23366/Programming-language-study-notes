# 覆盖索引与回表查询

> 来源：P84《27. 进阶-索引-使用规则-覆盖索引&回表查询》 · 档位 C 全新
> 与我已知的关系：这是"为什么 `SELECT *` 慢"的完整答案，也是 EF Core 里 `.Select(x => new {...})` 投影查询唯一的性能理由

==一：意义与概念==

先回到 11-04 的结论：二级索引叶子只存"索引列 + 主键"，查整行要**回表**去聚簇索引再找一次。

**回表为什么贵**：假设你要查 10 万行，主键是 `1, 5, 88, 3001, 99999...` 散乱分布。每次回表都要在聚簇索引树里从根走到叶子，是**随机 IO**。10 万次随机 IO，机械盘上就是几秒到几十秒。

**覆盖索引**：如果查询需要的**所有列**都在这棵二级索引里，就不用回表了 —— 这叫"索引覆盖"，`EXPLAIN` 的 `Extra` 会显示 **`Using index`**。

举例，索引 `idx_name_age (name, age)`：

```sql
-- 需要 name、age → 两个都在索引里 → 覆盖，不回表 ✅ Extra: Using index
SELECT name, age FROM emp WHERE name = '张三';

-- 需要 id → 主键也在二级索引叶子里（隐含）→ 覆盖 ✅
SELECT id, name FROM emp WHERE name = '张三';

-- 需要 salary → 不在索引里 → 必须回表 ❌ Extra: NULL
SELECT name, salary FROM emp WHERE name = '张三';

-- SELECT * → 所有列都要 → 一定回表 ❌
SELECT * FROM emp WHERE name = '张三';
```

这就是 **"不要 `SELECT *`" 的真正原因**：不是"多余列浪费带宽"这么轻，而是**破坏了覆盖索引，强制回表**。

三条实用推论：

1. **给高频查询设计"刚好覆盖"的联合索引**：`WHERE user_id = ? ORDER BY created_at` 且只要 `id, status` → 建 `(user_id, created_at, status)`，一次索引扫描全搞定。
2. **`COUNT(*)` 也能覆盖**：`SELECT COUNT(*) FROM emp WHERE name LIKE '张%'` 只需要索引，不回表。
3. **覆盖索引的代价**：索引列越多，索引树越大，写入越慢。所以覆盖索引是"为某几条高频查询定制"的，不是把所有列塞进去。

和 EF Core 的关系：这条对应一个非常具体的写法差异：

```csharp
// 回表：查整行实体
var list = db.Orders.Where(o => o.UserId == 1).ToList();

// 覆盖：只投影需要的列，如果索引刚好覆盖，就走 Using index
var list = db.Orders.Where(o => o.UserId == 1)
                    .Select(o => new { o.Id, o.Status, o.CreatedAt })
                    .ToList();
```

**这就是"只读列表页用投影、详情页才查实体"的性能依据**，不是风格偏好。EF Core 的 `AsNoTracking()` 解决的是"不追踪对象"（省内存），`Select` 投影解决的是"不回表"（省 IO），两件事不能互相替代。

常见误解：以为"索引越多列越容易覆盖"。覆盖的前提是**查询列 ⊆ 索引列 ∪ {主键}**，多塞用不上的列只会让索引变大、写入更慢。

==二：使用格式==

无新语法，靠 `EXPLAIN` 的 `Extra` 判断：

```sql
EXPLAIN SELECT name, age FROM emp WHERE name='张三';
-- Extra: Using index   ← 覆盖，未回表
```

==三：代码实践==

```sql
CREATE INDEX idx_name_age ON emp(name, age);

-- 1. 覆盖
EXPLAIN SELECT name, age FROM emp WHERE name = '张三';        -- Using index
-- 2. 覆盖（主键隐含在二级索引里）
EXPLAIN SELECT id, name FROM emp WHERE name = '张三';         -- Using index
-- 3. 回表
EXPLAIN SELECT name, salary FROM emp WHERE name = '张三';     -- Extra 为空
-- 4. 强制回表
EXPLAIN SELECT * FROM emp WHERE name = '张三';                -- Extra 为空

-- 5. 深分页的经典优化：先用覆盖索引取主键，再关联
SELECT e.* FROM emp e
JOIN (SELECT id FROM emp ORDER BY id LIMIT 1000000, 10) t ON e.id = t.id;
-- 子查询只取 id（覆盖索引，不用回表），只对最终 10 行回表
```

最后那条是第 12 章 `limit 优化` 的核心手法，现在先记住它的名字：**延迟关联**。

==四：总结归纳==

- 三条：查询列全在索引里 = 覆盖索引 = 不回表（`Extra: Using index`）；`SELECT *` 必然回表；深分页用"先取主键再关联"减少回表次数。
- 记忆锚：二级索引是"索引页"，回表是"按索引页上的页码去翻正文"——如果索引页上已经写着你需要的信息，就不用翻正文了。
