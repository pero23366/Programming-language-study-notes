# 全局锁与一致性数据备份

> 来源：P122–P123《65–66. 进阶-锁-全局锁-介绍 / 全局锁-一致性数据备份》 · 档位 C 全新
> 与我已知的关系：`FLUSH TABLES WITH READ LOCK` 是 MySQL 独有的一套"全库只读"机制，SQL Server 对应的是数据库快照/只读切换

==一：意义与概念==

**全局锁**：锁住整个实例，**所有表只读**，任何 `INSERT/UPDATE/DELETE/DDL` 都被阻塞。

```sql
FLUSH TABLES WITH READ LOCK;   -- 简称 FTWRL，开启全局锁
-- 备份...
UNLOCK TABLES;                 -- 释放
```

### 为什么需要它：一致性备份

痛点：`mysqldump` 导出 100 张表，导出第 1 张时是 10:00，导出第 100 张时是 10:30。这半小时里如果有转账发生，备份里就是"前 50 张有转账前、后 50 张有转账后"的状态——**数据不自洽**。

全局锁解决：加锁后全库只读，导出期间没有写入，快照自洽。

### 但它的代价几乎不可接受

加锁期间**业务全部停写**。线上库加全局锁 30 分钟 = 30 分钟不能下单。

所以真实做法是替代方案：

| 方案 | 做法 | 适用 |
|---|---|---|
| **`--single-transaction`** | InnoDB 的可重复读快照导出一致性数据 | **主流方案**（推荐）|
| 主从 + 从库备份 | 在从库上 `FTWRL` 或快照，不影响主库 | 生产标配 |
| 文件系统快照 | LVM/XFS 快照，秒级 | 大库 |
| `mysqldump` + `--single-transaction` | 一个事务里导出，靠 MVCC 保证一致 | 中小库 |

`--single-transaction` 的原理：开一个 `REPEATABLE READ` 事务，整个导出过程读的都是同一份快照（MVCC），**不加锁**。限制：只对 InnoDB 有效（MyISAM 表做不到一致性）。

### 另一类场景：全库只读维护

```sql
SET GLOBAL read_only = ON;           -- 普通账号只读（超级用户仍可写）
SET GLOBAL super_read_only = ON;     -- 8.0，连超级用户也禁写
```

这比 `FTWRL` 温和：不改表结构、不阻塞读，用于"停机维护窗口"或"从库防误写"。**生产上从库一定要开 `super_read_only`**，否则误连从库写了数据，主从不一致很难修。

和 EF Core 的关系：这三条都跟 ORM 无关，但如果你的应用连到了只读实例：

```csharp
// 读写分离的从库连接，写操作会报
// ERROR 1290: The MySQL server is running with the --read-only option
```

看到这个错，先查连接串是不是连错了实例，而不是怀疑 EF Core。

==二：使用格式==

```sql
-- 全局锁（慎用）
FLUSH TABLES WITH READ LOCK;
UNLOCK TABLES;

-- 只读模式
SET GLOBAL read_only = ON;
SET GLOBAL super_read_only = ON;

-- 一致性备份（推荐）
-- mysqldump -u root -p --single-transaction --source-data=2 demo > demo.sql
```

==三：代码实践==

```bash
# 推荐的一致性备份命令
mysqldump -u root -p \
  --single-transaction \
  --source-data=2 \
  --routines --triggers --events \
  demo > demo_$(date +%Y%m%d).sql
```

| 参数 | 作用 |
|---|---|
| `--single-transaction` | InnoDB 快照一致性，不加锁 |
| `--source-data=2` | 记录 binlog 位点（注释形式），便于搭从库 |
| `--routines --triggers --events` | 连存储过程/触发器/事件一起导（默认不导！）|

`--source-data=2` 这个坑很实际：**默认 `mysqldump` 不导出存储过程和触发器**，只导表结构和数据。恢复后业务报"过程不存在"，就是漏了这几个参数。

==四：总结归纳==

- 三条：`FTWRL` 全局只读，会停业务；一致性备份用 `--single-transaction`（MVCC 快照，不加锁）；从库开 `super_read_only` 防误写。
- 记忆锚：`FTWRL` 是"全店打烊再盘点"，`--single-transaction` 是"边营业边拍照"。
- 自测：① `--single-transaction` 对 MyISAM 表有效吗？② `mysqldump` 默认会导出存储过程吗？
