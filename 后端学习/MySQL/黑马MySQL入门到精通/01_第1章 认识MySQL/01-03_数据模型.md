# 数据模型

> 来源：P4《04. 基础-概述-数据模型》 · 档位 A 几乎重叠
> 与我已知的关系：`DbContext` → 库、`DbSet<T>` → 表、属性 → 列，一一对应

==一：意义与概念==

MySQL 是**关系型数据库**，数据摆成二维表。访问链路是一条直线：

```
客户端(DataGrip/命令行/你的 ASP.NET Core 程序)
        ↓  SQL
   DBMS（mysqld 服务）
        ↓
  数据库（一个服务下可以有多个）
        ↓
  表（行 = 记录，列 = 字段）
```

和 EF Core 的映射关系，逐项对齐：

| MySQL | 你的 C# 世界 |
|---|---|
| 一个数据库 | 一个 `DbContext` 实例连的那个库 |
| 一张表 | 一个 `DbSet<Order>` |
| 一列 | 实体类的一个属性（`Order.Total`） |
| 一行 | 一个实体实例（`new Order{...}`）|

**差别在"谁定义结构"**：EF Core 里你先写类、再由 Migration 推表；MySQL 里表是 DDL 直接建的，EF Core 只是映射层。所以用 EF Core 连 MySQL 时，`DbContext` 不是数据库，它只是一张"翻译表"。

常见误解：以为一个 MySQL 服务就是一个数据库。实际是一个服务实例管多个库，`USE db_name` 切库，跟你切换 `DbContext` 的连接串是同一件事。

==四：总结归纳==

- 一条链：客户端 → DBMS → 库 → 表 → 行/列。
- 记忆锚：EF Core 那套对象模型，在数据库这边叫"二维表"，中间隔着一层翻译。
- 自测：① `USE test` 相当于 C# 里的哪个动作？② 一个表有 3 行 5 列，EF Core 里对应几个对象、几个属性？
