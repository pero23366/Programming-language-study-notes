# 表操作：修改与删除

> 来源：P9《09. 基础-SQL-DDL-表操作-修改&删除》 · 档位 A 几乎重叠
> 与我已知的关系：`ALTER TABLE` 概念一样，**但改列类型的关键字换成了 MODIFY / CHANGE，不是 ALTER COLUMN**

==一：意义与概念==

五种改法，对应 T-SQL 的 `ALTER TABLE`：

| 要做的事 | MySQL | T-SQL 写法 |
|---|---|---|
| 加列 | `ADD 列 类型` | `ADD 列 类型` |
| 改列**类型** | `MODIFY 列 新类型` | `ALTER COLUMN 列 新类型` |
| 改列**名 + 类型** | `CHANGE 旧名 新名 新类型` | `sp_rename` |
| 删列 | `DROP COLUMN 列` | `DROP COLUMN 列` |
| 改表名 | `RENAME TABLE a TO b` | `sp_rename` |

`CHANGE` 必须把**新类型重写一遍**，哪怕不改类型——这是最容易漏参数的地方。

MySQL 也可以在一条 `ALTER` 里用逗号做多件事，比 T-SQL 方便：`ALTER TABLE t ADD a INT, DROP COLUMN b;`

==二：使用格式==

```sql
ALTER TABLE 表名 ADD 列名 类型 [COMMENT '...'];
ALTER TABLE 表名 MODIFY 列名 新类型;                    -- 改类型
ALTER TABLE 表名 CHANGE 旧列名 新列名 类型;              -- 改名（类型必写）
ALTER TABLE 表名 DROP COLUMN 列名;
ALTER TABLE 表名 RENAME TO 新表名;
```

==四：总结归纳==

- 记两个新关键字：`MODIFY` 改类型、`CHANGE` 改名（类型必带）。
- 记忆锚：T-SQL 一个 `ALTER COLUMN` 包打天下，MySQL 拆成两把刀，改名那把还得连类型一起交。
- 自测：`CHANGE name username`（不写类型）能执行吗？（不能，语法报错）
