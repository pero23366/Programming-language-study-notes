# DML 插入数据

> 来源：P12《12. 基础-SQL-DML-插入》 · 档位 A 几乎重叠
> 与我已知的关系：`INSERT INTO ... VALUES` 与 T-SQL 基本一致，MySQL 的批量插入写法更省事

==一：意义与概念==

给表里加行。写法与 T-SQL 相同，三点差异：

1. **批量插入一条语句搞定**：`VALUES (...), (...), (...)`。T-SQL 也支持，但 MySQL 更常用（性能差异明显，第 12 章会讲）。
2. **自增列不用写、也不能随便写**：不写列名时自动补；要显式指定得写 `NULL` 或 `DEFAULT` 占位。
3. **`INSERT ... SET` 写法是 MySQL 特有的**：`INSERT INTO t SET a=1, b=2;`，字段多时比列清单好读。

常见误解：以为不写列名就等于"所有列都能省"。不写列名时**必须按建表顺序给齐所有列**，且不能跳过非空无默认值的列。

==二：使用格式==

```sql
INSERT INTO 表名 (列1, 列2) VALUES (值1, 值2);
INSERT INTO 表名 VALUES (值1, 值2, 值3);           -- 按建表顺序全给
INSERT INTO 表名 (列1, 列2) VALUES (1,'a'), (2,'b'); -- 批量
INSERT INTO 表名 SET 列1=值1, 列2=值2;              -- MySQL 特有
INSERT INTO 目标表 (列) SELECT 列 FROM 源表;        -- 表间复制
```

==四：总结归纳==

- 三条：批量用逗号堆 `VALUES`；自增列交给数据库；`INSERT ... SET` 是 MySQL 方言。
- 记忆锚：和 T-SQL 同一个语法，只是批量那行能写得更长。
- 自测：`INSERT INTO t VALUES (1)` 而表有 3 列，会怎样？
