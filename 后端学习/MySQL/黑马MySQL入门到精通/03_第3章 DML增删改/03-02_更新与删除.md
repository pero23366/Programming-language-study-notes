# DML 更新与删除

> 来源：P13《13. 基础-SQL-DML-更新和删除》 · 档位 A 几乎重叠
> 与我已知的关系：`UPDATE` / `DELETE` 语法一致，MySQL 多了 `ORDER BY + LIMIT` 的限量写法

==一：意义与概念==

改行、删行。语法与 T-SQL 相同，差异两点：

1. **可以限量**：`UPDATE ... LIMIT 10`、`DELETE ... LIMIT 1000`。做大批量清理时分批执行，避免长事务锁表。T-SQL 得用 `TOP`（UPDATE）或子查询绕。
2. **没有 `TRUNCATE` 的差异**：`TRUNCATE TABLE` 两边都有，都是 DDL、不可回滚、重置自增值。

必须强调的坑：**`DELETE` 不带 `WHERE` 就是清空全表**，且 MySQL 默认 `sql_safe_updates=0`，不会拦你。DataGrip 有"确认执行"弹窗，命令行没有。

==二：使用格式==

```sql
UPDATE 表名 SET 列1=值1, 列2=值2 [WHERE 条件] [ORDER BY ... LIMIT n];
DELETE FROM 表名 [WHERE 条件] [ORDER BY ... LIMIT n];
TRUNCATE TABLE 表名;     -- 清空并重置自增，不可回滚
```

==四：总结归纳==

- 三条：`WHERE` 是保命符；批量删用 `LIMIT` 分批；`TRUNCATE` 不可回滚。
- 记忆锚：MySQL 的 DML 比 T-SQL 多一个"限行开关"。
- 自测：`DELETE FROM t LIMIT 100` 和 `TRUNCATE TABLE t` 在自增值上的区别是什么？
