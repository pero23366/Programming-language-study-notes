# 常用客户端工具

> 来源：P149–P150《92–93. 进阶-MySQL管理-常用工具1 / 2》 · 档位 B 部分重叠
> 与我已知的关系：这批命令相当于 SQL Server 的 `sqlcmd`/`bcp`/`SSMS 导出向导`，**但它们才是自动化和 CI 的入口**

==一：意义与概念==

六个工具，按用途分组：

| 工具 | 用途 | 类比 |
|---|---|---|
| `mysql` | 命令行客户端（执行 SQL、导入脚本）| `sqlcmd` |
| `mysqladmin` | 管理命令（改密码、看状态、关库）| `sqlcmd -Q` + 服务管理 |
| `mysqldump` | **逻辑备份**（导出 SQL 文本）| SSMS 的"生成脚本" |
| `mysqlimport` | 导入文本数据（对应 `LOAD DATA`）| `bcp in` |
| `mysqlbinlog` | **解析 binlog**（看/回放）| 无直接对应 |
| `mysqlshow` | 快速看库表结构 | `sp_helpdb` |

### `mysql`：别只会交互式

```bash
mysql -u root -p -h 127.0.0.1 -P 3306 -D demo              # 登录指定库
mysql -u root -p demo < backup.sql                          # 导入 SQL 文件
mysql -u root -p -e "SELECT COUNT(*) FROM demo.emp"         # 执行单条（脚本化必备）
mysql -u root -p --batch --raw -e "..." > out.tsv            # 表格化输出，便于处理
```

`-e` 这个参数是"让 mysql 变成可脚本化工具"的关键：没有它，你只能进交互界面。

### `mysqldump`：最重要，也最容易用错

```bash
mysqldump -u root -p \
  --single-transaction \
  --source-data=2 \
  --routines --triggers --events \
  --databases demo > demo.sql
```

| 参数 | 作用 | 不写会怎样 |
|---|---|---|
| `--single-transaction` | InnoDB 一致性快照，不锁表 | 备份期间数据不自洽 |
| `--source-data=2` | 记录 binlog 位点（注释形式）| 无法精确搭从库 |
| `--routines` | 导出存储过程/函数 | **恢复后过程不存在** |
| `--triggers` | 导出触发器 | 触发器丢失 |
| `--events` | 导出事件调度器 | 定时任务丢失 |
| `--databases` | 带 `CREATE DATABASE` | 恢复后要手工建库 |
| `--no-data` | 只要结构 | — |
| `--where="..."` | 只导部分行（按条件）| 大表可以分批导 |

**最容易被漏的是 `--routines` / `--triggers` / `--events`**：默认不导出，恢复后业务报"过程不存在"，很难第一时间想到是备份参数问题。

### `mysqlbinlog`：把 binlog 变成可读文本

```bash
mysqlbinlog --base64-output=DECODE-ROWS -v binlog.000001 | less
mysqlbinlog --start-datetime="2026-11-12 10:00:00" \
            --stop-datetime="2026-11-12 10:30:00" \
            binlog.000001 > today.sql
```

用途：

1. **误删数据恢复**：找到删除前的位点，用 `mysqlbinlog` 抽出反向操作（或用 `binlog2sql` 工具生成回滚 SQL）。
2. **追查"谁改的"**：binlog 里有事务与语句。
3. **主从延迟排查**：看从库执行到哪个位点。

这是 MySQL 相比 SQL Server 更"可见"的一个能力——**binlog 是纯文本可解析的**。

### `mysqladmin`：几个常用

```bash
mysqladmin -u root -p status            # 运行状态（QPS、连接数）
mysqladmin -u root -p processlist       # 当前连接
mysqladmin -u root -p extended-status   # 所有状态变量
mysqladmin -u root -p shutdown          # 关库
```

和 EF Core 的关系：批量数据导入/导出、环境初始化（建库+建表+种子数据）、CI 里的数据库准备，都靠这些命令行工具。**EF Core 的 `Migrate()` 只管结构，数据导入和备份要靠它们**。

一个实用组合：

```bash
# 开发环境重建：结构 + 数据
mysql -u root -p -e "DROP DATABASE IF EXISTS demo; CREATE DATABASE demo DEFAULT CHARSET utf8mb4;"
mysql -u root -p demo < schema.sql
mysql -u root -p demo < seed.sql
```

==二：使用格式==

见上。要点：`mysql -e` 脚本化、`mysqldump` 四个参数别漏、`mysqlbinlog` 解析 binlog。

==三：代码实践==

```bash
# 分表备份（大表按条件分批，避免单文件过大）
mysqldump -u root -p demo emp --where="id < 1000000" > emp_part1.sql
mysqldump -u root -p demo emp --where="id >= 1000000" > emp_part2.sql
```

==四：总结归纳==

- 三条：`mysql -e` 让客户端可脚本化；`mysqldump` 必须带 `--single-transaction --routines --triggers`；`mysqlbinlog` 能解析 binlog 做恢复与追查。
- 记忆锚：`mysqldump` 是"导出 SQL 文本"，`mysqlbinlog` 是"导出历史操作"。
