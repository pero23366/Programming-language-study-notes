# MVCC：隐藏字段与 undo 版本链

> 来源：P141–P143《84–86. 进阶-InnoDB引擎-MVCC-基本概念 / 隐藏字段 / undolog版本链》 · 档位 C 全新
> 与我已知的关系：EF Core 的 `AsNoTracking` 是"不追踪对象"，MVCC 是"数据库追踪行的多个版本"——两件事，别混

==一：意义与概念==

**MVCC（Multi-Version Concurrency Control，多版本并发控制）**：让"读"和"写"不互相阻塞——读的时候不用加锁，读到的是**快照**。

它解决的问题：如果只有锁，`SELECT` 要加 S 锁、`UPDATE` 要加 X 锁，读写互斥，并发极差。MVCC 让"读"永远能读到某个版本，不用等写。

### 三个隐藏字段

每行数据除了你定义的列，InnoDB 还偷偷加了三个字段：

| 字段 | 长度 | 作用 |
|---|---|---|
| `DB_TRX_ID` | 6 字节 | **最后修改这行的事务 ID** |
| `DB_ROLL_PTR` | 7 字节 | **回滚指针**，指向 undo log 里这个行的上一个版本 |
| `DB_ROW_ID` | 6 字节 | 隐藏主键（只有表没有主键时才用）|

`DB_ROLL_PTR` 是 MVCC 的关键——它把一行的所有历史版本串成一条链表。

### undo 版本链

假设事务 100 插入一行（金额 100），事务 200 改成 200，事务 300 改成 300：

```
当前行（金额 300）
  DB_TRX_ID = 300
  DB_ROLL_PTR ──┐
                ↓
        undo: 金额 200（TRX_ID=200）
          DB_ROLL_PTR ──┐
                        ↓
                undo: 金额 100（TRX_ID=100，插入版本）
                  DB_ROLL_PTR = NULL   ← 链尾
```

每个版本都记着"是哪个事务改的"。**这条链就是"历史"**，MVCC 靠它实现"读旧版本"。

### 快照读怎么选版本：ReadView

读到一行时，InnoDB 拿 `DB_TRX_ID` 跟"当前的 ReadView"比对，判断这个版本"我该不该看见"：

- 事务 ID 在 ReadView 之前提交 → **可见**
- 事务 ID 还在活跃列表里（未提交）→ **不可见，顺着链找上一个版本**
- 事务 ID 大于 ReadView（在我之后才开始的）→ **不可见，往前找**

具体规则在 17-06 展开。这里先记住：**MVCC = 隐藏字段 + undo 版本链 + ReadView**，三者缺一不可。

### 一个关键区分：快照读 vs 当前读

| | 读什么 | 加锁 | 语句 |
|---|---|---|---|
| **快照读** | ReadView 允许的历史版本 | ❌ | 普通 `SELECT` |
| **当前读** | 最新版本 | ✅ | `FOR UPDATE` / `FOR SHARE` / `UPDATE` / `DELETE` / `INSERT` |

同一个事务里，先 `SELECT` 读到金额 100（快照），再 `UPDATE` 会用最新值 300 做计算（当前读）——**这就是 09-03 提过的"同一事务里两种读法结果不同"**。现在你知道原因了。

和 EF Core 的关系（重要）：

```csharp
var order = db.Orders.Find(1);      // 快照读，读到的是事务开始时的版本
order.Status = 2;
db.SaveChanges();                    // 当前读 + 加锁，基于最新值更新
```

如果两个请求同时做这件事，**EF Core 不会帮你检测"中间被别人改过"**——除非你配了并发令牌（`IsRowVersion`）。所以"读-改-写"要么用乐观锁，要么用 `FOR UPDATE`，不能指望 MVCC 帮你兜住。


==三：代码实践==

```sql
-- 会话 A（RR）
START TRANSACTION;
SELECT salary FROM emp WHERE id = 1;    -- 1000（快照）

-- 会话 B
UPDATE emp SET salary = 2000 WHERE id = 1;
COMMIT;

-- 会话 A 再读：仍是 1000（读的是 undo 版本链里的旧版本）
SELECT salary FROM emp WHERE id = 1;    -- 1000

-- 但 A 一旦 UPDATE，就会用最新值 2000
UPDATE emp SET salary = salary + 100 WHERE id = 1;   -- 结果 2100，不是 1100
COMMIT;
```

==四：总结归纳==

- 三条：每行有三个隐藏字段（`DB_TRX_ID`/`DB_ROLL_PTR`/`DB_ROW_ID`）；`DB_ROLL_PTR` 把历史版本串成链；快照读沿链找可见版本，当前读拿最新值。
- 记忆锚：MVCC 是给每一行拍了"历史照片"，读的人各看各的那张，谁也不用等谁。
