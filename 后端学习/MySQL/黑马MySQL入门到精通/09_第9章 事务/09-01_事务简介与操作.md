# 事务简介与操作

> 来源：P51–P52《51. 基础-事务-简介 / 52. 基础-事务-操作演示》 · 档位 B 部分重叠
> 与我已知的关系：`BEGIN` / `COMMIT` / `ROLLBACK` 概念一样，**但 MySQL 默认自动提交（autocommit=1），且 DDL 会隐式提交**

==一：意义与概念==

事务把多条语句捆成一个原子操作：要么全成功，要么全回滚。经典场景是转账——扣款成功、加款失败，钱就凭空消失了。

概念与 T-SQL 完全一致，三处行为差异必须记住：

**1. `autocommit` 默认是开的**
MySQL 默认每条 SQL 执行完自动 `COMMIT`（`autocommit=1`）。所以你不写 `START TRANSACTION` 时，每条语句都是独立事务。T-SQL 的 `IMPLICIT_TRANSACTIONS` 默认是**关**的，行为其实类似——但概念表述不同：MySQL 是"自动提交每条"，T-SQL 是"不自动开事务"。结果都是"单条语句立即生效"。

**2. DDL 会隐式提交当前事务**
这是 MySQL 最坑的行为：事务进行到一半执行 `CREATE TABLE` / `ALTER TABLE` / `DROP TABLE`，**MySQL 会先悄悄 `COMMIT` 再执行 DDL**。你以为还在事务里，其实前面所有操作已经落库，后面 `ROLLBACK` 也撤不回来了。T-SQL 里 DDL 也在事务内，可以回滚。**这条是迁移项目时最容易出数据事故的地方。**

**3. `BEGIN` 与 `START TRANSACTION` 等价**
`BEGIN` 是简写，但注意 `BEGIN ... END` 在存储过程里表示语句块，含义完全不同（第 14 章）。

事务内还可以设**保存点**（savepoint），实现"部分回滚"：转账批量处理 10 笔，第 7 笔失败时只回滚第 7 笔，前 6 笔保留。

==二：使用格式==

```sql
START TRANSACTION;         -- 或 BEGIN; 开启事务
  ... 业务 SQL ...
SAVEPOINT 保存点名;         -- 打一个回滚点
  ... 
ROLLBACK TO 保存点名;       -- 回到保存点（之前的操作不回滚）
COMMIT;                    -- 提交
ROLLBACK;                  -- 全部回滚

SELECT @@autocommit;       -- 1 = 自动提交
SET autocommit = 0;        -- 关闭自动提交（之后必须手动 COMMIT）
```

| 语句 | 作用 | 注意 |
|---|---|---|
| `START TRANSACTION` | 开启显式事务 | 会临时把 autocommit 置 0，`COMMIT` 后恢复 |
| `COMMIT` | 提交并结束事务 | 提交后不可回滚 |
| `ROLLBACK` | 回滚整个事务 | 结束事务 |
| `SAVEPOINT x` | 设回滚点 | 不结束事务 |
| `ROLLBACK TO x` | 回到回滚点 | 事务仍在进行 |

==三：代码实践==

```sql
START TRANSACTION;

UPDATE account SET balance = balance - 100 WHERE id = 1;
UPDATE account SET balance = balance + 100 WHERE id = 2;

-- 此时在另一个会话查，看不到变化（未提交）

COMMIT;   -- 两个会话都能看到了
```

反例（DDL 隐式提交）：

```sql
START TRANSACTION;
UPDATE account SET balance = balance - 100 WHERE id = 1;
CREATE TABLE tmp (id INT);   -- ⚠️ 这里隐式 COMMIT 了，前面的 UPDATE 已经落库
ROLLBACK;                    -- 撤不回来了
```

==四：总结归纳==

- 三条：默认 `autocommit=1`；DDL 会隐式提交当前事务，`ROLLBACK` 救不回来；`SAVEPOINT` 支持部分回滚。
- 记忆锚：MySQL 的事务最怕中途建表——一建表，前面的活就定了。
