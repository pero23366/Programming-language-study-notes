# DQL 条件查询

> 来源：P16《16. 基础-SQL-DQL-条件查询》 · 档位 A 几乎重叠
> 与我已知的关系：`WHERE` 后那一整套运算符与 T-SQL 逐字相同

==一：意义与概念==

按行筛选。运算符全家桶与 T-SQL 一致：

| 运算符 | 写法 | 说明 |
|---|---|---|
| 比较 | `> >= < <= = <>` | `!=` 也能用，`<>` 是标准写法 |
| 逻辑 | `AND` `OR` `NOT` | `AND` 优先级高于 `OR`，混用必须加括号 |
| 范围 | `BETWEEN 小 AND 大` | **包含两端**，且小值必须在前 |
| 列表 | `IN (值,...)` | 等价于一串 `OR`，命中索引时更快 |
| 模糊 | `LIKE '张%'` | `%` 任意个字符，`_` 恰好一个字符 |
| 空值 | `IS NULL` / `IS NOT NULL` | **不能用 `= NULL`**，永远为假 |

唯一需要重新建立直觉的是模糊查询的索引含义：`LIKE '张%'`（前缀匹配）能走索引，`LIKE '%张%'`（前后都通配）**一定全表扫描**。这不是 MySQL 特有，但第 11 章会用它做索引失效的第一个案例。

==二：使用格式==

```sql
SELECT * FROM emp WHERE age BETWEEN 20 AND 30;
SELECT * FROM emp WHERE name LIKE '张_';        -- 张 + 恰好一个字
SELECT * FROM emp WHERE id IN (1,2,3);
SELECT * FROM emp WHERE id_card IS NULL;
SELECT * FROM emp WHERE (age > 30 OR salary > 10000) AND gender = 1;
```

==四：总结归纳==

- 三条：`BETWEEN` 含两端；判断空值只能 `IS NULL`；`LIKE` 前置 `%` 必全表扫。
- 记忆锚：这一段是 T-SQL 的复制粘贴，唯一新信息是"前置通配符等于放弃索引"。
- 自测：`WHERE age <> NULL` 会返回什么？为什么？
