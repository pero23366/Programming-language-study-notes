# DQL 排序查询

> 来源：P19《19. 基础-SQL-DQL-排序查询》 · 档位 A 几乎重叠
> 与我已知的关系：`ORDER BY` 多字段、`ASC`/`DESC` 与 T-SQL 完全一致

==一：意义与概念==

`ORDER BY 列 [ASC|DESC], 列2 ...`，默认 `ASC`。没有新知识，三个确认点：

1. **多字段排序按书写顺序生效**：第一个字段相同才看第二个。
2. **可以用别名和列序号**：`ORDER BY 2 DESC` 表示按第 2 列排。别名能用是因为 `ORDER BY` 在 `SELECT` 之后执行（下一篇讲执行顺序）。
3. **`NULL` 排序位置**：MySQL 把 NULL 当最小值，`ASC` 时排最前、`DESC` 时排最后。要强制 NULL 居后：`ORDER BY salary IS NULL, salary`（`IS NULL` 返回 0/1）。

中文排序不对是常见抱怨，根因是排序规则：`utf8mb4_general_ci` 按 Unicode 码点排，不是拼音序。要拼音序得用 `utf8mb4_zh_0900_as_cs`（8.0 才有）或在应用层排。

==二：使用格式==

```sql
SELECT name, salary FROM emp ORDER BY salary DESC, name ASC;
SELECT name, salary FROM emp ORDER BY salary IS NULL, salary;  -- NULL 排最后
```

==四：总结归纳==

- 三条：默认升序；多字段就近生效；NULL 被当最小值。
- 记忆锚：和 T-SQL 逐字相同，只多一个"NULL 排最后"的小技巧。
- 自测：`ORDER BY salary DESC` 时 NULL 排在结果的头还是尾？
