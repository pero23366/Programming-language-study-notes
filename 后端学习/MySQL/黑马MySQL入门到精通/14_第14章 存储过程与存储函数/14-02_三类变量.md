# 变量：系统变量、用户变量、局部变量

> 来源：P104–P106《47–49. 进阶-存储过程-变量-系统变量 / 用户定义变量 / 局部变量》 · 档位 B 部分重叠
> 与我已知的关系：C# 里变量有作用域就一种，MySQL 有三种，**靠符号前缀区分，且生命周期完全不同**

==一：意义与概念==

三种变量，看前缀就知道是谁：

| 类型 | 写法 | 作用域 | 谁定义 |
|---|---|---|---|
| **系统变量** | `@@global.xxx` / `@@session.xxx` / `@@xxx` | 全局 / 当前会话 | MySQL 预置 |
| **用户定义变量** | `@xxx`（单个 `@`）| **当前连接**，跨语句、跨过程都有效 | 你自己 `SET` |
| **局部变量** | `DECLARE xxx`（无前缀）| **`BEGIN...END` 块内**，出了块就没 | 用 `DECLARE` 声明 |

**最容易混的一对：`@x` 与 `DECLARE x`**

```sql
SET @a = 10;              -- 用户变量，整个连接有效，不需要声明
DECLARE b INT DEFAULT 5;  -- 局部变量，只能在 BEGIN...END 内、且必须写在块的最前面
```

三个必须知道的边界：

1. **局部变量的 `DECLARE` 必须在 `BEGIN` 后的第一段**，写在任何可执行语句之后都报语法错。多个变量要连续声明。
2. **用户变量在连接断开时消失**，且**不区分大小写**（`@A` 和 `@a` 是同一个）。
3. **`SET @x = (SELECT ...)` 与 `SELECT ... INTO @x`** 都能赋值，后者更适合多列。

系统变量的两个作用域：

```sql
SELECT @@global.max_connections;   -- 全局
SELECT @@session.sql_mode;         -- 当前会话
SET GLOBAL max_connections = 500;  -- 改全局（新连接生效，且重启失效）
SET SESSION sql_mode = '';         -- 只改当前连接
```

`SET GLOBAL` **重启后失效**——要持久化得改 `my.cnf` 或用 `SET PERSIST`（8.0 新增，写入 `mysqld-auto.cnf`）。

和 EF Core 的关系：`@@` 系统变量可以用来做"运行时探针"，比如连接池里检查 `@@transaction_isolation`。但注意：**用户变量 `@x` 是连接级状态，而 EF Core 用连接池会复用连接**，你设的 `@x` 可能被下一个请求看到——这是很难查的串数据 bug。**别在 ORM 项目里用用户变量传状态。**

==二：使用格式==

```sql
-- 系统变量
SELECT @@global.变量名 / @@session.变量名;
SET GLOBAL 变量名 = 值;
SET SESSION 变量名 = 值;
SET PERSIST 变量名 = 值;      -- 8.0，持久化

-- 用户变量
SET @x = 值;
SET @x := 值;                 -- 也行（:= 是赋值，= 在 SELECT 里是比较）
SELECT 列 INTO @x FROM 表 WHERE ...;
SELECT @x;                    -- 读取

-- 局部变量（只能在存储过程/函数/触发器内）
DECLARE x INT [DEFAULT 0];
SET x = 值;
SELECT 列 INTO x FROM 表 WHERE ...;
```

==三：代码实践==

```sql
DELIMITER $$
CREATE PROCEDURE p_demo()
BEGIN
  DECLARE v_cnt INT DEFAULT 0;        -- 局部变量必须在最前
  DECLARE v_name VARCHAR(20);

  SET @user_var = 100;                -- 用户变量，随便写在哪
  SELECT COUNT(*) INTO v_cnt FROM emp;
  SELECT name INTO v_name FROM emp WHERE id = 1;

  SELECT v_cnt, v_name, @user_var;
END $$
DELIMITER ;

CALL p_demo();
SELECT @user_var;      -- 过程结束后用户变量还在
-- SELECT v_cnt;       -- 报错：局部变量出了 BEGIN...END 就不存在
```

==四：总结归纳==

- 三条：`@@` 系统变量、`@` 用户变量（连接级）、`DECLARE` 局部变量（块级）；局部变量声明必须在块首；`SET GLOBAL` 重启失效，要 `SET PERSIST`。
- 记忆锚：`@@` 是"数据库的"，`@` 是"这个连接的"，裸名是"这个块的"。
