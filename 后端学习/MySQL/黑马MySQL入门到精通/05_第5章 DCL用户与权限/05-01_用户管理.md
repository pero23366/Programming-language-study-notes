# DCL 用户管理

> 来源：P24《24. 基础-SQL-DCL-用户管理》 · 档位 B 部分重叠
> 与我已知的关系：SQL Server 是「登录名 → 数据库用户」两层，**MySQL 把这两层压成了一个 `'user'@'host'` 二元组**

==一：意义与概念==

建账号、改密码、删账号。概念上两边都想表达"谁、从哪儿来、能干什么"，但建模方式不同：

| | SQL Server | MySQL |
|---|---|---|
| 身份 | 两套：**登录名**（服务器级）+ **数据库用户**（库级），要 `CREATE LOGIN` 再 `CREATE USER FOR LOGIN` | 一套：`'用户名'@'来源主机'` 一个二元组就是完整账号 |
| 来源限制 | 不区分来源主机 | **`host` 部分参与账号唯一性** |
| 同一个名字 | 全局一个登录名 | `'root'@'localhost'` 和 `'root'@'%'` 是**两个账号**，权限各算各的 |

`host` 是关键差异。`'tom'@'192.168.1.5'` 只允许那台机器连；`'tom'@'%'` 允许任何机器；`'tom'@'localhost'` 只允许本机（走 socket / 命名管道，不经 TCP）。

常见误解：以为 `'tom'@'%'` 包含 `localhost`。**不包含**——MySQL 里 `localhost` 走的是本地 socket 连接，与 `%`（TCP 来源）是两条路径，所以经常出现"`%` 账号建好了，本机却连不上"的情况。稳妥做法是本机和 `%` 各建一个。

8.0 的认证插件默认是 `caching_sha2_password`，旧版 .NET 驱动（MySql.Data 老版本）不认，会报 `Authentication plugin 'caching_sha2_password' cannot be loaded`。解法见本篇延伸。

==二：使用格式==

```sql
CREATE USER '用户名'@'主机' IDENTIFIED BY '密码';
ALTER USER '用户名'@'主机' IDENTIFIED BY '新密码';
DROP USER '用户名'@'主机';
SELECT * FROM mysql.user;      -- 看所有账号（密码是哈希，8.0 已不显示明文）
```

| 参数 | 说明 |
|---|---|
| `'主机'` | `localhost` 本机 / `%` 任意 / 具体 IP / 网段 `192.168.1.%` |
| 密码 | 8.0 默认要求一定强度（`validate_password` 插件装上后更严）|

==三：代码实践==

```sql
-- 给应用单独建账号，别用 root 连生产
CREATE USER 'app'@'localhost' IDENTIFIED BY 'App@2026#pwd';
CREATE USER 'app'@'%'         IDENTIFIED BY 'App@2026#pwd';

-- 验证：列出账号
SELECT user, host, plugin FROM mysql.user WHERE user = 'app';
```

> 💡 延伸：老驱动连不上 8.0 时，把该账号的认证插件改回旧协议：
> `ALTER USER 'app'@'%' IDENTIFIED WITH mysql_native_password BY '密码';`
> 治本方案是升级驱动（Pomelo.EntityFrameworkCore.MySql 新版已支持）。

==四：总结归纳==

- 三条：账号 = `'user'@'host'` 二元组，`host` 不同就是不同账号；`%` 不含 `localhost`；8.0 默认 `caching_sha2_password`。
- 记忆锚：SQL Server 的"登录名 + 用户"两层，在 MySQL 里被压成一张写着来源地址的门禁卡。
- 自测：① 建了 `'app'@'%'`，为什么本机 `mysql -u app` 可能连不上？② `'app'@'localhost'` 和 `'app'@'%'` 能同时存在吗？
