# 子查询

> 来源：P43–P47《43–47. 基础-多表查询-子查询介绍 / 标量 / 列 / 行 / 表子查询》 · 档位 B 部分重叠
> 与我已知的关系：四类子查询的划分与 T-SQL 一致，**但 MySQL 8.0 之前对子查询的优化很差，很多场景要改写成 JOIN**

==一：意义与概念==

把一条 SELECT 的结果当成另一条 SELECT 的**值**或**表**用。按返回形态分四类，判断标准是"返回几行几列"：

| 类型 | 返回 | 用在哪 | 运算符 |
|---|---|---|---|
| 标量子查询 | 1 行 1 列 | `WHERE` / `SELECT` 列位置 | `= > < >= <=` |
| 列子查询 | 1 列多行 | `WHERE` | `IN` / `NOT IN` / `ANY` / `SOME` / `ALL` |
| 行子查询 | 1 行多列 | `WHERE` | `(a,b) = (子查询)` |
| 表子查询 | 多行多列 | `FROM` 后当临时表（**必须起别名**）| 当表用 |

判断方法：先写子查询，看它返回什么形状，再选对应的运算符。**形状不匹配不报错的情况最危险**——标量子查询返回多行会直接报 `Subquery returns more than 1 row`，这个至少能发现；而 `IN` 遇到 NULL 会静默返回空集。

与 T-SQL 的实质差异在**执行方式**：

- **相关子查询**（子查询里引用了外层的列）在 MySQL 里是逐行执行外查询、每行跑一次子查询，N 行就是 N 次，性能随数据量线性劣化。
- MySQL 5.6 之前连非相关子查询都不做物化，每次重新算；8.0 有半连接（semi-join）优化，`IN` 子查询多数能被改写成 JOIN，但**不是所有写法都能**。

所以实践建议：**能用 JOIN 表达的，优先写 JOIN**。子查询的可读性更好，但在 MySQL 里性能不确定性更大。第 12 章会用 `EXPLAIN` 看它到底有没有被优化。

`NOT IN` 有个经典陷阱：**子查询结果里含 NULL 时，`NOT IN` 整个返回空集**。因为 `x NOT IN (1, 2, NULL)` 等价于 `x<>1 AND x<>2 AND x<>NULL`，最后一项永远为 NULL（假）。解法：子查询里加 `WHERE 列 IS NOT NULL`，或改用 `NOT EXISTS`。

==二：使用格式==

```sql
-- 标量：薪资高于平均值的员工
SELECT name FROM emp WHERE salary > (SELECT AVG(salary) FROM emp);

-- 列：在"销售部"和"教研部"的人
SELECT name FROM emp WHERE dept_id IN
  (SELECT id FROM dept WHERE name IN ('销售部','教研部'));

-- 行：与"张三"同部门同薪资的人
SELECT * FROM emp
WHERE (dept_id, salary) = (SELECT dept_id, salary FROM emp WHERE name='张三');

-- 表：把子查询当临时表，必须起别名
SELECT t.dept_id, t.cnt FROM
  (SELECT dept_id, COUNT(*) cnt FROM emp GROUP BY dept_id) t
WHERE t.cnt > 3;
```

`ANY` / `SOME` / `ALL` 的语义：

| 运算符 | 含义 |
|---|---|
| `> ANY(子查询)` | 大于其中**任意一个**即成立（等价于 `> MIN`）|
| `> ALL(子查询)` | 必须大于**所有**（等价于 `> MAX`）|
| `= ANY(...)` | 等价于 `IN` |

==三：代码实践==

```sql
-- 反例 1：NOT IN 遇 NULL → 返回空集
SELECT name FROM emp
WHERE dept_id NOT IN (SELECT id FROM dept);   -- dept.id 有 NULL 就全空

-- 正确：排除 NULL，或改用 NOT EXISTS
SELECT name FROM emp
WHERE dept_id NOT IN (SELECT id FROM dept WHERE id IS NOT NULL);

SELECT e.name FROM emp e
WHERE NOT EXISTS (SELECT 1 FROM dept d WHERE d.id = e.dept_id);
```

```sql
-- 反例 2：表子查询忘记别名
SELECT * FROM (SELECT id FROM emp);      -- ERROR 1248: Every derived table must have its own alias

-- 正确
SELECT * FROM (SELECT id FROM emp) t;
```

==四：总结归纳==

- 三条：按返回形状选类型（1行1列/1列多行/1行多列/多行多列）；表子查询必须起别名；`NOT IN` 遇 NULL 静默返回空集。
- 记忆锚：先问"子查询吐出什么形状"，形状决定运算符——这是唯一需要判断的事。
- 自测：① 子查询返回 3 行，用 `=` 会怎样？② 为什么 `NOT IN` 里出现 NULL 结果就空了？
