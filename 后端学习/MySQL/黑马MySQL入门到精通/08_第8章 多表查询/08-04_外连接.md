# 外连接

> 来源：P40《40. 基础-多表查询-外连接》 · 档位 B 部分重叠
> 与我已知的关系：`LEFT` / `RIGHT JOIN` 一样，**但 MySQL 没有 `FULL OUTER JOIN`，也没有 T-SQL 的 `*=` 老语法**

==一：意义与概念==

保留一边的全部行，另一边匹配不上就填 NULL。

| 类型 | 保留谁 | 典型场景 |
|---|---|---|
| `LEFT [OUTER] JOIN` | **左表全部** | "所有员工，含没分配部门的" |
| `RIGHT [OUTER] JOIN` | **右表全部** | 等价于把两表调换后写 LEFT |
| `FULL OUTER JOIN` | 两边全部 | **MySQL 不支持** |

三条差异，第一条是硬的：

**1. 没有 `FULL OUTER JOIN`**
这是与 T-SQL 最明确的语法差异。要"两边都保留"必须自己拼：

```sql
SELECT ... FROM A LEFT JOIN B ON ...
UNION
SELECT ... FROM A RIGHT JOIN B ON ...;
```

`UNION` 会去重，正好把两边都匹配上的重复行消掉。

**2. 没有 `*=` / `=*` 老语法**
SQL Server 2008 之前用 `WHERE a.id *= b.id` 表示左连接，MySQL 从来没支持过，只认关键字。

**3. `LEFT JOIN` 后 `WHERE` 写错条件会退化成内连接**
这是最实用的坑：

```sql
SELECT * FROM dept d LEFT JOIN emp e ON d.id = e.dept_id
WHERE e.salary > 5000;          -- 错：NULL 行被 WHERE 干掉了
```

`e.salary > 5000` 对 NULL 求值为 NULL（假），于是"没有员工的部门"整行被过滤——`LEFT JOIN` 白写了。要保留它们得把条件写进 `ON`：

```sql
SELECT * FROM dept d LEFT JOIN emp e ON d.id = e.dept_id AND e.salary > 5000;
```

`ON` 的条件只影响"能不能匹配上"，`WHERE` 的条件影响"匹配完的整行留不留"。这个区别只有在外连接里才看得出来。

==二：使用格式==

```sql
SELECT ... FROM A LEFT  JOIN B ON A.k = B.k [WHERE ...];
SELECT ... FROM A RIGHT JOIN B ON A.k = B.k [WHERE ...];

-- 全外连接模拟
SELECT ... FROM A LEFT JOIN B ON A.k = B.k
UNION
SELECT ... FROM A RIGHT JOIN B ON A.k = B.k;
```

==三：代码实践==

```sql
-- 所有部门 + 部门下的员工（没有员工的部门也要出现）
SELECT d.name AS 部门, e.name AS 员工
FROM dept d
LEFT JOIN emp e ON d.id = e.dept_id;

-- 找出没有员工的部门（左连接 + 右表主键为 NULL）
SELECT d.name
FROM dept d
LEFT JOIN emp e ON d.id = e.dept_id
WHERE e.id IS NULL;
```

第二个是经典套路：**用 `LEFT JOIN ... WHERE 右表主键 IS NULL` 找"从表里没有对应记录"的行**，比 `NOT IN` 干净（`NOT IN` 遇到 NULL 会返回空结果集）。

==四：总结归纳==

- 三条：`LEFT JOIN` 保留左表全部；MySQL 没有 `FULL OUTER JOIN`，用 `LEFT UNION RIGHT` 拼；外连接里条件写 `ON` 不写 `WHERE`。
- 记忆锚：`ON` 决定"能不能配上对"，`WHERE` 决定"配上之后这个对象还留不留"。
