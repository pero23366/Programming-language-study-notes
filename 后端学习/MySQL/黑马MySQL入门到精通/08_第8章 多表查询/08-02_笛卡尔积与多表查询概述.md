# 笛卡尔积与多表查询概述

> 来源：P38《38. 基础-多表查询-概述》 · 档位 A 几乎重叠
> 与我已知的关系：笛卡尔积现象与消除方式在 T-SQL 里完全一样

==一：意义与概念==

`SELECT * FROM emp, dept;` 不加连接条件，结果是 **emp 行数 × dept 行数**。3 行 × 4 行 = 12 行，其中只有 3 行是有效组合。

这叫**笛卡尔积**（交叉连接）。它是多表查询的起点：所有 JOIN 本质上都是"先做笛卡尔积，再按条件筛"。理解这一点，第 11 章的索引和连接算法就都好懂——**连接条件走索引还是走嵌套循环，决定了 3 行 × 100 万行是不是要算 300 万次**。

消除无效组合有两种写法：

| 写法 | 形式 | 说明 |
|---|---|---|
| 隐式连接 | `FROM emp, dept WHERE emp.dept_id = dept.id` | 条件写在 `WHERE` |
| 显式连接 | `FROM emp INNER JOIN dept ON emp.dept_id = dept.id` | 条件写在 `ON` |

**推荐显式**。理由是扩展性：隐式连接加 `WHERE` 条件时，连接条件和过滤条件混在一起，多个表时极易漏写一个导致笛卡尔积（结果行数暴涨还不报错）。显式连接的 `ON` 和 `WHERE` 分工清楚——`ON` 只管表间关系，`WHERE` 只管筛行。

==二：使用格式==

```sql
-- 隐式（老写法）
SELECT ... FROM A, B WHERE A.外键 = B.主键 AND 过滤条件;

-- 显式（推荐）
SELECT ... FROM A INNER JOIN B ON A.外键 = B.主键 WHERE 过滤条件;
```

==四：总结归纳==

- 三条：两表不加条件 = 行数相乘；所有 JOIN 都从笛卡尔积出发再筛；条件写 `ON` 不写 `WHERE`。
- 记忆锚：笛卡尔积是"所有可能的搭配"，JOIN 条件是从中挑出真实存在的那几种。
- 自测：A 表 1000 行、B 表 1000 行，漏写连接条件会返回多少行？
