# 内连接

> 来源：P39《39. 基础-多表查询-内连接》 · 档位 A 几乎重叠
> 与我已知的关系：`INNER JOIN ... ON` 与 T-SQL 逐字相同，没有新知识

==一：意义与概念==

只保留**两边都能匹配上**的行。`INNER` 可省略，`JOIN` 默认就是内连接。

两种写法等价，结果完全一样：

```sql
-- 显式
SELECT e.name, d.name FROM emp e INNER JOIN dept d ON e.dept_id = d.id;

-- 隐式
SELECT e.name, d.name FROM emp e, dept d WHERE e.dept_id = d.id;
```

内连接会**丢掉没有部门的员工**（`dept_id` 为 NULL 或指向已删除部门），这往往不是业务想要的——要保留左表全部行得用外连接（下一篇）。

唯一要养成的习惯：表起**短别名**（`emp e`），列前带别名前缀（`e.name`）。多表时列名重复（两张表都有 `name`）不加前缀会报 `Column 'name' in field list is ambiguous`。

==四：总结归纳==

- 三条：`JOIN` 默认内连接；只保留双面匹配的行；多表必起别名防列名歧义。
- 记忆锚：内连接是"交集"，两边都有的才留下。
- 自测：员工表有 `dept_id` 为 NULL 的行，内连接后会出现在结果里吗？
