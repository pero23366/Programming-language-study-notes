# 联合查询 union

> 来源：P42《42. 基础-多表查询-联合查询union》 · 档位 A 几乎重叠
> 与我已知的关系：`UNION` / `UNION ALL` 与 T-SQL 完全一致

==一：意义与概念==

把两个结果集**上下拼起来**（不是左右连接）。要求：列数相同、对应列类型兼容；列名取第一条 SELECT 的。

| 关键字 | 行为 | 性能 |
|---|---|---|
| `UNION` | 合并后**去重** | 需要排序/去重，慢 |
| `UNION ALL` | 合并后**不去重** | 直接拼接，快 |

原则：**能确定没有重复就用 `UNION ALL`**。很多场景下两段查询的 `WHERE` 条件互斥（比如"2025 年的订单"+"2026 年的订单"），根本不可能重复，用 `UNION` 白白多一次排序。

典型用途：

1. 外连接模拟全外连接（上一篇的用法）。
2. 结构相同的两张分表合并查询（分表后按时间范围查全量）。
3. 行转列的另一种解法（多条 `SELECT 常量 AS 列名` 拼起来）。

排序要写在**最后一条** SELECT 之后，作用于合并结果；写在前面只影响那一段。

==二：使用格式==

```sql
SELECT 列清单 FROM A WHERE ...
UNION [ALL]
SELECT 列清单 FROM B WHERE ...
ORDER BY 列;      -- 只放最后，作用于整体
```

==四：总结归纳==

- 三条：`UNION` 去重、`UNION ALL` 不去重（优先用后者）；列数类型必须兼容；`ORDER BY` 只写最后。
- 记忆锚：JOIN 是横着拼列，UNION 是竖着拼行。
- 自测：两段查询条件互斥时，用 `UNION` 有没有必要？
