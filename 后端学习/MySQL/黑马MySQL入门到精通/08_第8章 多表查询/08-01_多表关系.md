# 多表关系

> 来源：P37《37. 基础-多表查询-多表关系介绍》 · 档位 A 几乎重叠
> 与我已知的关系：一对多/多对多/一对一三种关系与 EF Core 的导航配置一一对应

==一：意义与概念==

三句话总结，构建方式与 EF Core 完全一致：

| 关系 | 怎么建 | EF Core 对应 |
|---|---|---|
| 一对多 | 外键放在**多**的那一方：`emp.dept_id → dept.id` | `HasMany(e => e.Emps).WithOne(d => d.Dept)` |
| 多对多 | 建**中间表**，两个外键各指一边：`student_course(student_id, course_id)` | EF Core 5+ 可隐式建中间表，MySQL 侧仍是物理中间表 |
| 一对一 | 外键加 **UNIQUE** 约束（否则退化为一对多）| `HasOne` + `WithOne`，需显式建唯一索引 |

一对一的关键点：**不加 UNIQUE 的"一对一"其实是一对多**。这是最常被忽略的一步。

多对多的中间表通常还带业务字段（选课时间、成绩），所以它往往不是纯关联表，而是个有独立主键的实体——MySQL 里就是建一张普通的表 + 两个外键。

==四：总结归纳==

- 三条：一对多外键在多侧；多对多靠中间表；一对一靠 UNIQUE 兜住。
- 记忆锚：和 EF Core 的实体关系图同一张图，只是把它画成表。
- 自测：两张表各加一个指向对方的外键，是不是就一对一了？（不是，还缺 UNIQUE）
