# 自连接

> 来源：P41《41. 基础-多表查询-自连接》 · 档位 A 几乎重叠
> 与我已知的关系：一张表起两个别名当两张表用，写法与 T-SQL 一致

==一：意义与概念==

表里存了"指向自己"的外键时（员工表的 `manager_id` 指向本表 `id`），要查"员工和他的上级"就得把这张表**当成两张表**用——各起一个别名。

```sql
SELECT e.name AS 员工, m.name AS 上级
FROM emp e JOIN emp m ON e.manager_id = m.id;
```

必须起别名，否则 `emp.name` 不知道指哪个角色，报 `Not unique table/alias`。

**自连接不一定是内连接**：查"没有上级的员工"（老板）就得用 `LEFT JOIN`，否则老板本人会被过滤掉。

另一个用途是把"行转列"：一张 `score(student, subject, score)` 表，自连接三次就能拼成 `student, 语文, 数学, 英语` 的三列。课程后面的练习会用这招。

性能提醒：自连接是**同一张表扫两遍**，数据量大时比两次独立查询快不了多少——但通常比 `OR` 或子查询好优化，因为有索引可用。

==四：总结归纳==

- 三条：自连接 = 一表两别名；必须有别名；查"缺失参照"要用 `LEFT JOIN`。
- 记忆锚：把自己当外人，再跟自己握一次手。
- 自测：员工表里 `manager_id` 为 NULL 的那行（老板），用内连接自连接后会出现吗？
