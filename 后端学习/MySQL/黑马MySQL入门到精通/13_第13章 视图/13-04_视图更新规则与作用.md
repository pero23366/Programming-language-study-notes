# 视图的更新规则与作用

> 来源：P100–P101《43–44. 进阶-视图-更新及作用 / 案例》 · 档位 B 部分重叠
> 与我已知的关系：能更新视图的条件比 T-SQL 更严格，这一篇是"什么时候视图能写"的判定清单

==一：意义与概念==

视图本质是"命名查询"，能不能 `INSERT`/`UPDATE`/`DELETE` 取决于**基表与视图之间是否一一对应**。

**可更新的条件（同时满足）**：

1. 视图的 `SELECT` 里**没有** `DISTINCT`、聚合函数、`GROUP BY`、`HAVING`、`UNION`
2. `FROM` 只有**一张表**（多表 JOIN 的视图基本不可更新）
3. 没有子查询出现在 `SELECT` 列表里
4. 要更新的列**必须能从视图列直接映射回基表列**（不能是表达式、函数结果）

**不可更新的典型视图**：

```sql
-- 有聚合 → 不可更新
CREATE VIEW v_stat AS SELECT dept_id, COUNT(*) c FROM emp GROUP BY dept_id;
-- 有 DISTINCT → 不可更新
CREATE VIEW v_distinct AS SELECT DISTINCT dept_id FROM emp;
-- 多表 JOIN → 一般不可更新
CREATE VIEW v_join AS SELECT e.*, d.name dn FROM emp e JOIN dept d ON ...;
```

单表视图即使可更新，**也不是所有列都能改**：表达式列（`salary * 12 AS 年薪`）不能写，因为不知道反解成什么。

`WITH CHECK OPTION`（13-02）是**可更新视图的额外约束**：能写，但写进去的行必须还在视图范围内。

### 视图的三个真实作用（课程小结）

| 作用 | 做法 | 好处 |
|---|---|---|
| **简化查询** | 复杂 JOIN 包装成视图 | 少写重复 SQL（但不提速）|
| **安全/权限** | 只授视图权限，隐藏敏感列 | 用户看不到 `salary`、`id_card` |
| **数据独立** | 表结构变了改视图 | 应用代码不用动 |

安全这一条最实用，举个具体例子：

```sql
CREATE VIEW v_emp_public AS
SELECT id, name, dept_id, entry_date FROM emp;   -- 不含 salary、id_card

GRANT SELECT ON demo.v_emp_public TO 'report'@'%';
-- 报表账号只能看这一列子集
```

和 EF Core 的关系：三条实践结论：

1. **只读视图用 `HasNoKey().ToView(...)`**，不要试图更新它。
2. **不要让 EF Core 迁移管理视图**：EF Core 的 `EnsureCreated`/`Migrate` 不管视图，视图要靠手工 SQL 或 `migrationBuilder.Sql()` 创建，否则新环境部署会缺视图。
3. **视图里不要做逻辑**：把 `CASE WHEN` 一堆业务规则塞进视图，是"用数据库写业务代码"的开始，后期没人敢改。视图只做"结构映射"和"权限收口"。

==二：使用格式==

```sql
-- 可更新视图
UPDATE 视图名 SET 列=值 WHERE ...;
INSERT INTO 视图名 (列...) VALUES (...);
DELETE FROM 视图名 WHERE ...;

-- 判断视图是否可更新：看 SHOW CREATE VIEW 的定义里有没有聚合/JOIN/DISTINCT
SHOW CREATE VIEW 视图名;
```

==三：代码实践==

```sql
-- 可更新
CREATE VIEW v_emp_sales AS
SELECT id, name, salary, dept_id FROM emp WHERE dept_id = 1;

UPDATE v_emp_sales SET salary = 9000 WHERE id = 1;    -- ✅ 改的是基表
INSERT INTO v_emp_sales (name, salary, dept_id) VALUES ('王五', 7000, 1);  -- ✅

-- 不可更新
CREATE VIEW v_stat AS SELECT dept_id, AVG(salary) avg_sal FROM emp GROUP BY dept_id;
UPDATE v_stat SET avg_sal = 10000 WHERE dept_id = 1;
-- ERROR 1288: The target table v_stat of the UPDATE is not updatable
```

==四：总结归纳==

- 三条：单表、无聚合/去重/UNION 的视图才可更新；表达式列不可写；视图不提速，价值在权限收口与结构解耦。
- 记忆锚：视图能写，只因为它能"原路返回"到某一行；一旦有了聚合或去重，就没有"原路"了。
