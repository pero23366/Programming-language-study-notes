# 日期函数

> 来源：P29《29. 基础-函数-日期函数》 · 档位 B 部分重叠
> 与我已知的关系：**这一组是函数名差异最大的一段**——`GETDATE()`、`DATEADD` 那套名字全换了，且 `DATE_ADD` 的参数顺序反了

==一：意义与概念==

取当前时间、算日期差、加减日期、格式化。需求与 T-SQL 一样，但几乎每个函数都改名了，且有两处**参数顺序/语义**的坑。

先看对照表：

| 需求 | MySQL | T-SQL |
|---|---|---|
| 当前日期时间 | `NOW()` | `GETDATE()` |
| 当前日期 | `CURDATE()` | `CAST(GETDATE() AS DATE)` |
| 当前时间 | `CURTIME()` | `CAST(GETDATE() AS TIME)` |
| 取年/月/日 | `YEAR(d)` / `MONTH(d)` / `DAY(d)` | 同名 |
| 加减日期 | `DATE_ADD(d, INTERVAL 7 DAY)` | `DATEADD(day, 7, d)` |
| 差几天 | `DATEDIFF(d1, d2)` | `DATEDIFF(day, d1, d2)` |
| 差几小时 | `TIMESTAMPDIFF(HOUR, d1, d2)` | `DATEDIFF(hour, d1, d2)` |
| 格式化 | `DATE_FORMAT(d, '%Y-%m-%d')` | `FORMAT(d, 'yyyy-MM-dd')` |
| 字符串转日期 | `STR_TO_DATE('2026-11-09', '%Y-%m-%d')` | `CONVERT(date, '...')` |

**三个真正的坑：**

1. **`DATE_ADD` 的参数顺序反了**：T-SQL 是 `DATEADD(单位, 数量, 日期)`，MySQL 是 `DATE_ADD(日期, INTERVAL 数量 单位)`。换个位置写，结果可能是另一个日期或直接报错。
2. **`DATEDIFF` 只算"日期部分"的差**：`DATEDIFF('2026-11-09 23:00', '2026-11-09 01:00')` 返回 **0**，不是 0.9 天。要精确到小时/分钟/秒，用 `TIMESTAMPDIFF(HOUR, ...)`。
3. **`DATE_FORMAT` 的格式串里 `%i` 才是分钟**，不是 `%m`（`%m` 是月份）。写成 `%H:%m:%S` 会把分钟显示成月份数字，看起来"时间乱了"。

==二：使用格式==

```sql
DATE_ADD(日期, INTERVAL 数量 单位)     -- 单位：DAY / MONTH / YEAR / HOUR ...
DATE_SUB(日期, INTERVAL 数量 单位)
DATEDIFF(日期1, 日期2)                 -- 日期1 - 日期2，只到"天"
TIMESTAMPDIFF(单位, 日期1, 日期2)       -- 日期2 - 日期1，精确到单位
DATE_FORMAT(日期, '%Y-%m-%d %H:%i:%s')
STR_TO_DATE(字符串, '%Y-%m-%d')
```

`%Y` 四位年、`%m` 月、`%d` 日、`%H` 24 小时、`%i` 分钟、`%s` 秒。

==三：代码实践==

```sql
SELECT NOW(), CURDATE(), CURTIME();

-- 7 天后
SELECT DATE_ADD(NOW(), INTERVAL 7 DAY);

-- 相差几天（只看日期）
SELECT DATEDIFF('2026-11-09', '2026-11-01');       -- 8

-- 相差几小时（精确）
SELECT TIMESTAMPDIFF(HOUR, '2026-11-09 01:00', '2026-11-09 23:00');  -- 22

-- 格式化输出
SELECT DATE_FORMAT(NOW(), '%Y年%m月%d日 %H:%i');    -- 2026年11月09日 19:20
```

反例：

```sql
SELECT DATE_FORMAT(NOW(), '%Y-%m-%d %H:%m');  -- 错：%m 是月份，分钟显示成 11
SELECT DATEDIFF('2026-11-09 23:00', '2026-11-09 01:00');  -- 0，你以为 0.9
```

==四：总结归纳==

- 三条：`NOW()` 替代 `GETDATE()`；`DATE_ADD(日期, INTERVAL n 单位)` 参数顺序与 `DATEADD` 相反；分钟是 `%i`。
- 记忆锚：把 T-SQL 的 `DATEADD(单位,数,日期)` 整个倒过来念，就是 MySQL 的写法。
