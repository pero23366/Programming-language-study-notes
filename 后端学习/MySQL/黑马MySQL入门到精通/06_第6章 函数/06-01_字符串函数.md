# 字符串函数

> 来源：P27《27. 基础-函数-字符串函数》 · 档位 B 部分重叠
> 与我已知的关系：功能需求与 T-SQL 一一对应，**但函数名换了，且拼接不能用 `+`**

==一：意义与概念==

处理字符串。需求（截取、拼接、大小写、填充、去空格）与 T-SQL 完全一样，问题是名字对不上，得背一张对照表。

本篇三个真正的坑：

1. **拼接只能用 `CONCAT`**。`'a' + 'b'` 在 MySQL 里会被当成算术加法，`'1' + '2'` 得 `3`，`'a' + 'b'` 得 `0`（无法转数字按 0 算），全程不报错——结果错了你还不一定发现。
2. **`LENGTH` 与 `CHAR_LENGTH` 不是一回事**：`LENGTH` 返回**字节数**，`CHAR_LENGTH` 返回**字符数**。`utf8mb4` 下中文占 3 字节，`LENGTH('张三')` = 6，`CHAR_LENGTH('张三')` = 2。T-SQL 的 `LEN` 是按字符算的，所以你要用的是 `CHAR_LENGTH`。
3. **`SUBSTRING` 下标从 1 开始**（和 T-SQL 一样，不影响你），但**不支持负数下标**——想从末尾取用 `RIGHT()`。

==二：使用格式（对照表）==

| 需求 | MySQL | T-SQL |
|---|---|---|
| 拼接 | `CONCAT(a,b,c)` | `a + b` |
| 带分隔符拼接 | `CONCAT_WS('-', a, b)` | 无直接对应 |
| 字符长度 | `CHAR_LENGTH(s)` | `LEN(s)` |
| 字节长度 | `LENGTH(s)` | `DATALENGTH(s)` |
| 截取 | `SUBSTRING(s, 起始, 长度)` | `SUBSTRING` |
| 从右截 | `RIGHT(s, n)` / 从左 `LEFT(s, n)` | 同 |
| 大小写 | `UPPER` / `LOWER` | 同 |
| 去空格 | `TRIM` / `LTRIM` / `RTRIM` | `TRIM` / `LTRIM` / `RTRIM` |
| 左右填充 | `LPAD(s, n, 'x')` / `RPAD` | 无直接对应（得用 `REPLICATE`）|
| 替换 | `REPLACE(s, 旧, 新)` | 同 |
| 查找位置 | `INSTR(s, 子串)` | `CHARINDEX(子串, s)` ← **参数顺序反了** |
| 转大写比较 | `UPPER(a) = UPPER(b)` | 同 |

注意 `INSTR` 与 `CHARINDEX` 的参数顺序相反：MySQL 是"串在前、要找的在后面"，T-SQL 反过来。写错不报错，只是永远返回 0。

==三：代码实践==

```sql
SELECT CONCAT('编号-', id) AS 编码 FROM emp;
SELECT CONCAT_WS(',', name, gender, age) FROM emp;     -- 自动跳过 NULL
SELECT CHAR_LENGTH('张三'), LENGTH('张三');             -- 2, 6
SELECT SUBSTRING('2026-11-09', 6, 2);                  -- '11'（月份）
SELECT LPAD('7', 4, '0');                              -- '0007'
SELECT INSTR('abcabc', 'bc');                          -- 2（第一次出现的位置）
```

反例：

```sql
SELECT '1' + '2';               -- 3，不是 '12'
SELECT LENGTH('张三') = 2;      -- 结果是 0（假），因为返回 6
```

==四：总结归纳==

- 三条：拼接用 `CONCAT`；要字符数用 `CHAR_LENGTH`（不是 `LENGTH`）；`INSTR` 参数顺序与 `CHARINDEX` 相反。
- 记忆锚：功能照 T-SQL 的思路想，落笔前查一次名字——差别全在"叫什么"，不在"干什么"。
