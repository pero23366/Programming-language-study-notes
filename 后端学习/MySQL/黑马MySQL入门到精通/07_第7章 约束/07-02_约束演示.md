# 约束演示

> 来源：P33《33. 基础-约束-演示》 · 档位 B 部分重叠
> 与我已知的关系：写法与 T-SQL 一致，**但 `CHECK` 在 8.0.16 之前根本不生效，`UNIQUE` 允许无限个 NULL**

==一：意义与概念==

把六种约束写进建表语句。骨架与 T-SQL 相同，三处行为差异必须知道：

**1. `CHECK` 约束曾经是个装饰品**
MySQL 5.7 及更早版本会**解析并接受** `CHECK (age > 0)`，但**完全不执行**——插 `age = -5` 照样成功。直到 **8.0.16** 才真正生效。所以你从网上抄的老建表语句里那些 `CHECK`，在老版本库里等于没写。8.0.16+ 上它会正常拦截。

**2. `UNIQUE` 允许无数个 NULL**
T-SQL 的唯一约束在 SQL Server 里只允许**一个** NULL（因为 NULL 被当作相等值参与唯一性判断）。MySQL 认为"NULL 不等于任何值，包括 NULL"，所以**多个 NULL 可以共存**。这在"手机号唯一但可空"这类需求上是好事，在"以为只能有一个空值"时是坑。

**3. `AUTO_INCREMENT` 必须依附于键**
它只能加在**主键或唯一键**列上，且一张表只能有一列。T-SQL 的 `IDENTITY` 没这个约束。

==二：使用格式==

```sql
CREATE TABLE 表名 (
  列名 类型 [约束],
  ...
);
```

| 约束 | 列级写法 | 表级写法（推荐，便于命名）|
|---|---|---|
| 非空 | `name VARCHAR(20) NOT NULL` | 无表级形式 |
| 唯一 | `id_card CHAR(18) UNIQUE` | `CONSTRAINT uk_id_card UNIQUE(id_card)` |
| 主键 | `id INT PRIMARY KEY` | `CONSTRAINT pk_emp PRIMARY KEY(id)` |
| 默认 | `gender TINYINT DEFAULT 1` | 无表级形式 |
| 检查 | `age TINYINT CHECK(age > 0)` | `CONSTRAINT ck_age CHECK(age > 0)` |
| 外键 | — | `CONSTRAINT fk_dept FOREIGN KEY(dept_id) REFERENCES dept(id)` |

命名规范 `pk_` / `uk_` / `ck_` / `fk_` 不是强制的，但不命名时 MySQL 会自动生成 `emp_chk_1` 这类名字，将来想删约束都找不到。

==三：代码实践==

```sql
CREATE TABLE emp (
  id        INT AUTO_INCREMENT,
  name      VARCHAR(20) NOT NULL,
  id_card   CHAR(18),
  age       TINYINT,
  gender    TINYINT DEFAULT 1,
  CONSTRAINT pk_emp PRIMARY KEY(id),
  CONSTRAINT uk_id_card UNIQUE(id_card),
  CONSTRAINT ck_age CHECK(age BETWEEN 1 AND 150)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;

-- 验证 UNIQUE 允许多个 NULL
INSERT INTO emp (name) VALUES ('A'), ('B'), ('C');   -- 三行 id_card 都是 NULL，全部成功
```

反例（8.0.16 之前）：

```sql
INSERT INTO emp (name, age) VALUES ('D', -5);   -- 5.7 上成功，8.0.16+ 报 3819 违反 ck_age
```

==四：总结归纳==

- 三条：`CHECK` 在 8.0.16 起才生效；`UNIQUE` 允许多个 NULL；`AUTO_INCREMENT` 必须挂在主键/唯一键上。
- 记忆锚：MySQL 认为"NULL 谁都不等于"，所以唯一约束对 NULL 完全放行。
- 自测：① 5.7 的库上 `CHECK(age>0)` 能挡住负数吗？② 唯一列上插入 3 行 NULL 会报错吗？
